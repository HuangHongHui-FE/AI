# 04 配图：下候选 → 停手等用户筛 → 定引用

复用 `src/find_img.cjs`（从 wechat-img 零改拷来，四渠道找图）。

## 目录铁律：一个事件一个文件夹，图平铺

```
input/<YYYYMMDD>-<slug>/     ← 一个事件就这一个目录
├── 001.jpg ~ NNN.jpg        ← 所有图平铺，不再分子目录
└── _index.json              ← 每张图的来源批次（供回溯）
```

**不要按阶段/主题建子目录。** 曾经试过按「阶段1-确诊前 / 阶段2-确诊初期」分目录，结果：搜索拿不到对应时期的图（见下），子目录反而把图拆散了，用户筛图时要在十几个目录间来回翻。平铺 + `_index.json` 更实用。

## 流程

### 1. 下候选

```bash
node src/find_img.cjs --history --batch "<主体词>" "<事件词>" "input/<YYYYMMDD>-<slug>" 20
```

- 四渠道：必应 + 搜狗图库 + 头条 + 360
- 真实格式按文件头 sniff 转 JPEG（防微信 40137 invalid image format）
- `manifest.md` 列出每张的尺寸、来源

**`--history` 必须加**（历史事件梳理用）：默认批处理有「URL 时间戳超 3 个月即弃」的新鲜度门，会把往年图全滤掉。`--history` 关掉该门并去掉必应时间过滤，抓往年旧图。

### 2. ⛔ 停手等用户筛

**这是硬性停顿。** 候选下完后必须停下来，把清单摘要给用户，等用户删到剩下满意的。

不许自己选完就往下走——用户要亲自过一遍图。

### 3. 核对现存图

用户删完图后，**先 `ls` 确认现存文件**再写引用：

```bash
ls input/<事件目录>/*.jpg
```

⚠️ 别沿用删图前的引用清单——引用了不存在的图会导致推送时静默出问题（wechat-img 实踩过）。

### 4. 在节点里引用（用 `images` 字段，**不要**写进 detail）

⚠️ **2026-10-06 更正**：本节原先写的是「在 `detail` 里插 markdown 图片语法」，**与代码不符**。`src/facts.js` 的 `renderNode()` 只读 `node.images` 字段，把图渲染在 `:::time` 块**之前**（块内不解析 markdown，也放不了图）。写进 `detail` 的图片会被原样当文字输出。

```json
{
  "date": "2026-01-05",
  "title": "...",
  "images": [
    { "src": "input/<事件目录>/002.jpg", "alt": "写实的图注" }
  ],
  "detail": "..."
}
```

一个节点可以挂多张（数组顺序即渲染顺序），同一篇里跨节点分布，别堆在一个节点上。

### 5. 每篇封面自动取该篇首图

`src/index.js` 不再全篇共用一张封面：**每篇用它自己正文里的第一张图**做封面（用户 2026-09-30 定）。因此：

- **想指定某篇的封面，就把那张图挂在该篇最早的那个节点上**——挂晚了，封面就是别的图
- 该篇一张图都没有时，才退回 `--image` 兜底
- 封面只作公众号列表页缩略图，**不再嵌进正文**，所以不必担心和正文首图重复

## 配图分布原则

按时间线分布，不是堆在开头：

| 位置 | 配什么 |
|---|---|
| 封面 | `001-主图.jpg`，选宽图（宽/高 ≥ 1.6，封面 2.35:1 硬裁） |
| 起点节点 | 事件发生时的场景 |
| 转折节点 | 关键变化的现场 |
| 最新进展 | 最新状态 |

**封面图不要重复用在正文首图**——`index.js` 会自动把封面图嵌到正文顶部，正文里再引同一张就是开局重复。

## 找不到图的处理

具体案件、远海事故等热点，当事现场图客观搜不到（泛词只返示意图）。处理方式：

1. 用**场景图**替代，alt 写实描述（「某地法院外景」而非「本案庭审现场」）
2. **不要编造** alt 里没有的内容
3. 实在没有就**不配图**——时间线文章靠文字密度撑得住，硬凑示意图反而降低可信度

## ⚠️ 别指望按「时间段」搜到对应时期的图

**实测结论（2026-09-30，蔡磊事件，71 张图逐张审计）：关键词搜索拿不到历史阶段图。**

搜索引擎不理会年代词。无论关键词写成「蔡磊 2019 确诊初期」还是「蔡磊 2023 新书发布」，返回的**几乎全是他近期最热门的形象**——因为只有那些图被大量转载，历史图被热度压住。

六轮按阶段搜索的结果：

| 搜索意图 | 实际拿到 |
|---|---|
| 确诊初期 | 央视近期截图，人物已是坐轮椅状态 |
| 直播创业 | 大量卖货海报、产品证书（"国产生酮"），不是人物照 |
| 失声期（眼控仪） | **眼镜/眼科广告**——「眼控仪」被拆成「眼」+「眼镜」 |
| 科研突破 | 混进**女演员**照片，完全无关 |

**可行的做法**：

1. **用泛词批量搜，然后逐张审计筛选** —— 第一轮用「<主体> <事件>」泛词搜到的 20 张，反而天然覆盖了多个时期，比按阶段搜的还准
2. **搜事件专名而非时期** —— 「冰桶挑战」「新书发布」这类有专属现场的活动，能搜到真实现场照片（但注意现场人物未必是主体本人）
3. **逐张 Read 审计** —— 敏感词极易被拆解误伤（"眼控仪"→眼镜广告）。拼联系表（contact sheet）一次看多张，比逐张 Read 快得多

**审计要点**：
- 确认是本人（可能有完全无关的人，如演员、其他患者）
- 剔除商品海报/证书/文档截图（不是人物照）
- 标注人物状态对应哪个时期，供写正文时配对

**如果确实需要各时期对应图**，只能靠：① 用户提供素材；② 从视频报道里截帧。
