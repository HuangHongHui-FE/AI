# 02 查证：每个时间点都要有据可查

**这一步决定成败。** 用户明确要求「一定要保证事情很准确，包括事件发生的时间点也必须非常准确」。

## 铁律

| 规则 | 说明 |
|---|---|
| 时间必须查实到日 | 宁可标「未能查证」也不许用「近日」「上个月」糊过去 |
| 日期不许瞎猜 | 只能从来源里读到，不许由上下文推断 |
| 每个节点至少一个来源 | 无来源的节点进不了发布流程 |
| 重要节点至少两个来源 | 单源节点过半会触发 WARN |
| 事发日 ≠ 报道日 | 以事发时间为准，报道日写进 `sources[].date` |
| 一手来源优先 | 官方通报 / 警情通报 / 企业公告 / 法院文书 > 媒体转述 |
| 口径冲突以官方为准 | 但必须在 `note` 里写明分歧，正文会渲染成提醒框 |

## 查证通路

国内事件用 curl + 移动端 UA（WebSearch 是 US-only 搜不了国内；WebFetch 打不开百度/微博）。

```bash
UA='Mozilla/5.0 (iPhone; CPU iPhone OS 16_0) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/16.0 Mobile/15E148 Safari/604.1'

# ① 百度 m 站（通用检索，最好用）
curl -s -A "$UA" "https://m.baidu.com/s?word=<关键词>"

# ② 头条搜索（百度挂了时兜底，抓 title+abstract）
curl -s -A "$UA" "https://so.toutiao.com/search?keyword=<关键词>"

# ③ 搜狗网页搜索（补充）
curl -s -A "$UA" "https://www.sogou.com/web?query=<关键词>"

# ④ 央视网站内搜索（2026-10-06 实测最好用，见下）
curl -s -A "$UA" "https://search.cctv.com/search.php?qtext=<关键词>&type=web&sort=timeasc&page=1"
```

### 站内搜索：比通用搜索引擎可靠（2026-10-06 实测）

通用搜索引擎正在退化——**百度 m 站和头条搜索现在只返 JS 壳页，正文提取不到**（之前能抓，接口变了）；公安部官网 `mps.gov.cn` 返 521 不可达；cn.bing.com 结果质量差。查国家级事件的通稿，直接打目标站的搜索接口反而稳：

| 站点 | 接口 | 解析要点 |
|---|---|---|
| 央视网 | `https://search.cctv.com/search.php?qtext=<词>&type=web&sort=timeasc&page=N` | `sort=timeasc` 按时间升序，适合顺时间线找最早报道；**真实 URL 藏在 `link_p.php?targetpage=<urldecode 后>` 参数里**，要 urldecode 还原 |
| 中新网 | `https://sou.chinanews.com.cn/search.do?q=<词>` | 响应里含 `var docArr = [...]` 的 JSON，可直接解析出 `title`/`pubtime`/`url`/`content_without_tag` |

可直连的站点：央视网、新华网、人民网、中新网、澎湃、观察者网、环球网。公安部/最高法的通稿通常会被央视网、中新网原文转载，走这两个站能拿到**发布方+发布时间戳**，比二手转述可信。

**官方站列表页比搜索引擎更可靠**（2026-10-06 补）——拿直链不要靠搜：

| 站点 | 列表页直链格式 |
|---|---|
| 最高人民法院 | `court.gov.cn/zixun/xiangqing/<id>.html` |
| 广东法院网 | `gdcourts.gov.cn/xwzx/fayuanxinmeiti/content/post_<id>.html` |
| 深圳中院 | `szcourt.gov.cn/ajtb/content/post_<id>.html` |
| 中国警察网 | `news.cpd.com.cn/n3553/<YYMM>/t_<id>.html` |

**引擎可用性实测**：360 搜索（`so.com/s?q=`）是当时唯一好用的中文引擎，但**有速率限制，连续请求返 0 条，需间隔 5–10 秒**；Bing 查中文人名会退化成汉字字典结果（查**完整新闻标题**反而命中率高），不可用于人名检索。

**按事件类型补充专用源**：

| 事件类型 | 优先查 |
|---|---|
| 社会案件 | 当地公安官微/官网通报、法院公告 |
| 企业事件 | 企业公告、交易所披露、工商信息 |
| 政策事件 | 政府官网原文、部委发布会实录 |
| 事故灾难 | 应急管理部门通报、新闻发布会 |

## 统计口径：同一件事的三套数字，不许并置（2026-10-06 定，缅北案实采）

大案子会同时存在几套**统计对象不同**的数字，长得像但不能放一起：

| 口径 | 含义 | 缅北案实例 |
|---|---|---|
| 移交数 | 外方移交给我方的累计人数，**随发布时点变** | 3.1万（2023-11）→ 4.4万（2024-01）→ 4.9万（2024-05）→ 5.3万（2024年底）→ 5.9万余（2026-07） |
| 检察环节数 | 进入批捕/起诉环节的人数 | 批捕 4.8 万、起诉 4.7 万（最高检白皮书） |
| 判决数 | 法院审结人数 | 另算 |

**规矩**：
- 每个数字**必须带时点**（「截至2024年底，累计移交5.3万余名」），光写「5.3万人」等于造谣
- **严禁并置或相加**不同口径的数字——移交数 ≠ 检察数 ≠ 判决数，三者互相包含但不是同一对象
- 同一时点的数字若有两个以上发布方（如人民网首发、央视网转载），**是同一稿件，不算交叉验证**——判断方法看正文措辞是否完全一致


## 交叉验证

同一时间点**至少两个独立来源**。

⚠️ **多家媒体转同一篇通稿只能算一个来源**——这是最容易自欺的地方。判断方法：看正文措辞是否完全一致，一致就是通稿。

```bash
# 验证是否为通稿：抓多家标题和首段比对
curl -s -A "$UA" "https://m.baidu.com/s?word=<事件+关键日期>" | grep -o '<title>[^<]*</title>'
```

## 时间精度分层

不是所有节点都需要精确到分钟。按可获得性分层记录：

- **精确到分钟** `2026-01-05T14:30` —— 有官方通报时间戳、发布会时间
- **精确到日** `2026-01-05` —— 大多数情况
- **只知道月份** → 标 `confidence: "low"` + `note` 说明「具体日期未能查证，据 X 报道为 Y 月」，**date 字段仍要填一个能站住的日期**（如报道中提到的当月首日或月中），并在 note 里注明不确定

## 存疑处理

查不到实锤但有流传的说法，标 `confidence: "low"` + `note` 记录分歧：

```
"confidence": "low",
"note": "关于这一点，A 媒体称是 X，B 媒体称是 Y，此处取官方通报口径，待后续确认。"
```

**注意分工（2026-09-30 定）**：

- `note` 是**内部批注**，给自己看的，**不会渲染进正文**（用户明确要求：正文里不出现「此处说法存在分歧……」这类自白）
- 读者看到的只有 `detail`，所以**存疑要在 `detail` 里就把措辞写准**：用「他称」「据其表述」「此后未见公开披露」这类客观陈述，而不是先写死再打免责声明

**不许把存疑内容当确定事实写**——底线没变，只是实现方式从「打免责声明」改成「措辞本身留有余地」。

## 完成标志

每个待梳理的时间点都有：
- [ ] 一个可站住的日期（精确到日）
- [ ] 至少一个可点击的来源 URL
- [ ] 重要节点两个独立来源
- [ ] 存疑之处已标记
