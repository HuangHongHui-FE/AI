# 01 选题：定这次梳理什么事件

## 分支 A：用户指定了事件

直接进入 `02-查证.md`。

先确认两件事（一句话即可，不要反复追问）：
1. **梳理到哪个时间点** —— 事件已结束就梳理全程；仍发展中就梳理到最新
2. **给谁看** —— 默认是「不了解这件事的普通读者」，从背景讲起

## 分支 B：用户问「有什么值得梳理的事件」

主动扫候选，**列出来等用户选，不要自己开写**。

### 扫描范围（用户 2026-09-29 定，四类）

| 类别 | 挑什么 | 例子方向 |
|---|---|---|
| 社会民生 | 案件侦破、安全事故、公共争议 | 过程曲折、时间线清晰、有官方通报 |
| 科技/产业 | 企业兴衰、技术突破、行业变局 | 有明确起点和转折 |
| 财经政策 | 政策演变、金融风波、市场周期 | 节点可查证、有公开文件 |
| 文娱/网络 | 现象级话题、舆论事件 | 发酵过程有迹可循 |

### 筛选标准（宁可少推，不可凑数）

1. **有完整时间线** —— 至少 5 个可查证节点，节点之间有因果推进，不是零散快讯
2. **有时间跨度** —— 跨几周到几年
3. **细节可查** —— 能找到具体日期、数字、人名、官方通报
4. **有梳理价值** —— 过程存在转折、反转，或多数人只知道开头不知道结尾

**反向排除**：
- 当天发生的事 → 归 `wechat-img` 追热点，不走这里
- 只有一条通稿、查不到细节的 → 时间线撑不起来
- 纯观点争议、没有事实推进的 → 不是「过程」

### 输出格式

给 3-5 个候选，每个写清：

```
【事件名】
梗概：一句话说清是什么
时间：起始日期 → 最新日期
节点：估计 N 个可查证节点
推荐理由：为什么值得梳理（转折在哪、多数人的认知盲区在哪）
```

然后**停下来等用户选**。

### 怎么找候选

国内热点 WebSearch 搜不到（US-only），用 curl：

```bash
UA='Mozilla/5.0 (iPhone; CPU iPhone OS 16_0) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/16.0 Mobile/15E148 Safari/604.1'

# 百度 m 站
curl -s -A "$UA" "https://m.baidu.com/s?word=<关键词>"

# 头条搜索（百度挂了时兜底）
curl -s -A "$UA" "https://so.toutiao.com/search?keyword=<关键词>"
```

也可查各项目已有素材：`../wechat-img/input/`（历史热点）、`../forecast/results/`（财经线）。
