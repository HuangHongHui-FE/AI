# 05 发布：过硬门 → 渲染 → 分篇推草稿

## 命令

```bash
# 先看效果，不推（强烈建议每次都先 dry-run）
node src/index.js --facts facts/<slug>.json --image input/<dir>/001-主图.jpg --dry-run

# 单篇（节点少，一篇讲完）
node src/index.js --facts facts/<slug>.json --image input/<dir>/001-主图.jpg

# 分篇（长事件，推成多个独立草稿，标题自动加【上】【中】【下】前缀）
node src/index.js --facts facts/<slug>.json --image input/<dir>/001-主图.jpg --parts 3
```

## 参数

| 参数 | 说明 |
|---|---|
| `--facts <path>` | 事实卡 JSON（必填） |
| `--image <path>` | 封面图（必填） |
| `--parts <n>` | 分几篇，默认 1。长事件 2-3 篇，标题自动加【上】【中】【下】前缀 |
| `--dry-run` | 只核查 + 出预览，不调微信 API |
| `--out-dir <path>` | 输出目录，默认 `result/YYYY-MM-DD/<slug>/` |
| `--author "<name>"` | 覆盖署名 |
| `--theme <name>` | 指定配色，默认跟事实卡 `theme` 或 `cool` |

## 执行流程

```
[1/5] 事实核查      ← 独立进程跑 preflight.js，FAIL 直接退出，物理跳不过
[2/5] 渲染正文      ← 由事实卡确定性渲染，不是 LLM 二次生成
[3/5] 合成封面      ← cover.js，plain 纯图不叠文字
[4/5] 分篇渲染      ← 优先按 parts 叙事边界切，逐篇落盘 article-N.json/html
[5/5] 推草稿        ← 上传封面 → 内文图 → 写草稿箱
```

**关键**：`[2/5]` 不经过 LLM——发布出来的内容就是你在事实卡里核查过的内容，中间没有环节能改掉一个日期。

## 分篇规则

- **独立草稿**（用户 2026-09-29 定）——`--parts 3` 推 3 个草稿，不是一篇挂 3 条图文
- **序号统一前置**（用户 2026-09-30 定）：`【上】蔡磊确诊渐冻症：医生说他只剩三到五年`
  - 三篇形式统一，一眼能排出顺序
  - 所以 `parts[].title` **不要写「（上）」**——会被剥离后统一加前缀，写了等于白写
  - 代码有防重：标题自带的篇序（「（上）」「第2篇」等）会被剥掉再加前缀
- **每篇要有专属 digest**（`parts[].digest`）——不写的话三篇共用同一段总摘要，读者在列表里分不清是哪篇
- **两种切分方式**：
  - `facts.parts` 定义（推荐）—— 按叙事边界切，每篇可写专属标题与摘要
    ```json
    "parts": [
      { "title": "蔡磊确诊渐冻症：医生说他只剩三到五年",
        "summary": "2019年9月，41岁的京东集团副总裁蔡磊拿到一张诊断书……",
        "closing": "一个被判了三到五年的人，把时间花在了给自己找不到答案、但别人可能用得上的地方。",
        "digest": "2019年9月确诊，医生说生存期三到五年……",
        "until": "2022-09-21" },
      { "title": "蔡磊捐了一个亿：渐冻症还没被攻克",
        "digest": "《相信》卖了200万册，他和妻子再捐1亿元……",
        "until": "2025-12-30" }
    ]
    ```
    `until` 是该篇最后一个节点的日期（含），断点落在叙事转折处
  - 无 `parts` 时退回按节点数均分，此时标题加 `【上】` 前缀
- 每篇开头用 `parts[].summary`（本篇概述），结尾用 `parts[].closing`（手写结尾）
- 节点不够分那么多篇时会**警告并少推**（不会静默）

## 封面：每篇用自己正文的第一张图

**用户 2026-09-30 定**：不要每篇共用同一个封面。

封面取**该篇正文里的第一张图**（`firstImageOf()`），三篇各不相同、且都与本篇内容相关。

`--image` 退化为**兜底**——只在某篇完全没有配图时使用。

**正文不再以图片开头**：去掉「自动把封面嵌到正文顶部」的逻辑。封面只作公众号列表页缩略图，正文直接从文字进内容。

> 注：封面取自正文首图**不算重复**。微信封面是列表页缩略图，读者点进来后正文里只显示那一次。之前看到的重复，是因为额外把封面图又插了一遍到正文顶部。

## 正文里不写导航语

**用户 2026-09-30 定**：正文顶部不出现「本文是XX全过程梳理的上篇（共 3 篇）」「时间跨度：X → Y」「本篇时间范围：X → Y」这类导航说明。

篇序和范围已由**标题 + 摘要**交代清楚，正文里再讲一遍是冗余。

⚠️ **「时间跨度」曾是漏网之鱼**：首篇会自动加「时间跨度：全事件起止」，但分篇时首篇只讲到 2022 年，却标着 `2019-09 → 2026-09-26`，读者会误以为本篇跨度七年。已删。

## 结尾必须手写，不许套模板

**用户 2026-09-30 定**：结尾不写「以上为「XX」截止 X 的进展，事件仍在发展中，后续变化会另行梳理」这类代码拼出来的套话——它放到任何事件上都成立，等于没说。

结尾由 `parts[].closing` **为这篇单独写**：可以是这段内容的总结，可以是一句有分量的话，也可以是当事人的原话。

实测的三种写法（蔡磊事件）：

| 篇 | 结尾 |
|---|---|
| 上 | 一个被判了三到五年的人，把时间花在了给自己找不到答案、但别人可能用得上的地方。 |
| 中 | 有人问他图什么。他说得很直白：几十万病友的生机面前，个人的面子和尊严已经不值一提。 |
| 下 | 药做出来了，救的却不是他……七年了，他还在。 |

**没写 `closing` 就宁可不写结尾**，也不退回模板话——代码里已按这个逻辑处理。

## 每篇的开头概述必须是「本篇的」

**用户 2026-09-30 定**：分篇时正文开头那段概述用 `parts[].summary`，**不能用全事件的 `summary`**。

否则上篇会**剧透结局**——首篇只讲到 2022 年，却写着「截至2026年9月，他已完全失声、全身仅剩眼球能动」，读者会错乱。

```json
"parts": [
  { "title": "蔡磊确诊渐冻症：医生说他只剩三到五年",
    "summary": "2019年9月，41岁的京东集团副总裁蔡磊拿到一张诊断书……",
    "digest": "……",
    "until": "2022-09-21" }
]
```

三种文本各司其职，别混用：

| 字段 | 用途 | 出现在哪 |
|---|---|---|
| `summary`（顶层） | 全事件一句话概览 | **单篇**发布时的正文开头 |
| `parts[].summary` | 本篇范围的开头概述 | **分篇**时各篇正文开头 |
| `parts[].digest` | 本篇摘要 | 公众号列表页的摘要栏 |

## 正文不展示来源

**用户 2026-09-30 定：正文里不出现来源标注。**

但事实卡的 `sources` 字段照旧必填——`preflight.js` 仍强制每个节点带来源，那套校验是**写给作者自己看的**，确保写进去的每个时间点都有据可查。只是不再渲染给读者。

所以：少了「来源」引用块，但事实核查的严格程度**一分未减**。

## 内部批注不进正文（关键区分）

**用户 2026-09-30 定**：事实卡里的 `note` 是**内部工作批注**，不渲染进正文。

原先 `confidence: "low"` 会在正文渲染出一个橙色提醒框「此处说法存在分歧：……」，这是**把备忘录印在报纸上**——读者要的是一篇文章，不是作者的自白。

实测踩到的反面例子（已删）：

> 此处说法存在分歧：「突破性发现」的具体内容至今未见论文或数据公开披露……此处按「其本人宣称」记录，不宜当作已证实的科研结论。

同样要避免的还有写进 `detail` 的批注语气，如「需要说明的是……」「不宜当作……」。

**存疑内容的正确处理**：

| 类别 | 放哪 | 会进正文吗 |
|---|---|---|
| `note` | 事实卡 | ❌ 不渲染 |
| `sources` | 事实卡 | ❌ 不渲染 |
| `confidence` | 事实卡 | ❌ 不渲染（preflight 用） |
| `detail` / `facts` | 事实卡 | ✅ 渲染 |

所以存疑的处理方式是**在 `detail` 里就把措辞写准**——用「他称」「据其表述」「此后未见公开披露」这类客观陈述，而不是先写死再打免责声明。

正例（改后）：

> 2023年12月12日，蔡磊……称「已在渐冻症的病因上获得突破性发现」，当日登上热搜，被多家财经媒体转引。
>
> 此后近三年，这一「发现」的具体内容未见论文或数据公开披露，蔡磊本人也未再重申。

事实核查的强度不变：`confidence: "low"` 仍**必须**写 `note`，只是 note 留给自己看。

## 产物落盘 `result/YYYY-MM-DD/<slug>/`

```
cover.jpg           封面
article-1.json      第 1 篇（title/digest/body_markdown/theme）
article-1.html      第 1 篇 HTML 预览
article-2.json/html 第 2 篇...
```

**`result/` 长期保留**，是这些事件文章的存档。回看、重推、复查都从这里拿。

## 排版扩展语法（`src/html.js`）

正文由 `facts.js` 的 `renderNode()` 自动生成，**不需要手写**。但要知道生成了什么：

| 语法 | 效果 | 来源字段 |
|---|---|---|
| `![](图)` | 节点配图（**在 :::time 块之前**，块内不解析） | `images` |
| `:::time 日期 标题 ... :::` | 时间线节点（日期胶囊 + 浅底卡片，**无左侧竖线**） | 每个 node 主体 |
| `:::stat 数值 说明 :::` | 数据卡片（大字数值） | `data` |
| `:::quote 原话 \| 说话人 :::` | 引语 + 署名 | `quote` |

## 时间线节点样式（2026-09-30 定）

**不用左侧竖线**（用户要求）。改为：

```
┌─────────────────────┐
│ [2022-09]            │  ← 日期胶囊：主题色填充 + 白字 + 圆角
│ 标题                  │  ← 独立成行
│ 正文…                 │
│ · 细节列表            │
└─────────────────────┘  ← 浅底色圆角卡片，无左右边距
```

两条样式硬规则：

- **日期只显示到月** `YYYY-MM`。事实卡里仍存完整精度（供核查与排序），只是不呈现给读者——精确到日的节点也统一显示成月份
- **卡片左右留白 14px**（`margin:14px 0; padding:14px 14px`）。试过完全去掉（`padding:14px 0`），太贴边不好看；16px 偏松。14px 是折中值

样式定义在 `html.js` 的 `:::time` 替换规则里。

## ⚠️ 踩坑记录

### 1. `:::time` 块内不能嵌套其它 `:::` 语法

`html.js` 的扩展语法正则都是非贪婪匹配到最近的 `:::`，嵌套会互相吞——数据卡片会整个消失。

已通过「各块单行闭合 + `:::time` 内只放纯 markdown」规避（2026-09-29 实踩修复）。

### 2. 正文图片必须上传替换，否则草稿里不显示

**（2026-09-30 实踩）** 推出来的草稿只有封面首图能看，正文里 4 张图全是裂图。

原因：`index.js` 只上传了封面图当首图，**没有扫描正文里的本地图片路径**。正文里 `![](input/...)` 是相对路径，微信服务器读不到。

修复：推送前先跑 `uploadInlineImages()` 把正文里的本地路径上传成微信 URL，再转 HTML。

**注意分工**：
- **本地** `article-N.html` 保留相对路径（浏览器能直接打开预览）
- **推给微信的**用替换成微信 URL 后的 HTML

两条路径分开走，别混。

同时加了**缺失图硬拦截**——正文引用了不存在的图直接拒推，不再静默推出半篇文章（用户删图后没重新对齐 `images` 时最容易踩）。

## 发布后

草稿在 `mp.weixin.qq.com` → 草稿箱。分篇是独立草稿，发布时按（上/中/下）顺序逐篇发。

**token 过期与 IP 白名单**：推草稿报 `42001` = token 过期（脚本会自动重取），报 `40164` = 出口 IP 不在白名单，需去公众号后台加当前 IP。
