# 热点自动发文 Skill（主流程）

> 项目根目录：`/Users/zcy1/code_self/AI/project/wechat-img`
> 调用方式：用户说「写热点文章」「今天发」「来一波热点」之类，Claude **自动**抓榜选点、找图、生成、推草稿——不让用户挑热点，写完自查 AI 痕迹与微信规范
> 找图 / 排版 / CTA / 推草稿的细节见 [[wechat-daily]]，本文只写**选点 + 去重 + 自查 + 串流程**

## 触发条件

用户说「写热点文章」「今天发热点」「来几篇热点」「发一波」之类，要的是**当下实时热点**，不是用户指定主题。

**执行原则**：触发后**不再问任何澄清问题**，直接跑完整流程——抓榜 → 选点 → 去重 → 找图 → 生成 → 自查 → 推草稿 → 写日志。中途的模糊判断（标题怎么起、CTA 选哪类、哪张图更贴、时段怎么排）自己定。除非真正阻塞（接口全挂、所有图都下不下来），才停下来报告。

## ⚠️ 低创作度规避红线（2026-07-17 账号被限推荐后强化）

2026-07-16 一批文章被微信判为「低价值 AIGC / 同质化 / 信息量不足」，停止推荐。根因是旧流程产出高度模板化：标题全「XX，我X了」、结构全六段+每段引言+每段加粗+讲真收口、全文情绪议论零事实。**现强制四条红线，每篇必过**：

1. **事实增量**：每篇 ≥ 3 条可查证事实（人名/数字/时间/地点/引语）。选点后先 curl 抓新闻正文补事实，不能只靠榜单标题脑补感受。**这是根治信息量不足的核心**。
2. **标题去「我X了」**：标题不得以「看懵了/愣了下/笑了/慌了/乐了/有点小激动」收尾，须含一个具体信息点+轻钩子。
3. **结构去模板**：禁「## 一~六 六段 + 每段引言 + 每段加粗 + 第六段家里念叨 + 讲真收口」全套；三件套至多用两件；每篇结构须与近 5 篇不同形。
4. **口头禅跨篇去重**：讲真/我说一句实在的/我愣了/看懵了/咋说呢/说白了/笑归笑/慌归慌/乐归乐等，一周内不重复，每篇记日志。

不过关的回炉重写或弃写，**不为凑数推残次品**。

## 选点规则（核心：不挑，自动取每平台 top2）

### 1. 抓四平台实时热榜

按 [[hotlist]] 抓头条 / 百度 / 抖音 / B站 四榜。**微博 / 知乎抓不到**（访客系统 / 401），不补，四榜重叠足够覆盖。

### 2. 每平台取热度最高的 2 条

- 头条：`data[]` 按 `HotValue` 降序，取前 2
- 抖音：`data.word_list[]` 按 `hot_value` 降序，取前 2
- B站：`data.trending.list[]` 按 `heat_score` 降序，取前 2
- 百度：`data.cards` 顺序即热度序，取前 2（百度无稳定热度数字，按榜单顺序）

→ 候选池最多 8 条。**不让用户挑，直接进下一步。**

### 3. 去重（默认不重复，极火爆热点可破例再写）

**a. 跨平台同主题合并**：不同平台同事件（如「杨某诋毁袁隆平」「男子诋毁袁隆平科研成果」）算同一条，合并保留热度最高那条的标题，只写一篇。Claude 自己判断同义。

**b. 历史已写过的不写**：扫所有 `logs/*.md` 的「话题」列。**注意话题列标题措辞常与今次选题不同**（如历史「台风巴威朝浙江来了」vs 今次「台风巴威又改路线了」），逐条比对会漏判——务必同时对候选选题的**关键实体词**（人名 / 事件名 / 地名）单独 `grep -h` 扫一遍再定：

```bash
# 1. 全量话题列
grep -hE '^\| [0-9]' logs/*.md | awk -F'|' '{gsub(/^ +| +$/,"",$4); print $4}' | sort -u
# 2. 关键实体词再扫一遍，防漏判（换成今次候选的人名/事件名/地名）
grep -h '巴威\|摩洛哥\|晋江\|李建波' logs/*.md
```

候选话题若和历史上某篇同事件（语义相同即算，不必字面一致），**该平台顺延取第 3 条**，再不顺延取第 4 条……直到拿到一条全新的。每平台最终仍只出 2 条全新话题。

**c. 例外：极火爆热点可破例再写一篇**。满足以下任一条件，即使历史写过，也**不顺延、继续写**（一篇）：

- 跨 **3 个及以上平台**同时上榜（四榜重叠 = 真全民热点，热度真实）
- 或单平台热度极高：头条 `HotValue ≥ 3000 万` / 抖音 `hot_value ≥ 1000 万` / B站 `heat_score ≥ 500 万`

破例再写时**必须换角度**（不同于历史那篇的切入），不能复读旧文：

| 历史角度 | 这次换什么角度 |
|---|---|
| 防灾应对 / 路径预警 | 路径再变的新进展 / 灾后重建 / 亲历者视角 |
| 赛事结果 / 比分 | 某球员表现 / 球迷反应 / 历史意义 / 后续赛程 |
| 事件通报 | 后续追责 / 当事人回应 / 类似旧案对照 |

标题仍贴原词，但带上**新进展关键词**（如「又改路线」「再被查」「晋级后」），让读者认得出是同一热点的最新一话，而非旧文重发。

**同热点不无限重复**：历史已写过 **≥ 2 次**的，挡掉顺延，不再破例（再火也写不出新意了）。

**同一天若已跑过一批**：先读当日 `logs/YYYY-MM-DD.md` 看已发哪几条，别撞今早的选题；今早写过但极火爆的，可按 c 规则换角度再写一篇。

### 4. 适性过滤（只挡写不了的）

不挑热点，但以下三类**写不出中年叙事、直接挡掉顺延**：
- 游戏版本 / 充值活动（Steam夏促、和平精英派对、手游神装）
- 纯政策口号（「教育强国这样建设」「十五五规划」这类无故事的）
- 纯国际战况简报（俄乌伤亡数字、空泛外交表态）

其余一律照写——体育、民生、物价、教育代际、社会事件、人物争议都行。

### 5. 最终篇数

去重 + 过滤后剩几条就写几篇（通常 5-7 篇）。**全部写、全部推草稿，不人为砍篇数**——但**每篇须过自查 A/B 全部门槛**（尤其 ≥3 条事实、无六段全套、标题不以「我X了」收尾、口头禅跨篇不重复），不过关的回炉重写或弃写，不为凑数推残次品。

## 标题起名规则（热点专属，覆盖 [[wechat-daily]] 样本风格）

热点文章的标题**必须贴着热点原词起**，蹭到关键词和搜索流量才吸引人。不要像日常贴图发文那样把标题改写成远离原词的中年叙事化标题——日常那套没问题，但**热点场景下是错的**：读者搜不到、信息流里认不出，等于白蹭热度。

**原则**：保留热点原话题的关键词（人名 / 事件名 / 地名 / 数字），只做轻度中年视角微调加一个轻钩子。

**做法**：
1. 先写下热点原词（如「日本市民大排长龙买中国相机」）
2. 保留核心名词「日本 / 中国相机 / 排队」，加一个**信息点型轻钩子**（「这步踩实了」「可惜吗」「会不会跟进」「怎么看」），而非情绪词。
3. ≤22 字，不标题党（无「震惊 / 速看 / 刚刚」等限流词）。

**🚫 禁用「XX，我X了」句式**（看懵了 / 愣了下 / 笑了 / 慌了 / 乐了 / 有点小激动 / 看很久）——2026-07-16 被微信点名 6 篇标题全此格式，判为低价值 AIGC。**热点标题不得以「我X了」收尾**。改用信息点+轻判断/轻反问。

**正反例**：

| 热点原词 | ✅ 贴热点标题 | ❌ 离原词太远 / 踩雷 |
|---|---|---|
| 日本市民大排长龙买中国相机 | 日本市民排长买中国相机，我看愣了 | 中国制造让人排队这事我想了半天 |
| 清华大学一本科生被公告退学 | 清华一本科生被公告退学，可惜吗 | 一纸退学通知背后的教育焦虑 |
| 微波炉热菜微塑料飙升125倍 | 微波炉热菜微塑料飙升125倍，吓一跳 | 我们习以为常的加热方式藏着什么 |
| 凯恩双响绝杀助英格兰晋级 | 凯恩双响绝杀，英格兰这回没掉链子 | 那个不认输的人又站起来了 |
| 杰伦布朗与保罗乔治互换东家 | 杰伦布朗和保罗乔治互换，看懵了 | 一笔交易撕碎了多少球迷的心 |
| 失联20年女儿归来和外甥女争遗产 | 失联20年女儿回来争遗产，怎么算 | 亲情在钱面前到底值多少 |

> 注：上表 ✅ 列里「我看愣了」「吓一跳」「看懵了」属历史样本，**新发文不再用此类情绪词收尾**，改写如「日本市民排长买中国相机，制造这回硬了」「杰伦布朗保罗乔治互换，东家变了」。

**自检**：①标题里是否出现热点原词的关键名词？没有 → 重起；②是否以「我X了」收尾？是 → 重起。

**反例共性**：把具体事件抽成抽象议题（「教育焦虑」「藏着什么」「值多少」），读者在信息流里扫一眼认不出是哪条热点，点击率塌方。热点的全部价值就在「熟悉 + 当下」，标题一抽象就全丢。

## 发文流程（复用 [[wechat-daily]]）

对每条选题，按顺序：

1. **找图**：必应图片 `cn.bing.com/images/async` curl 搜 + 下载到 `input/NN-话题.jpg`（头图），**并多下 1-2 张内文图**到 `input/NN-话题-内图1.jpg`（现场/人物/数据/对比图），供正文中段插入。Read 预览确认相关性。详见 [[wechat-daily]]「找图流程」。多篇可并行搜图下载，看图串行。
2. **抓正文取事实（必做，根治低信息量）**：选点后不能只靠榜单标题脑补「我」的感受，须 curl 抓 2-3 条新闻源正文，摘出**人名 / 数字 / 时间 / 地点 / 当事人原话**作为写作素材：

   ```bash
   UA="Mozilla/5.0 (iPhone; CPU iPhone OS 16_0) AppleWebKit/605.1.4 Mobile/15E148 Safari/604.1"
   curl -s -m 10 -A "$UA" -H "Accept-Language: zh-CN" -H "Referer: https://m.baidu.com/" \
     "https://m.baidu.com/s?word=关键词" -o /tmp/m.html
   # python 提取正文里的事实点，写进文章
   ```

   **硬性标准**：每篇 ≥ 3 条可查证事实（具体人名/数字/时间/地点/引语），少于 3 条不合格、补足再发。例：写「纯国产卡训出万亿模型」须答出哪家公司、卡型号、模型名、参数量、耗时、对标国外哪档——答不出说明事实没抓够，别发。
3. **生成 article.json**：按 [[wechat-daily]] 的长度/结构/调性/反 AI 味/JSON 字段要求，写到 `output/YYYY-MM-DD/NN-话题/article.json`。CTA 按主题选型。**结构每篇须与近 5 篇不同形**，禁「六段+每段引言+每段加粗+讲真收口」全套。
4. **自查**（见下，**写完每篇必做，不合格重写再自查**）。
5. **推草稿**：`node src/index.js --image "input/NN-话题.jpg" --out-dir "output/YYYY-MM-DD/NN-话题/"`。**必须串行，不能并行**——微信同 appid 多次调 gettoken 会使旧 token 失效，并发推会全部报 `40001 invalid credential`（token 互踩）。用 for 循环逐篇跑，每篇间隔 2 秒。若曾并行失败过，先 `rm -f cache/token.json` 清缓存再串行重推。
6. **写日志**：`logs/YYYY-MM-DD.md`，每篇记标题 / 话题 / media_id / 时段建议 / **本篇用到的口头禅**（跨篇去重用）/ **排版 theme**（跨篇轮换用）。

文件编号 `NN` 从 `01` 起，按「头条2条 → 抖音2条 → B站2条 → 百度2条」顺序，去重/过滤后空缺不补位、顺延连续编号。

## 自查清单（写完每篇必过，不过则重写）

### A. AI 痕迹自查（目标：像真人朋友圈长文）

逐条扫 `body_markdown`：

- [ ] **字数 800-1200**：去 markdown 符号后纯文字字数（含标点），不足 800 扩写、超过 1200 精简。热点文章也不得低于 800。
- [ ] **≥3 条可查证事实**：出现至少 3 处具体事实（人名/数字/时间/地点/当事人原话），非纯抽象议论。少于 3 条 → 回抓正文补足再发。
- [ ] **先介绍热点再感悟**：开头 1-2 段把事件讲清楚（什么事/谁/何时何地/经过/结果/为何重要），自我感悟放在事实之后，感悟占比 ≤ 事实介绍。不能上来就「我」的情绪。旧「刷到条消息→我愣了→我琢磨」三段全情绪零事件是反面教材。
- [ ] **内文插图 1-2 张**：正文中段用 `![图说明](input/NN-内图.jpg)` 标记插入热点相关图（现场/人物/数据/对比），图说明具体。`src/index.js` 自动上传替换。纯文字长文不合格。
- [ ] **无「六段全套模板」**：不得同时出现 `## 一~六` 六段 + 每段 `>` 引言 + 每段 `**加粗**` + 第六段「我跟家里念叨」+ 结尾「讲真」收口。三件套至多用两件。每篇结构须与近 5 篇不同形。
- [ ] **标题不以「我X了」收尾**：无「看懵了/愣了下/笑了/慌了/乐了/有点小激动/看很久」收尾句式。
- [ ] **口头禅跨篇不重复**：本篇用到的口头禅（讲真/我说一句实在的/我愣了/看懵了/咋说呢/说白了/笑归笑/慌归慌/乐归乐等）须与近一周已发篇不撞，撞了 → 替换。
- [ ] **排版 theme 跨篇轮换**：`article.json` 的 `theme` 字段（minimal/warm/cool）须与近 5 篇不同套，避免连续同形。详见 [[wechat-daily]]「排版主题轮换」。
- [ ] **禁用词全删**：搜索是否含「值得注意的是」「总而言之」「此外」「综上所述」「综上」「在当今社会」「在快节奏的」「不仅...而且」「既...又...」「毋庸置疑」「众所周知」「由此可见」「应该说」「某种程度上」。命中一个就改写。
- [ ] **无工整排比对仗**：没有「不是 A，而是 B；不是 C，而是 D」这种两两对称的句式堆叠；没有连续三句字数句式雷同。
- [ ] **段落长短不齐**：6 段里至少有 1 段只有 1 句话、有 1 段 6-8 行，不要每段都 3-5 行等长。
- [ ] **开头不套话**：第一段不是「在...的今天」「随着...的发展」「最近，...引发热议」这类万能开头。要直接进场景或一句对话。
- [ ] **有人称落地**：出现「我」「我们家那位」「我一个朋友」之类第一人称落点，不是上帝视角评论。
- [ ] **不端着说教**：没有「我们应该」「我们要学会」「让我们珍惜」这类号召式结尾。
- [ ] **口语感**：至少 2 处口语表达（「说白了」「那时候」「你别说」「可不」之类），不全是书面语。

不合格 → 重写问题段落，再扫一遍。

### B. 微信公众号规范自查

- [ ] **标题**：≤22 字，有钩子但不标题党（「震惊」「速看」「刚刚」等标题党词会被限流，删）。**热点标题须贴原词**，详见上方「标题起名规则」——标题里没有热点关键名词的，重起。
- [ ] **摘要 digest**：≤54 字，不含换行、不含外链。
- [ ] **正文无外链**：微信正文超链接会被屏蔽（非白名单域名变纯文本），`body_markdown` 里不能有 `[文字](url)` 形式的正文链接。引用来源用文字描述，不带 URL。
- [ ] **图片合规**：封面 900×383、正文头图均 < 10MB、JPG。不盗用带明显水印的图（素材站水印图已在该挡）。
- [ ] **无诱导关注/分享违规词**：不含「转发抽奖」「集赞」「强制分享后可见」「关注领取」等微信明确禁止的诱导话术。CTA 卡片的「点赞 在看 转发」是引导非强制，OK。
- [ ] **无敏感红线**：不涉政治人物评价、不涉医疗诊断 / 处方、不涉金融具体投资建议（金价跳水可写感受，不能写「建议买入」）、不涉未审案件定性（用「涉嫌」「被刑拘」原样转述，不预判）。命中即换角度或弃写。
- [ ] **标点**：全中文标点（顿号、引号用「」或""一致），无中英混用逗号。无错别字（自己通读一遍）。
- [ ] **加粗 / 引言 / 分隔符**：`**加粗**` 2-4 处、`> 引言` 0-1 处、`---` 分章节，不过度（全篇加粗等于没加粗）。**编号小标题（## 一二三）+ 每段引言 + 每段加粗三件套不得同时出现**，详见自查 A。

不合格 → 改到合格再推草稿。

## 已知坑

1. **并发推草稿必崩**：两篇以上并行跑 `node src/index.js` 会全部 `40001 invalid credential`。微信同 appid 多次 gettoken 互相使旧 token 失效。**一律串行推**（for 循环 + sleep 2）。2026-06-30 实测 4 篇并行全崩，改串行 8 篇全成。
2. 头条1「中国对日本再出重拳」类时政外交话题，写中年叙事易踩政治人物评价红线，选点时宁可顺延换 top4，不要硬写。
3. **JSON body 内引号一律用中文「」**：`body_markdown` 里若用 ASCII 双引号 `"..."`（如 `"我家狗不咬人"`）会破坏 article.json 解析，推送报 `Unexpected token X in JSON`。生成时直接用「」，不要用 ASCII "。2026-07-05 实测 4 篇因此首推失败，改「」后重推全成。
4. **去重要 grep 实体词不能只比对完整话题串**：历史日志「话题」列标题措辞常与今次选题不同（「台风巴威朝浙江来了」vs「台风巴威又改路线了」），只逐条比对完整串会漏判成「全新」。务必对候选选题的人名/事件名/地名单独 `grep -h` 扫一遍 `logs/*.md`。2026-07-10 第二批初选 3 条（台风/法国摩洛哥/晋江火灾）就这样漏判、核实后临时替换。规则 c 就是为兜这种「写过但极火爆想再写」的情况而设——满足跨 3 平台 / 高热度阈值，换角度即可再写一篇，不必硬顺延换弱话题。

## 不要做

- 不跨天重复选题（每次开跑先扫 `logs/` 历史；极火爆跨 3 平台热点除外，按规则 c 换角度可破例再写一篇）
- 不为凑数写适性过滤挡掉的话题
- 不跳过自查直接推（自查是发文前最后一道关）
- 不对历史已写 ≥2 次的热点再破例（再火也写不出新意）
- 不定时任务（用户喊才跑）
