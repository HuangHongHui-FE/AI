# 微信公众号每日 N 篇贴图发文 Skill（主流程 · 入口）

> 项目根目录：`/Users/zcy1/code_self/AI/project/wechat-img`
> 调用方式：用户在会话里给 1~N 个主题（纯文本，不放图），Claude 自己搜图、下载到 `input/`、生成文章 JSON、跑脚本推到草稿箱
> 本文件是**入口串接器**，只写触发约定（触发 + 执行原则 + 账号定位 + 文件布局 + 脚本复用约定）+ 步骤链清单。写作/找图/生成/推送细节拆分到独立 skill 文件，按需查阅。

---

## 触发条件

用户说「帮我生成对应文章」「发几篇」「今天发」之类，并直接在会话里给了若干个主题文字（1 个、2 个、3 个都行，不再要求预先放图，也不强制 3 个）。

示例：
- 用户发「给你一个主题：吴艳妮女子100米栏夺冠」→ 生成 1 篇
- 用户发「给你三个主题：1、吴艳妮夺冠。2、F1奥地利一练。3、陈妤颉百米夺冠」→ 生成 3 篇

文件命名约定：`NN-话题.jpg`（如 `01-吴艳妮女子100米栏夺冠.jpg`），按用户给的顺序从 `01` 开始编号。**话题直接从用户消息里取，不让用户重复说一遍。** 篇数 = 用户给的主题数。

**执行原则（重要）**：用户提供主题之后，**不要再问任何澄清问题**，直接按本 skill 完整流程跑完——搜图、下载、看图、生成 article.json、推草稿、写日志。中途遇到模糊判断（标题怎么起、CTA 选哪类、时段怎么排、哪张图更贴主题）自己定，不要回头问用户。除非遇到真正的阻塞错误（API 调不通、所有候选图都下不下来等），才停下来报告。

## 执行流程（步骤链）

按顺序跑完整流程，各步骤细节见对应 skill 文件：

### ① 定题（用户已给）→ 主题直接取自用户消息
### ② 找图 + 用户确认 → [[02-find-image]]
按主题词搜图（必应 async 主策略，`--wide` 头图硬门 / `--news` 内图新闻源），下载到 `input/` → Read 预览确认相关性 → **把候选图给用户确认（唯一中途停手点）** → 用户删图后只用删剩图，封面用「主图」那张。

### ③ 抓正文取事实 → [[03-fetch-facts]]
热点/社会类主题 curl 搜狗新闻→必应→百度 m 站多源兜底链，摘出人名/数字/时间/地点/原话，**每篇 ≥3 条可查证事实**。

### ④ 写作维度轮换 → [[04-writing-pools]]
先跑 `node src/recent.js 5` 读近 5 篇已用维度喂 prompt；按账号定位 + 生成要求（800-1200 字、先事实后感悟、禁六段全套）+ 各轮换池每篇随机抽、与近 5 篇不撞。

### ⑤ 生成 + 自查 + 推草稿 + 写日志 → [[05-generate-publish]]
生成 article.json（正文禁引封面文件）→ preflight.js 硬门 → 自查 A/B/C（不过回炉）→ 串行推草稿（禁并发）→ 写日志（字段格式不可变，recent.js 靠它解析）。

## 文件布局

```
wechat-img/
├─ input/                          用户放图（文件名 = 话题）
│  ├─ 01-话题1.jpg
│  ├─ 02-话题2.jpg
│  └─ 03-话题3.jpg
├─ output/
│  └─ YYYY-MM-DD/                  每日文件夹
│     ├─ 01-话题1/                  ← 文件夹名 = 输入文件名（去扩展名）
│     │  ├─ article.json           Claude 写
│     │  ├─ cover.jpg              脚本生成
│     │  └─ article.html           脚本生成（预览用）
│     ├─ 02-话题2/
│     └─ 03-话题3/
├─ logs/
│  └─ YYYY-MM-DD.md                每日生成记录
├─ cache/                          access_token 缓存
└─ src/                            代码
```

**关键约定**：输出文件夹名 = 输入文件名去扩展名（`01-雷军吃早饭被小女孩吐槽.jpg` → `01-雷军吃早饭被小女孩吐槽/`），不要重新 slugify。

## 脚本复用约定（重要）

**`src/` 代码完全复用，日常发文不碰代码。**

| 角色 | 谁做 | 是否每天变 |
|---|---|---|
| 代码（`src/index.js` + `html.js` + `cover.js` + `wechat.js` + `config.js`） | 已写好，跑管线 | ❌ 不动 |
| 配置（`.env`、`skills/*.md`、`logs/`） | 已写好 | ❌ 不动 |
| 输入（`input/NN-话题.jpg`） | Claude 搜图 + 下载 | ✅ 每天换 |
| 文章 JSON（`output/YYYY-MM-DD/NN-话题/article.json`） | Claude 在会话里生成 | ✅ 每天换 |
| 日志（`logs/YYYY-MM-DD.md`） | Claude 在会话里更新 | ✅ 每天加一行 |

**每天实际发生的事**（全部在会话里，不碰代码）：

1. 批量找图 → `node src/find_img.cjs --batch "主体" "事件" "input/YYYYMMDD-NN-话题/" 20`（四渠道，见 [[02-find-image]]）
2. 生成 N 个 `article.json`（见 [[04-writing-pools]] / [[05-generate-publish]]）
3. 串行跑 N 次 `node src/index.js --image ... --out-dir ...`（见 [[05-generate-publish]]）
4. 更新 `logs/YYYY-MM-DD.md`（见 [[05-generate-publish]]）

**只有这些情况才动 `src/`**（半年都不会动一次）：

- 换主色 / 字号 / CTA 卡片结构 → 改 `src/html.js`
- 换封面尺寸 / 标语字号 → 改 `src/cover.js`
- 换账号 / 加新公众号 → 改 `.env`
- 微信 API 变更 → 改 `src/wechat.js`

**不要为了「优化」去改代码**——当前脚本已经跑通 3 篇实发，调性、排版、CTA 都验证过。除非用户明确要求改样式或加功能，否则不动 `src/`。
