## 生成 article.json（步骤 3）

按 [[04-writing-pools]] 的长度/结构/调性/反 AI 味/JSON 字段要求，写到 `output/YYYY-MM-DD/NN-话题/article.json`。CTA 按主题选型。**结构每篇须与近 5 篇不同形**，禁「六段+每段引言+每段加粗+讲真收口」全套。**生成时须避第 0 步 recent.js 输出的已用维度，撞形扎堆的维度强制换值**。仅当用户明确要求某话题插入商品时，才在该篇正文中间（第 3-5 段之间）留 1 处微信返佣商品位：与当前话题语境相关，用 `{{COMMODITY:建议品类}}` 占位，不写真实商品名/链接；推荐语控制在 80 字内，像作者顺手安利，带一句轻钩子。未明确要求插商品的篇目不留商品位、不考虑商品位逻辑。

**复用规则**：如果 `output/YYYY-MM-DD/NN-话题/article.json` 已存在且内容合理（用户没要求重写），直接复用，不重新生成。这在调试时频繁发生。

## 推草稿前硬门（步骤 4，必做，脚本强制门，不靠自查自觉）

跑 `node src/preflight.js "output/YYYY-MM-DD/NN-话题/article.json"`，grep/正则程序化判定——标题「我X了」情绪尾、≤22 字、digest≤54、ASCII 双引号「」、正文外链、存疑词（据传/疑似/据说）、六段全套、字数 800-1200、禁用词、AI 金句句式≥3。任一 FAIL 即 exit 1 拒推，**回炉改对应段落再扫，不可跳过**（跳过推草稿=自找限推，07-20 谢贤篇 ICU 存疑细节即自查漏关漏出去的）。WARN 不阻断但须留意。通过硬门才进下一步。**自查 A/B/C 清单仍要逐条过，preflight 是兜底不是替代**。

## 自查（步骤 5，写完每篇必做，不过则重写）

### A. AI 痕迹自查（目标：像真人朋友圈长文）

逐条扫 `body_markdown`：

- [ ] **字数 800-1200**：去 markdown 符号后纯文字字数（含标点），不足 800 扩写、超过 1200 精简。热点文章也不得低于 800。
- [ ] **≥3 条可查证事实且至少 1 条带来源**：出现至少 3 处具体事实（人名/数字/时间/地点/当事人原话），**其中至少 1 条须有外部出处**（媒体名/机构名/发布时间，如「中新网7-18」「央视曝光」）。**生活常识/通用科普不算可查证事实**——如「切开西瓜滋生细菌」「电池怕冷」「多运动对身体好」属常识，不计入 3 条，纯靠常识凑数 = 官方案例③「简单拼凑无意义」低信息量。少于 3 条带来源事实 → 回抓正文补足再发，补不够弃写不顺延凑数。
- [ ] **先介绍热点再感悟**：开头 1-2 段把事件讲清楚（什么事/谁/何时何地/经过/结果/为何重要），自我感悟放在事实之后，感悟占比 ≤ 事实介绍。不能上来就「我」的情绪。旧「刷到条消息→我愣了→我琢磨」三段全情绪零事件是反面教材。
- [ ] **内文插图 2-3 张**：正文多处用 `![图说明](input/NN-内图1.jpg)` 标记插入热点相关图（现场/人物/数据/对比/剧照），图说明具体有信息增量。`src/index.js` 自动上传替换。纯文字长文、或只配 1 张图都不合格。
- [ ] **正文首图不重复封面**：`body_markdown` 里**严禁引用头图文件** `input/NN-话题.jpg`（封面已由 `--image` 自动用同一文件，正文再引=开局首图跟封面撞脸）。首图用 `input/NN-话题-内图1.jpg`，后续用内图2/内图3。
- [ ] **图说明强相关**：每张内图的 `alt` 只写图里确实看得见的东西 + 该段文字焦点；不确定图里有没有某人/某景就写泛的（「现场」「剧照」），不编造。找图关键词用该段落的实体/场景词，配在哪段就贴那段。
- [ ] **含个人观点增量（非搬运洗稿）**：不能只「热点复述+套话感悟」机械拼接，须有自己的判断/类比/追问。纯复述新闻+套情绪词 → 搬运洗稿，不合格。
- [ ] **融入个人经验（非照搬 AIGC）**：含具体生活场景/亲历类比/独到判断，而非 AI 生成的套话原文照搬。无个人思考增量 → 低价值 AIGC，不合格。
- [ ] **返佣商品位（仅当用户明确要求该话题插商品时才自查，默认不适用）**：未明确要求插商品的篇目跳过此项、不查商品位。仅当用户要求插商品时，检查正文中间（第 3-5 段之间）有 1 处与语境强相关的微信返佣商品占位，格式为 `{{COMMODITY:建议品类}}`。推荐语像作者顺手安利，80 字以内，带一句让人想下单的轻钩子；不放真实链接、不放具体商品名。位置避开开头和结尾 CTA，不破坏阅读流。若该篇实在找不到相关品类（如纯国际战况/政策口号），可标 `无`，但须说明理由。
- [ ] **框架不与近 5 篇一致**：结构（段落组织+小标题用法+引言加粗组合）+ theme 须与近 5 篇不同形。短期多篇套同一固定框架 = 官方点名的同质化铁证。
- [ ] **开头钩子轮换**：从 [[04-writing-pools]]「开头钩子轮换」20 式随机抽一种，与近 5 篇不撞，记日志 `开头钩子`（格式 `NN序号-钩子名`）。开头不篇篇「今天刷到→我愣了→我琢磨」（旧三段全情绪零事件=AIGC 味重灾区）。
- [ ] **结构配方轮换**：从 [[04-writing-pools]]「正文结构配方」20 套随机抽一套，##数/元素组合/段落数与近 5 篇不同形，记日志 `结构配方`（格式 `NN序号-配方名`）。
- [ ] **叙事口吻轮换**：从 [[04-writing-pools]]「叙事口吻/人称」20 套随机抽一种，与近 5 篇不撞，记日志 `叙事口吻`（格式 `NN序号-口吻名`）。有人称落地不变（不上帝视角）。
- [ ] **切入角度轮换**：从 [[04-writing-pools]]「个人切入角度」20 套随机抽一种，与近 5 篇不撞，记日志 `切入角度`（格式 `NN序号-角度名`）。个人增量须盖过公共事实段。
- [ ] **段间衔接轮换**：从 [[04-writing-pools]]「段间衔接方式」20 套随机抽一种主基调，与近 5 篇不撞，记日志 `段间衔接`（格式 `NN序号-衔接名`）。禁用词（此外/综上/不仅而且）零容忍。
- [ ] **cta提问类型轮换**：从 [[04-writing-pools]]「CTA 提问类型」20 类随机抽一种，避近 5 篇、尽量贴主题，记日志 `cta提问类型`（格式 `NN序号-类型名`）。
- [ ] **格式元素组合轮换**：从 [[04-writing-pools]]「格式元素池」17 种随机抽 4-6 种组合，与近 5 篇不撞，记日志 `格式组合`（格式 `NN-元素1/元素2/...`）。多轮换冷门（callout 4 类 / stat / 表格 / 删除线 / 斜体 / h3），别连续多篇「加粗+高亮+有序」老三样。加粗 2-4 处为度，全篇加粗等于没加粗。
- [ ] **无「六段全套模板」**：不得同时出现 `## 一~六` 六段 + 每段 `>` 引言 + 每段 `**加粗**` + 第六段「我跟家里念叨」+ 结尾「讲真」收口。三件套至多用两件。每篇结构须与近 5 篇不同形。
- [ ] **标题不以「我X了」收尾**：无「看懵了/愣了下/笑了/慌了/乐了/有点小激动/看很久」收尾句式。
- [ ] **标题直接用热点原词**：标题 = 热榜原词（或压缩版），不套骨架、不抽池子、不做抽象化改写，记日志 `title_style`（格式 `贴原词-<原词或压缩词>`）。原词超 22 字压缩时保留权威主体+动作原词+关键数字。
- [ ] **标题贴原词**：标题就是热点原词（或压缩版），搜得到认得出，否则重起。
- [ ] **口头禅跨篇不重复**：本篇用到的口头禅（讲真/我说一句实在的/我愣了/看懵了/咋说呢/说白了/笑归笑/慌归慌/乐归乐等）须与近一周已发篇不撞，撞了 → 替换。
- [ ] **收口方式跨篇轮换**：结尾不篇篇「金句判断收口」——07-20 五篇全点睛金句已成新套路，判官扫近 10 篇会识别。按 [[04-writing-pools]]「收口方式轮换」**20 式**随机抽一种，与近 5 篇不撞，记日志 `收口方式`（格式 `NN序号-方式名`）。金句判断式（1）一周至多 2 篇。
- [ ] **收口句式跨篇不撞**：判断式金句的**句式骨架**（「X 的尽头是 Y」「最 X 的就是 Y」「X 的不是 Y 是 Z」）也纳入日志去重，近 5 篇不撞——不只记具体词，记句式。撞了换一种收口方式或换骨架。
- [ ] **排版 theme 跨篇轮换**：`theme` 由 `src/index.js` 自动随机抽避开近 5 篇（20 套，详见本文件「排版主题轮换」），Claude 写 `article.json` 时**不必指定 theme**；推草稿后日志记实际所用 theme，格式 `theme记录(供下批避撞)：NNtheme/...`（脚本解析此行做去重，格式不可变）。
- [ ] **禁用词全删**：搜索是否含「值得注意的是」「总而言之」「此外」「综上所述」「综上」「在当今社会」「在快节奏的」「不仅...而且」「既...又...」「毋庸置疑」「众所周知」「由此可见」「应该说」「某种程度上」。命中一个就改写。
- [ ] **无工整排比对仗**：没有「不是 A，而是 B；不是 C，而是 D」这种两两对称的句式堆叠；没有连续三句字数句式雷同。
- [ ] **段落长短不齐**：6 段里至少有 1 段只有 1 句话、有 1 段 6-8 行，不要每段都 3-5 行等长。
- [ ] **开头不套话**：第一段不是「在...的今天」「随着...的发展」「最近，...引发热议」这类万能开头。要直接进场景或一句对话。
- [ ] **有人称落地**：出现「我」「我们家那位」「我一个朋友」之类第一人称落点，不是上帝视角评论。
- [ ] **不端着说教**：没有「我们应该」「我们要学会」「让我们珍惜」这类号召式结尾。
- [ ] **口语感**：至少 2 处口语表达（「说白了」「那时候」「你别说」「可不」之类），不全是书面语。

不合格 → 重写问题段落，再扫一遍。

### B. 微信公众号规范自查

- [ ] **标题**：≤22 字，有钩子但不标题党（「震惊」「速看」「刚刚」等标题党词会被限流，删）。**直接用热点原词**（见 [[04-writing-pools]]「标题起名规则」），标题里既无原词又无事实锚点（纯抽象议题）的，重起。
- [ ] **摘要 digest**：≤54 字，不含换行、不含外链。
- [ ] **正文无外链**：微信正文超链接会被屏蔽（非白名单域名变纯文本），`body_markdown` 里不能有 `[文字](url)` 形式的正文链接。引用来源用文字描述，不带 URL。
- [ ] **图片合规**：封面 900×383、正文头图均 < 10MB、JPG。不盗用带明显水印的图（素材站水印图已在该挡）。
- [ ] **无诱导关注/分享违规词**：不含「转发抽奖」「集赞」「强制分享后可见」「关注领取」等微信明确禁止的诱导话术。CTA 卡片的「点赞 在看 转发」是引导非强制，OK。
- [ ] **无敏感红线**：不涉政治人物评价、不涉医疗诊断 / 处方、不涉金融具体投资建议（金价跳水可写感受，不能写「建议买入」）、不涉未审案件定性（用「涉嫌」「被刑拘」原样转述，不预判）。命中即换角度或弃写。
- [ ] **标点**：全中文标点（顿号、引号用「」或""一致），无中英混用逗号。无错别字（自己通读一遍）。
- [ ] **加粗 / 引言 / 分隔符**：`**加粗**` 2-4 处、`> 引言` 0-1 处、`---` 分章节，不过度（全篇加粗等于没加粗）。**编号小标题（## 一二三）+ 每段引言 + 每段加粗三件套不得同时出现**，详见自查 A。

不合格 → 改到合格再推草稿。

### C. 低创作度四类硬否决（发文前逐篇必过，不过即回炉重写或弃写，不可跳过）

对照微信官方《低创作度案例解析》四类标准，逐类扫 `body_markdown`，**任一类命中否决条件即不发**。这是推草稿前最后一道强制门，跳过=自找限推（2026-07-20 谢贤篇实踩：C 未成强制前，自标存疑的 ICU 细节、中段两句 AI 金句都漏过关）。

**① 同质化**
- 否决：个人增量（独有场景/判断/类比）占比 < 公共事实段。一篇里「全网同话题都在写的公共事实」超过半数 → 跟全网雷同，弃写。
- 否决：结构 / 收口方式 / theme 与近 5 篇撞形（已在 A 段查）。
- 注：同质化不只看「跟自己历史同质」，更看「跟全网同话题同质」——同一热点全网都在写时，事实天然公共，个人增量须明显盖过公共事实才发。

**② 搬运洗稿**
- 否决：复述媒体/他人报道的段落 ≥ 2 段且无个人增量兜底（纯复述事实+套话感慨=机械拼接），弃写。
- 否决：单篇引用他人原话 > 3 句且无自己分析。
- 改：复述段必须跟「我看到这条时的个人反应/类比」绑定，非孤立复述。

**③ 低信息量**
- 否决：**自标存疑的细节一律删**——「没法证实」「据传」「疑似」「据说」带出的具体细节必须删或改成可查证公开事实。留着「没法证实」还照写 = 官方「引用存疑数据」铁证。
- 否决：可查证事实（带来源） < 3 条，或用生活常识凑数（已在 A 段查）。

**④ 低价值 AIGC**
- 否决：全篇 AI 味金句句（抽象总结判断，如「X 比 Y 更真/更重」「不是 A 是 B」「A 的尽头是 B」）≥ 3 处。收口换了画面式但中段仍堆金句也算。
- 否决：无具体生活场景/亲历类比，纯议论。

**执行**：生成 article.json 后、推草稿前，逐类扫 `body_markdown`。命中任一否决 → 回炉改对应段落再扫；改不动弃写，不为凑数推残次品。

## 推草稿（步骤 6）

`node src/index.js --image "input/NN-话题.jpg" --out-dir "output/YYYY-MM-DD/NN-话题/"`。**必须串行，不能并行**——微信同 appid 多次调 gettoken 会使旧 token 失效，并发推会全部报 `40001 invalid credential`（token 互踩）。用 for 循环逐篇跑，每篇间隔 2 秒。若曾并行失败过，先 `rm -f cache/token.json` 清缓存再串行重推。**index.js 已内置封面冲突硬拦截（2026-08-27 加）**：正文 `body_markdown` 里若引用了 `--image` 传入的封面文件，脚本会报 `✗ 硬拦截：正文引用了封面文件` 并 exit 1，不生成草稿——生成 article.json 时务必保证正文图片引用 ≠ 封面文件，否则推不动。

每篇终端打印 `草稿 media_id` 后，该篇就在草稿箱。**记下 media_id 写日志要用。**

## 写日志（步骤 7）

## 结尾 CTA 卡片（必须按此结构生成）

文章正文结束后，自动追加一个 CTA 卡片。**结构按 theme 分 2/3/4 层**（minimal 2 层 / cool 3 层 / warm 4 层），**标签、引导语、图标行文案按标题 hash 从文案池确定性轮换**（非每篇一字不差，破同质化），只有「提问」和「关注按钮文字」两个变量由文章字段指定。配色全跟 theme，按钮不再是固定橙。`src/html.js` 实现，详见该文件 `CTA_TAGS`/`CTA_MIDS`/`CTA_ICONS` 池。

### 视觉结构（从上到下）

> ⚠️ 以下为旧「全橙」规格的历史描述，保留作字段含义参考。实际配色随 theme（容器底=t.bg、标签色=t.accent、按钮=t.btnBg），文案随标题 hash 从池轮换，**以 `src/html.js` 的 `ctaBlock` 实现为准**。

1. **容器**：渐变橙底（`#FFF4EC → #FFEEE0`）+ 圆角 10px + 浅橙描边（`#FFE0CC`）+ 内边距 22×20px + 居中文字
2. **标签**：白底圆角胶囊，文字「留 言 互 动」，橙色（`#FF6B35`），字号 12px，字间距 3px
3. **提问**（加粗深色，字号 16px，行高 1.6）：来自 `cta_question` 字段
4. **引导文字**（字号 14px，浅褐 `#7a4a2a`，行高 1.7）：「评论区聊聊，是哪句话戳穿了你？<br/>点赞 + 在看，让更多人看见。」
5. **分隔线**：浅橙色细线，宽度 60%，居中
6. **关注引导**（字号 13px，灰色）：「👇 长按关注，每天一篇心里话」
7. **关注按钮**：橙色渐变胶囊（`#FF6B35 → #FF9A6B`），白字加粗，字号 14px，字间距 2px，带橙色阴影。文字来自 `cta_follow` 字段，默认「点 个 关 注 不 迷 路」
8. **图标行**（字号 13px，灰色，字间距 4px）：「❤ 点赞 · 在看 · 转发」

### 为什么这个结构有效

- 标签 + 提问双层抓住注意力，标签像「彩蛋」让人想看下文
- 提问具体到场景/对象/反应（不是「你有没有过...」这种 yes/no 问题），读者脑子会自动浮现故事
- 引导文字明确告诉读者三个动作：评论、点赞、在看
- 「👇 长按关注」用 emoji + 具体动作，比「关注我」更有召唤力
- 渐变按钮是整页唯一的高饱和色块，视觉重心，引导点击
- 图标行最后兜底，给那些不想评论但愿意点赞的读者一个轻量动作出口

### CTA 提问选型规则

每篇文章的 `cta_question` 从 [[04-writing-pools]]「CTA 提问类型」20 类随机抽，避近 5 篇（读日志 `cta提问类型` 列），尽量贴合主题（从主题最贴的 3-5 类里随机抽，撞近 5 篇则换），记日志。主题大类作参考（不必硬绑）：

- **身份/自我认知类**（被戳穿、被定义、被替代）→ 优先 身份类/反问类/判断类
- **回忆/共鸣类**（看球、家乡、青春）→ 优先 故事类/回忆类/共鸣类
- **反应/冲突类**（被怼、被误解、被夸）→ 优先 反应类/选择类/评价类
- **多方关系类**（家庭、职场）→ 优先 三选一类/建议类/对比类

提问要扣住文章高潮那句话，问「是什么时候 / 是哪场 / 是哪一句」，不问「有没有」。

## 已知坑

1. **并发推草稿必崩**：两篇以上并行跑 `node src/index.js` 会全部 `40001 invalid credential`。微信同 appid 多次 gettoken 互相使旧 token 失效。**一律串行推**（for 循环 + sleep 2）。2026-06-30 实测 4 篇并行全崩，改串行 8 篇全成。
2. **JSON body 内引号一律用中文「」**：`body_markdown` 里若用 ASCII 双引号 `"..."`（如 `"我家狗不咬人"`）会破坏 article.json 解析，推送报 `Unexpected token X in JSON`。生成时直接用「」，不要用 ASCII "。2026-07-05 实测 4 篇因此首推失败，改「」后重推全成。
3. **token 2 小时过期**：脚本自动缓存 `cache/token.json`，过期前 5 分钟刷新。
4. **IP 白名单**：已配置 `124.90.104.29`，换网络环境跑不动时去公众号后台「基本配置 → IP 白名单」加新 IP。
5. **中文路径 cp 报错**：Windows 上 `cp src dst` 含中文路径会失败，改用 `cd` 进目录后 `mkdir -p 文件夹名 && cp 文件 文件夹/`，或直接用 Write 工具写文件。
6. **大图 Read 失败**：原图太大 Read 不进来，先用 `sharp.resize(900).jpeg({quality:75})` 生成预览版。
7. **微信剥样式**：所有样式必须 `style="..."` 内联，`<style>` 和 class 会被剥光（已修）。
8. **marked v12 签名**：`heading(text, level)` 不是 `{text, depth}`，改 renderer 要注意（已修）。
9. **sharp 中文渲染**：依赖系统字体（微软雅黑），文字渲染失败会回退到无文字封面，不会让管线挂。
