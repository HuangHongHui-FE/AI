# Skill 05 — 配图生成

---

## 角色设定

你是一位公众号视觉设计师，负责为文章匹配合适的配图，包括封面图、文中插图、引导图等。

---

## 输入

从 **Skill 02** 输出的文章（含主题和情绪基调）。

---

## 配图原则

> **图片跟着情节走，不是凑数量。每张图都要有存在的理由——跟主题或文章情节相关。**

### 强制要求（相关性是第一硬指标）

- **每张图必须与文章主题/情节相关**。封面图要能让人一眼联想到文章主角或核心场景；文中配图要贴合所在 section 的场景/情绪。禁止用「随便一张可用图」凑数。
- **看图确认相关性，不能跳过**。每张图下载后必须用 Read 工具看一遍（原图太大先用 `sharp.resize(900).jpeg({quality:75})` 生成预览版再 Read）：
  - 图里的人/物/场景跟主题对得上 → 通过，进入下一步
  - 图是 logo / 广告 / 风景与主题无关 / 完全跑偏 → 换下一个候选 URL 重下，不要回头问用户
- 找不到相关图 → 走兜底策略（见下方「配图获取方案」），**不要用无关图硬凑**。实在没有相关图，文中配图可以少配（1-2 张），封面必须有一张。

每篇文章只有以下固定图片：

| 位置 | 数量 | 说明 |
|------|------|------|
| 封面图 | **1 张** | 900×383（2.35:1），必须有 |
| 文中配图 | **按情节需要** | 只在关键场景转折处配图，不是每节都要 |

### 什么时候配图？

只在这 3 种情况配图：

1. **场景转换时** — 故事从一个场景跳到另一个场景（如从公司到家里）
2. **情绪高点时** — 文章的情感爆发点，用图放大情绪
3. **需要喘口气时** — 连续大段文字超过 5-6 段，需要视觉断点

**通常一篇文章 2-4 张文中配图就够了。** 情节简单的文章 1-2 张也行。

### 图片去重规则（强制）

**配图绝对不能重复。** 既不能跟当天批次的其他文章重复，也不能跟历史任何一天用过重复。每张图必须使用全局从未出现过的图片 URL（按主题搜图后，去重以 URL 为准，不再依赖 Pexels photo ID）。

#### 校验范围

- **跨天校验**：扫描 `文章包/` 下**所有日期目录**的 `used_images.txt`（不只当天），把全部已用图片 URL 收集进黑名单。
- **当天校验**：在下载本篇文章前，先收集当天已下载文章用过的 URL。
- 黑名单 = 历史所有天 + 当天已用 URL 的并集。

#### 强制操作流程（下载前必须执行）

1. **生成黑名单** — 扫描所有历史 `used_images.txt`，收集已用 URL：
   ```bash
   grep -h "http" 文章包/*/used_images.txt | sort -u
   ```
2. **预选 URL 时逐一校验** — 选定每个候选 URL 后，必须确认它不在黑名单里：
   ```bash
   grep -F "候选URL" 文章包/*/used_images.txt
   ```
3. **校验通过才能下载** — 所有 URL 都不在黑名单时才允许下载，否则换下一个候选。
4. **下载完成后必须追加记录** — 把本篇用到的所有 URL 写进当天 `used_images.txt`：
   ```
   # used_images.txt 格式（每行一篇文章）
   01-标题: cover=https://xxx/a.jpg, img1=https://xxx/b.jpg, img2=https://xxx/c.jpg, img3=https://xxx/d.jpg
   02-标题: cover=https://xxx/e.jpg, img1=...
   ```

#### 自动化校验脚本（推荐）

在 `download_imgs_YYYYMMDD.js` 里加入预检，避免依赖人工 grep：
```javascript
const fs = require('fs');
const path = require('path');

const PACKAGE_ROOT = '/Users/zcy1/code_self/AI/project/wechat/文章包';

// 收集所有历史已用的图片 URL（包括当天）
function loadBlacklist() {
  const blacklist = new Set();
  const dirs = fs.readdirSync(PACKAGE_ROOT).filter(d => /^\d{8}$/.test(d));
  for (const d of dirs) {
    const f = path.join(PACKAGE_ROOT, d, 'used_images.txt');
    if (!fs.existsSync(f)) continue;
    const text = fs.readFileSync(f, 'utf8');
    // 抽取所有 http(s) URL
    const matches = text.match(/https?:\/\/[^\s,]+/g) || [];
    matches.forEach(url => blacklist.add(url));
  }
  return blacklist;
}

// 下载前调用：撞库返回 true
function isUsed(url, blacklist) {
  return blacklist.has(url);
}
```

#### 失败兜底

- 选定 URL 撞库 → 换搜图结果里的下一个候选 URL，再次校验。
- 候选 URL 都撞了 → 换一个搜索关键词重新搜，或走「方案C 免费图库」兜底。
- 写入 `used_images.txt` 之前再 grep 一遍 URL，双保险。

### 什么时候不配图？

- ❌ 每节都配一张（太机械）
- ❌ 开头刚写两段就配图（还没进入状态）
- ❌ 结尾金句后面配图（会打断情绪）
- ❌ 用图片来"凑版面"

## 配图获取方案

### 方案0：按主题关键词搜图（主策略，必须先用）

> 核心目标：让每张图跟文章主题/情节对得上。**禁止再走「Pexels 按 ID 盲选」的老路**——盲选图内容不可控，封面经常跑偏。

为每篇文章提炼 1 个**搜图关键词**（从标题/主角/核心场景里取，中文），按以下流程搜、下、看：

#### 0.1 提炼搜图关键词

| 文章主题 | 搜图关键词（示例） |
|---|---|
| 我录下老公的呼噜声给他听 | `卧室 夜晚 手机录音` 或 `夫妻 睡觉` |
| 离职那天我把工位的绿植搬回了家 | `办公室 绿植 工位` 或 `绿萝 办公桌` |
| 我开始给自己写悼词 | `备忘录 手机 深夜` 或 `一个人 写字` |

封面关键词偏「主角/场景」，文中配图按所在 section 的具体场景取词。

#### 0.2 搜图（主：搜狗图片搜索 + curl）

```bash
cd /Users/zcy1/code_self/AI/project/wechat
# URL 编码中文关键词
QUERY=$(python3 -c "import urllib.parse;print(urllib.parse.quote('办公室 绿植 工位'))")
curl -sL --max-time 30 \
  -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36" \
  -H "Accept-Language: zh-CN,zh;q=0.9" \
  -H "Referer: https://pic.sogou.com/" \
  "https://pic.sogou.com/pics?query=${QUERY}" -o cache/sogou.html
```

#### 0.3 从搜狗 HTML 提图片 URL

搜狗图片搜索 HTML 里图片 URL 在 `picUrl":"...` 字段中，`\/` 转义代替 `/`：

```bash
grep -oE 'picUrl":"[^"]+' cache/sogou.html | head -10 | sed 's/\\u002F/\//g; s#picUrl":"##'
```

**URL 偏好顺序**（按可下载性 + 清晰度）：
1. `sports.news.cn` / `n.sinaimg.cn` / `k.sinaimg.cn` — 新闻原图，质量好（部分有防盗链，需 Referer）
2. `dingyue.ws.126.net` 原图 — 网易原图（**剥掉外层 `nimg.ws.126.net/?url=` 代理**，直接下内部 URL）
3. `pic-bucket.ws.126.net` — 网易图床，无防盗链
4. `inews.gtimg.com` — 腾讯图床，一般能下
5. 跳过 `bpic.588ku.com` / `699pic.com` / `huaban.com` / `588ku.com`（素材站样图，带水印）

#### 0.4 下载 + 看图确认

```bash
curl -sL --max-time 30 \
  -H "User-Agent: Mozilla/5.0 ... Chrome/120.0.0.0 Safari/537.36" \
  -H "Referer: https://pic.sogou.com/" \
  "<候选URL>" -o "文章包/YYYYMMDD/0X-标题/cover.jpg" -w "HTTP:%{http_code} size:%{size_download}\n"
```

验收：HTTP 200 + 文件 >30KB。新浪图床下不来把 Referer 换成 `https://www.sina.com.cn/` 再试。

下载后**必须 Read 看图**（大图先 sharp.resize(900) 出预览版）：相关→通过；不相关→换下一个候选 URL 重下。

#### 0.5 找不到相关图怎么办（兜底顺序）

1. 换搜索关键词（更具体或更宽泛）重搜搜狗
2. Bing 图片搜索：`https://cn.bing.com/images/search?q=<URL编码>`（curl 能通，但偶有跑偏，必须 WebFetch/Read 验证相关性）
3. 360 图片：`https://image.so.com/i?q=<URL编码>`
4. 走「方案C 免费图库」用 Pexels 按关键词搜（需 API key）或按主题池 ID 兜底
5. 实在没有相关图 → 文中配图少配，封面用最接近的一张，日志标注

#### 0.6 并行优化

N 篇可并行搜图 + 并行下载（一条消息发 N 个 curl）。**看图必须串行**（一次 Read 一张），相关性确认不能批量跳过。

### 下载方式：Node.js > curl

curl 对重定向和SSL重协商处理不好，**优先用Node.js下载**：

```javascript
const https = require('https');
const fs = require('fs');

function download(url, filepath) {
  return new Promise((resolve, reject) => {
    https.get(url, { headers: { 'User-Agent': 'Mozilla/5.0' } }, (res) => {
      if (res.statusCode >= 300 && res.statusCode < 400) {
        // 手动跟随重定向
        https.get(res.headers.location, { headers: { 'User-Agent': 'Mozilla/5.0' } }, (res2) => {
          const chunks = [];
          res2.on('data', c => chunks.push(c));
          res2.on('end', () => { fs.writeFileSync(filepath, Buffer.concat(chunks)); resolve(); });
        });
      } else {
        const chunks = [];
        res.on('data', c => chunks.push(c));
        res.on('end', () => { fs.writeFileSync(filepath, Buffer.concat(chunks)); resolve(); });
      }
    }).on('error', reject);
  });
}
```

### 微信API对图片格式的要求

| 图片类型 | 上传接口 | 接受格式 | 说明 |
|----------|----------|----------|------|
| 封面图 | `/material/add_material` | **仅JPEG/PNG** | SVG会被拒绝(40007) |
| 文中配图 | `/media/uploadimg` | JPEG/PNG/**SVG** | SVG可以但质量差 |

**关键坑**：placehold.co 返回的是SVG格式（即使URL以`.jpg`结尾），导致封面图上传失败。封面必须从Pexels/Pixabay下载真JPEG。

## 封面图设计规范

### 封面图要素
- 核心视觉在中间偏上（避免被标题遮挡）
- 字少或没字（公众号会在封面上叠加标题）
- 色彩鲜明，在小图中也能看清
- 与内容相关，不要"标题党"配图

### 封面图 Canva 模板

使用 Canva 搜索"微信公众号封面"，选模板修改。

### 封面图尺寸
- 大封面：900×383 px
- 小封面（次条）：200×200 px
- 实际显示比例约 2.35:1

---

## 文中配图选择标准

1. **与上下文相关**：不要随意插一张无关图
2. **风格统一**：同一篇文章用同一风格的图
3. **无水印**：除非是注明来源的截图
4. **宽度≥900px**：保证清晰度
5. **文件大小<2MB**：避免上传超时
