## 项目定位（多书隔离，每书独立目录）

本号**固定写男频都市爽文**，连续剧式连载（每本书一条主线，人物/世界观贯穿，逐章推进）。番茄流量基本盘，读者基数最大、最容易起量。

### 📚 多书隔离机制（核心）

**每本书一个独立目录 `books/<书名slug>/`，互不干扰**，skill 是通用流程，不写死任何一本书。后续开新书**不改 skill**，直接新建目录即可：

```
books/<书名slug>/
  settings.json    书名/作者/方向/简介/更新策略（本书唯一配置，续写时读它）
  characters.json  主角/配角/女主角色卡
  world.md         世界观/力量体系/系统规则
  outline.md       全书剧情蓝图（卷+章节点）
  history.md       剧情进度日志（已写/伏笔/下一章提示）
  chapters/NN.md   已写章节（markdown）
```

**当前书**（从 `books/*/settings.json` 读取，或用户指定）：
- 已有：`books/jianbing-shenghao/`《摊煎饼的我，签到成了神豪》（煎饼大侠，都市脑洞·签到系统流×神豪县城流×烟火气）

**怎么区分是哪本书**：
- 用户说「写一章/写三篇/更新」默认续**当前书**（最近操作/最后更新的那本，或用户点名的书）。
- 用户说「**开新书**」→ 新建 `books/<新slug>/` 完整目录（settings/characters/world/outline），详见「开书流程」。
- 用户说「写 XX 那本」→ 切到指定书的目录。
- **每本书的 `history.md`/`outline.md`/`chapters/` 独立**，写 A 书绝不影响 B 书。

### 按需续写（默认）

- 用户说「写下一篇」「继续写」「写三篇」即续写**当前书**下一章，每章 2000-4000 字。
- 每次续写流程：读当前书 `history.md` 接剧情 → 读 `outline.md` 定位章节节点 → 抽套路避撞 → 生成 → 自查 → **本地产出两份**（见下「本地产物规范」）→ 更新 history + logs → 汇总给用户（发草稿/发布按用户指令）。

### 本地产物规范（每章必产出两份）

每章写完后，**除了创作稿，本地必须再生成一份成品**，供用户直接阅读/复制发布：

```
books/<slug>/chapters/NN.md                     # ① 创作稿（章节正文，本项目内部）
output/YYYY-MM-DD/NN-<章号slug>/chapter.md      # ② 干净发布稿（仅标题+正文，可直接复制）
output/YYYY-MM-DD/NN-<章号slug>/preview.html    # ③ 本地预览（手机/浏览器阅读排版）
```

- **chapter.md**：去掉内部注释/提示，只有 `# 第N章 标题` + 正文，用户复制即可发布。
- **preview.html**：内联 CSS 的干净排版（正文 17px、行高 1.9、章节标题加粗），手机可读，方便发前检查。
- 之后每章写毕即时生成。

## 番茄平台规范（写书前必读）

### 连载机制

- **日更是命**：番茄推荐强依赖更新稳定性，断更掉量。默认**日更 4000-6000 字**（2 更×2000 或 3 更×2000）。
- **核心指标**：追读率、完读率、章末停留。前几章留存决定推荐上限。
- **黄金三章**：开书前三章必须抓住人——第一章冲突前置 + 金手指曝光 + 第一个小爽点落地。铺垫不得超过半章。

### 章节形态

- 每章 **2000-4000 字**（番茄基础 2000/章，3000+ 更佳）。
- 每章**至少 1 个爽点**（打脸/收获/升级/身份揭露/反转），章尾**必有钩子**（悬念/冲突升级/新变数/敌人登场）。
- 章节标题 5-15 字，是爽点/钩子的浓缩（如「第3章 一个电话，整个圈子沸腾」）。

### AI 标注与原创合规

- 番茄对 AI 辅助创作有标注要求：**发布时在番茄作家后台如实勾选「AI 辅助创作」标注**，具体以作家助手后台提示为准，不假装纯人工。
- 规避「低价值 AIGC」判定（对照番茄/字节对 AI 内容的判定逻辑）：**禁套路同质化**——金手指/开局/打脸/钩子逐维轮换，不篇篇同一个套路；**有人物有事件有冲突**，非干巴巴的设定堆砌。

### 敏感红线

- 不涉政治人物评价、不涉时政敏感话题。
- 都市爽文可以写「富人/势利眼/反派被打脸」，但**主角不得践踏法律底线**（杀人越货、黑帮火并过度渲染），打脸须在合法框架内（报警/举报/商业碾压/实力碾压）。
- 不写涉黄擦边、血腥过度渲染；不具体教犯罪手段。

### 女主线与感情线红线（合规暧昧张力，每本书通用）

**通用规则**（适用于所有书）：女主线/感情线全程**合规**，吸引力来自「暧昧张力 + 情感拉扯」，不靠擦边。

**✅ 可以写**：暧昧互动（对视/调侃/嘴硬心软/递东西碰到手/护住/并肩心跳）、情感拉扯（前任后悔对照/女主吃醋不点破/「工作」当借口的欲拒还迎）、侧面气质描写（「扎了马尾，走过来时闻到一丝淡淡的洗衣粉味」「低头吃煎饼，耳根发红」）、脸红心跳点到即止。

**🚫 绝对不写**（番茄红线，写了封书封号）：露骨身体部位/性行为/性暗示/擦边挑逗；引导性着装描写（薄纱/低胸/清凉）；卧室浴室大尺度场景；露骨台词。

> 每章自查加一条：本章情感描写是否「点到即止」？某句读起来像擦边 → 立即改写为含蓄表达。

**当前书实例**（《摊煎饼的我，签到成了神豪》`books/jianbing-shenghao/`）：女主**苏晚**（县文旅局产业科科员，第 5 章登场），与陈默不打不相识→互相欣赏→暧昧张力。角色卡见 `books/jianbing-shenghao/characters.json`，剧情嵌入见 `books/jianbing-shenghao/outline.md` 第 4-20 章。其他书各自的女主线在各自 `characters.json`/`outline.md` 里定义。

## 开书流程（`开新书` 时走）

### 1. 建书目录

```
books/<书名slug>/
  settings.json    书名/作者签名/简介/更新策略/简介文案
  characters.json  主角团固定角色卡（身份/性格/金手指/外貌/口头禅）
  world.md         世界观（都市背景/力量体系/等级/势力）
  outline.md       大纲（主线 + 卷 + 章节点）
  chapters/01.md…  已写章节（markdown）
  history.md       剧情进度日志（每章更新：本章事件/埋的伏笔/未接的线）
```

`characters.json` 结构参考：

```jsonc
{
  "book": "龙王归来",
  "protagonist": {
    "name": "林北",
    "identity": "落魄外卖员，实为隐世龙王",   // 身份反差是都市爽文爽点核心
    "personality": "前期隐忍，触底线则狠辣",
    "goldenFinger": "龙王军令（可号令地下势力）",
    "quirk": "被小区保安催过房租"
  },
  "supporting": [
    { "name": "林母", "role": "开篇靠她制造压迫感", "desc": "催婚、嫌儿子没出息" }
  ]
}
```

### 2. 定世界观（world.md）

一句话都市背景 + 力量/社会体系。都市爽文三种体系任选一种为主：

- **纯现实**（战神/神豪/神医回归）：靠身份/财富/医术碾压，不涉超自然。
- **低魔都市**（异能/古武隐世）：现实世界 + 隐藏的超自然圈子。
- **系统流**（系统/面板）：主角带金手指，任务/升级/兑换。

### 3. 写简介（settings.json 的 `intro`）

番茄简介 = **前 300 字钩子**（不是作者签名，签名在账号资料里）。写法：

```
一句话悬念/身份反差 → 主角现状被踩 → 金手指即将改变一切 → 一句让人想追的钩子
```

示例：

> 三年前，林北被豪门逐出家门，一无所有。三年后，他身披龙纹回到这座城市——当年踩他的人，都在瑟瑟发抖。有人跪着喊他「龙王」，有人还在嘲笑他外卖员。直到他站在那位不可一世的大少面前，所有人都听见他说：「这栋楼，是我名下的。」

### 4. 黄金三章大纲（outline.md 前 3 章节点）

- 第1章：开篇冲突（被踩/被轻视/困境）+ 金手指现身 + 小爽点。
- 第2章：金手指初用，第一次小打脸，敌人/反派登场。
- 第3章：第一个完整打脸闭环，确立主角实力定位，抛主线悬念。

### 5. 主线大纲（outline.md）

主线 + 3-5 卷（每卷一个阶段目标），卷下章节点（每 5-10 章一个事件高潮）。不必一次性写全，先写主线 + 前 2 卷，边写边补。

## 章节写作模板

### 生成流程

1. 读 `history.md` 接剧情、读 `characters.json` 保人物一致、读 `outline.md` 定位当前卷章。
2. 从各轮换池抽套路（金手指/开局/打脸/钩子），记入日志避撞。
3. 按模板生成正文。

### 章节结构（2000-4000 字）

```
[章名：5-15字，浓缩爽点/钩子]

开头 1-2 段：上章尾钩子接续 or 直接推进，前 3 行内抛出本段小冲突/小目标
中段：事件推进 + 爽点落地（打脸/收获/升级/揭露）
——爽点过程要「先压后扬」：让反派/路人先嘲讽踩压，主角再雷霆反击，反差才有爽感
章尾 1-2 段：新钩子（悬念/冲突升级/敌人登场/新金手指线索），别把本段爽完就收
```

### 男频都市爽文爽点写法

- **打脸**：反派/势利眼先踩 → 主角亮底牌 → 围观者震惊反转 → 反派失态。围观群众是「震惊工具人」，写他们的反应放大爽感。
- **身份反差**：主角表面落魄（外卖员/保安/赘婿），实为大人物。前期被踩，后期身份揭开。
- **收获**：财富/地位/人情/功法，具体到数字和画面（「银行卡到账 3000 万」「全场死寂」）。
- **升级**：力量或势力体系内推进，给明确的阶段性提升。

## 自查 / 硬门

### A. 番茄连载硬门

| 门 | 规则 |
|---|---|
| 字数 | 2000-4000 字/章，不足扩写、超了精简 |
| 爽点 | 每章 ≥1 个落地爽点（打脸/收获/升级/揭露），无爽点回炉 |
| 钩子 | 章尾必有悬念/升级，不能平收 |
| 人物一致 | 主角/配角姓名、金手指、身份与 `characters.json` 一致，不串线 |
| 剧情接续 | 和上一章、大纲对得上，`history.md` 记的伏笔没被吃书 |

### B. AI 痕迹自查（对照番茄/字节 AIGC 判定逻辑）

- [ ] 金手指/开局/打脸/钩子四维与近 5 章不撞形
- [ ] 有具体人物、场景、对白，不是设定堆砌
- [ ] 对话口语化（「你算什么东西」「跪下」「这笔账我记下了」），不书面腔
- [ ] 打脸过程「先压后扬」有反差，不是平铺直叙
- [ ] 无「总而言之/综上所述/不由得让人深思」等 AI 八股词
- [ ] 章名 5-15 字且是钩子/爽点浓缩，不「第X章 新的开始」这种水名

### C. 敏感红线

- [ ] 不涉政治/时政敏感
- [ ] 打脸在合法框架内（不教犯罪、不渲染黑帮暴力过度）
- [ ] 无涉黄擦边、无血腥过度

## 按需续写模式（用户说「写下一篇/写三篇」就写）

- **不做定时任务**。用户说「写下一篇」「继续写」「更新一章」「写三篇」等，即续写 `books/jianbing-shenghao/` 的下一章。
- **每次续写流程**：读 `history.md`（剧情进度+下一章提示）→ 读 `outline.md` 定位当前章节点 → 抽套路避撞 → 生成 → 自查 → 存 `chapters/NN.md` → 更新 history + logs → 本地产物（chapter.md + preview.html）。
- **批处理（用户说「写三篇」等）**：一次连续写 N 章（N=用户指定），每章按上述流程独立写、独立更新 history/logs，章号连续递增，剧情不断档。三章可围绕当前卷的连续节点展开。

### 发稿指令（用户说「发草稿」或「发布」）

- 用户说「**发草稿**」→ 把指定章节（或刚写的几篇）**存草稿箱**（三步接口，见「发布流程」）。
- 用户说「**发布**」→ 才执行**发布**（`publish_article` 提交发布）。**默认永远只存草稿箱，发布只在用户明确说「发布」时执行。**
- 若用户只写不指定「发草稿/发布」，默认只写本地 + 提醒用户草稿箱检查后手动发。

## 发布流程（铁律：默认只存草稿，发布需用户明确指令）

> ⚠️ **最重要的一条红线**：脚本**默认只把章节存入草稿箱**，**绝不自动发布、绝不定时发布**。**只有在用户明确说「发布」时**，才执行发布。任何一次发章，默认只存草稿。

### 自动化现状（已跑通）

novel 项目已配好 `src/publish.js`，读 `.auth/fanqie.json` 鉴权调番茄真实 HTTP 接口（book_id 见 `books/jianbing-shenghao/settings.json`，或 `npm run publish -- --list` 查询）：

```bash
npm run publish -- --book <book_id> --file "output/YYYY-MM-DD/NN-<章名>/chapter.md"   # 存草稿箱（默认）
npm run publish -- --list                                                             # 列书
```

**存草稿的正确三步接口**（2026-08-11 实测）：
1. `POST /api/author/article/new_article/v0/` — 建空草稿，得 `item_id`（参数 book_id + need_reuse=1）
2. `POST /api/author/article/cover_article/v0/` — 填标题+正文 HTML（item_id/title/content/volume_id/volume_name）
3. `POST /api/author/article/save_doc_history/v0/` — 标记「已保存草稿」（book_id + item_id）

**发布（仅用户明确说「发布」时）**：走 `POST /api/author/article/publish_article/v0/`（提交发布/上架）。**默认禁用**，只在用户明确指令时用。

- 发章后提示「已存入草稿箱（item_id: …）」。**若报 `code=-1019 提交字数超出每日上限`**，是番茄单日字数硬上限（新手约 1 万字/天），当天额度用尽，**隔天再发**，不是 bug。
- 鉴权失效（cookie 约 1-2 月过期）报「鉴权失效」，让用户重跑 `npm run login` 或重新抓 cookie。

### 手动发布（唯一允许的发布方式）

1. 章节已存草稿箱（上面脚本）。
2. 用户打开**番茄作家助手** → 草稿箱 → 找到该章草稿。
3. 用户检查正文、**补封面**、确认无误后，由**用户手动点「发布」**。
4. 发布时在后台**如实勾选「AI 辅助创作」标注**（平台政策以作家助手提示为准）。

> 不做假装纯人工的操作——AI 辅助标注照实填；**发布按钮永远在用户手里**。

## 已知坑

1. **番茄无草稿 API**：发布只能手动复制或后续 Playwright 半自动，别承诺全自动。
2. **断更掉推荐**：日更是命，默认按 4000-6000 字/天生产；用户长期不发章节要提醒。
3. **简介 ≠ 签名**：书简介是「前 300 字钩子」写在 settings.json；作者签名（个人简介）在账号资料里（见 `docs/creator-account.md`），两码事别混。
4. **黄金三章不能铺垫**：第一章不亮金手指/不给爽点，追读直接崩，前几章决定推荐上限。
5. **打脸要合法**：都市爽文「爽」在碾压的快感，不在越界违法；别写主角杀人越货。
6. **套路轮换是硬要求**：男频爽文同质化最重，四维池 + 日志避撞是防「低价值 AIGC」判定的核心手段。
7. **AI 标注照实填**：不假装纯人工，后台勾「AI 辅助创作」。
8. **伏笔要记账**：`history.md` 埋的伏笔必须在后续章节收，别吃着吃着忘了（读者记得比你清楚）。

## 串流程速查

```
用户「写一章」
 → 定位当前书：读 books/<slug>/settings.json + history.md + outline.md + characters.json
 → 定本卷本章节点：读 outline.md 当前卷
 → 抽套路：金手指/打脸/钩子 从池随机，grep logs 避近5章
 → 生成正文：章名（钩子浓缩）→ 开头接续/推进 → 中段先压后扬打脸爽点 → 章尾新钩子
   （字数 2000-4000，人物与角色卡一致，剧情与大纲/历史接续）
 → 自查硬门：字数/爽点/钩子/人物一致/剧情接续 + AI 痕迹 + 敏感红线，不过回炉
 → 存 books/<slug>/chapters/NN.md
 → 更新 books/<slug>/history.md（剧情+伏笔）
 → 写 logs/YYYY-MM-DD.md 一行（四维已用值）
 → 提醒用户：番茄作家助手复制发布，后台勾「AI 辅助创作」标注

用户「开新书」
 → 定方向（默认男频都市爽文，可指定具体子类/金手指）
 → 建 books/<书名slug>/：settings.json + characters.json + world.md + outline.md
 → 写简介（前300字钩子）→ 黄金三章大纲 → 生成第1章 → 同上自查/存/日志
```
