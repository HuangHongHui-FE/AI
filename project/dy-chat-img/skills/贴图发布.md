# 微信公众号贴图发布 Skill

> 项目根目录：`/Users/zcy1/code_self/AI/project/dy-chat-img`
> 调用方式：用户说「发贴图」「发图片消息」「发小绿书」等，或发来抖音链接
> 发布类型：微信公众号图片消息（贴图 / 小绿书），对应 `article_type: "newspic"`
> **数量不限**（2026-07-26 修订）：写好一篇就推一篇，不再限制每日篇数；去同质化靠领域/篇型/图源错开，不靠数量上限。同 AppID token 互踩，多篇串行发布、禁止并发。
> **选题源风险（重点）**：微博热搜是公共榜单，直接转述话题/排名/热度值=搬运+同质化+低信息量+低价值AIGC 四条连锁踩雷。把热搜只当**选题线索**，内容用实拍/自制图+自己查的事实，不照搬榜单原文与热度值。

## 触发条件

用户表达想要发布**图片消息 / 贴图 / 小绿书**类型到微信公众号草稿箱，或发来抖音链接要求生成贴图，例如：

- 「发贴图」
- 「发图片消息」
- 「发小绿书」
- 「今天发一篇贴图」
- 「这是抖音链接，帮我发成贴图」
- 用户直接发来 `https://v.douyin.com/xxxxx/` 类链接

## 执行流程

触发后按以下顺序执行，**不再问澄清问题**，中途模糊判断（标题、配图、文案风格）自己定：

### 情况一：用户提供抖音链接

#### 1. 下载抖音原图

运行 `download_douyin.py`：

```bash
python3 download_douyin.py --url "https://v.douyin.com/xxxxx/" --out douyin_raw_imgs
```

脚本依赖 Playwright + Chromium，会：
- 用无头浏览器打开抖音页面
- 移除登录弹窗和遮罩
- 拦截页面图片的网络响应
- 把高清原图保存到 `douyin_raw_imgs/`

#### 2. WebP 转 JPEG

抖音原图可能是 webp 格式，微信 `material/add_material` 不直接支持，需要转换：

```bash
mkdir -p douyin_raw_imgs_jpg
for f in douyin_raw_imgs/*.webp; do
  sips -s format jpeg "$f" --out "douyin_raw_imgs_jpg/$(basename "$f" .webp).jpg"
done
```

#### 3. 剔除 UI/emoji 缩略图

下载的图里混有 UI 图标、头像、emoji 动图。按**像素尺寸**精确剔除：

```bash
for f in *.jpg; do
  w=$(sips -g pixelWidth "$f" | awk '/pixelWidth/{print $2}')
  h=$(sips -g pixelHeight "$f" | awk '/pixelHeight/{print $2}')
  echo "$f ${w}x${h}"
done | sort -k2 -n
```

剔除规则：宽或高 <300px 的小图（73x73、100x100、144x144 等 emoji）、细长条（如 774x92 横幅、128x7680 装饰条）、明显是头像/图标的图。保留真正正文图。

#### 4. OCR 识别 + 主题分析 + 撰写高互动配文

图片内容不限于聊天记录，可能是漫画、截图、海报等。先识别图中文字，再归纳主题：

```bash
# macOS 原生 Vision OCR，逐张提取文字（脚本已存于项目根 ocr.swift）
swift ocr.swift img_xxx.jpg img_yyy.jpg ...
```

OCR 若返回「无文字」（纯插画/漫画），改用**视觉读图**（Read 工具）理解画面内容。

综合所有图文字/画面，**归纳出一个主题**，再据此生成 `贴图草稿-YYYYMMDD.json`：

- `title`：贴合主题、有钩子、≤22 字，能让人忍不住点开
- `summary`：一句话总起，作为 digest
- `cover.placeholder`：封面图片本地文件名（选最有冲击力的一张）
- `images`：正文图片列表（只管挑图与上传，不参与文本）
- `body`：整篇主题正文，一段或几段讲透共同主题，有内涵、有事实或独家视角，字数不限（见「文案核心原则」）

**文案核心原则——整篇讲透主题，不逐图配文：**

- 一组贴图必有一个**共同主题**，文本**只把这个主题讲透**，不逐张图介绍（不要写「这张图是 XX」、也不要每图配一句金句并列）。
- 文本放在草稿的 `body` 字段，是一段（或几段）连贯的主题正文，有内涵、有观点、有信息增量，不是图解说明，也不是并列金句。
- `summary` 仍作为 digest（一句话总起），`images` 数组只管挑图与上传，**不参与文本拼接**（脚本已改为 `content = draft.body`，旧逐图草稿仍兼容）。
- 字数不限，但要有真实事实或独家视角打底——纯情绪感悟会被判低信息量。
- **body 灵活写，别堆模板**：可选素材有——把热点讲明白、提炼主题、升华（从下方「升华素材箱」挑一种角度深挖，每篇挑不同、不雷同）、科普延伸（健康/科学/物理/材料/经济等硬知识）。按话题自然组织，**不强求齐全、不固定顺序**，每篇随机组合；其中科普是好信息增量来源，话题合适就用。
- 科普基于可靠常识，不确定的查证或用定性表述，**不编造伪科学数据**；选角自然贴合热点，不硬塞。
- 口语化、人设化、不 AI 味；结尾**不用**「评论区聊聊」「你呢」之类套路话术，自然收束即可。

#### 5. 复制图片到项目根目录

```bash
cp douyin_raw_imgs_jpg/img_xxx.jpg cover-YYYYMMDD.jpg
cp douyin_raw_imgs_jpg/img_yyy.jpg img1.jpg
cp douyin_raw_imgs_jpg/img_zzz.jpg img2.jpg
# ...
```

**图片保持原始比例，不裁剪。** 微信图片消息会自适应显示，强行裁成统一比例反而会切掉正文内容（如长条聊天记录、竖图关键区域）。直接用转码后的原图即可。

封面 `cover-YYYYMMDD.jpg` 可与正文第一张相同，选冲击力最强的一张。

#### 6. 更新 Access Token

打开 `post_draft.js`，检查顶部 `ACCESS_TOKEN` 是否有效。`access_token` 有效期 2 小时，过期后重新获取并替换。

获取方式：

```bash
curl -s "https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=APPID&secret=APPSECRET"
```

#### 7. 发布到草稿箱

```bash
cd /Users/zcy1/code_self/AI/project/dy-chat-img
node post_draft.js --draft "贴图草稿-YYYYMMDD.json"
```

脚本会自动：

1. 读取草稿 JSON
2. 上传封面和正文图为微信永久素材
3. 按 `article_type: "newspic"` 调用 `draft/add` 创建图片消息草稿
4. 把返回的 `media_id` 写入 `draft_response.json`

#### 8. 记录发布结果

更新 `发布结果.md`，记录：

- 操作日期
- 来源抖音链接
- 草稿 `media_id`

- 本次上传的素材 `media_id`

## 关键参数说明

微信公众号图片消息 `draft/add` 接口与普通图文不同，必须注意：

| 字段 | 图文消息 `news` | 图片消息 `newspic` |
|---|---|---|
| `article_type` | `news`（默认） | 必须显式填 `newspic`，且放在 `articles[0]` 内 |
| 封面 | `thumb_media_id` | 也需要 `thumb_media_id` |
| 正文图片 | HTML `<img>` | 必须用 `image_info.image_list` 传永久素材 `media_id` |
| content | 支持 HTML | 只支持纯文本和部分特殊标签 |

错误示例（之前发成普通图文的原因）：

```json
{
  "articles": [{ "title": "..." }],
  "article_type": "newspic"
}
```

正确示例：

```json
{
  "articles": [
    {
      "article_type": "newspic",
      "title": "...",
      "content": "纯文本...",
      "thumb_media_id": "...",
      "image_info": {
        "image_list": [
          { "image_media_id": "..." },
          { "image_media_id": "..." }
        ]
      }
    }
  ]
}
```

## 低创作度规避（重点）

公众号对低创作度内容限推荐，四条标准：①同质化 ②搬运洗稿 ③信息量不足 ④低价值AIGC。贴图尤其中招，每篇对照：

| 标准 | 规避做法 |
|---|---|
| ①同质化 | 一天 1~2 篇，不批量；篇型轮换（故事/盘点/对比/科普），同领域一周不重复 |
| ②搬运洗稿 | 图源走 B 档：搜真实图后精选处理（裁切/拼图/加来源标注条/注明出处），不原图直搬、不批量整组搬；自制卡片仅辅助；不照搬热搜榜单原文与热度值 |
| ③信息量不足 | `body` 有信息增量打底——可用热点介绍/升华/科普（健康/科学/物理/材料/经济等）等素材灵活组合，不堆固定模板；事实可核查，不编数据 |
| ④低价值AIGC | AI 只整理素材，观点/经历/判断人工填并固定人设；不用「评论区聊聊」「你呢」套路结尾；不批量套模板金句 |

> 自制信息图可参考根目录 `make_cards.py`（PIL 生成黑底金字卡片，零搬运）。真要不踩雷，核心是「断链」——选题源别依赖公共热搜，图别用网图，文别只靠 AI。

## 图源档位

贴图核心是图，图源分四档，**日常默认走 B 档**：

| 档 | 做法 | 搬运风险 | 视觉 | 用途 |
|---|---|---|---|---|
| A 自制卡片 | PIL 文字信息图（`make_cards.py`） | 零 | 弱（无真实画面） | 无合适图时辅助 |
| B 真实图+处理 | 搜来后裁切/拼图/加来源标注条/注明出处 | 低（有二创） | 强 | **日常主用** |
| C 可商用图库 | pexels/unsplash 等无版权图 | 零 | 中 | 商业安全场景 |
| D 实拍/截图 | 自己拍或界面脱敏截图 | 零 | 强 | 有现场时 |

B 档处理：搜图用 `download_imgs.sh`，加来源标注用 PIL（底部加 30px 条 +「图源：网络，侵删」或原站名）。**禁止**：原图直发、批量整组搬、不注明出处。

> **搜图关键词必须紧扣 body 文字主题反推的视觉，不泛搜**：先想清楚主题对应的画面是什么，再用贴主题的词搜（例：「瓜农倒亏」主题 → 搜「西瓜滞销/烂在地里/低价批发/瓜农劳作」，不搜「西瓜丰收」这种情绪反着的词）。主题是抽象观点、找不到对应视觉时，降级用 A 档自制信息图（成本拆解/流程图等反而更贴）。

## 升华素材箱

贴图 body 的「升华」段，从下列角度**每篇挑一种**深挖，每篇挑不同、不雷同（这是去同质化 + 去模板味的关键）：

**信息增量类**：数据/统计、历史时间线、当事人原话、横向或纵向对比、真实案例
**换视角类**：反常识/辟谣、争议多角度、经济/商业链、法律/政策、心理机制、文化/地域
**实用类**：方法/操作指南、预测/趋势、词源/冷知识

> 挑哪种看话题：洞洞鞋→反常识+科普；收入→数据+对比；事件→历史时间线+当事人。科普另算一类硬知识，可和升华角度并用，但别每篇都堆一样的料。

## 注意事项

1. **access_token 会过期**：2 小时有效，发布前检查是否还有效。
2. **图片必须本地上传**：`post_draft.js` 会调用 `material/add_material` 把图片转成微信永久素材。
3. **抖音下载依赖 Playwright**：环境需安装 `playwright` 和 Chromium 浏览器。
4. **WebP 需要转换**：抖音原图常见 webp 格式，微信素材接口不认，必须先用 `sips` 转成 JPEG。
5. **并发问题**：同 AppID 多次获取 token 会互踩，同一批贴图串行发布，不要并发跑多个 `post_draft.js`。
6. **后台确认**：接口返回 `media_id` 后，去公众号后台「草稿箱」确认类型是否为「图片消息」。
7. **不做群发**：脚本只创建草稿，不调用群发接口。
8. **版权/隐私**：抖音图可能含他人头像/昵称/聊天记录等隐私，正式发布前建议打码或确认无侵权风险。
9. **图片保持原始比例**：直接用转码后的原图，不强制裁剪成统一比例，避免切掉正文内容。

## 不要做

- 不要把 `article_type` 放到 payload 顶层。
- 不要在 `newspic` 的 `content` 里塞复杂 HTML。
- 不要并发发布多篇贴图。
- 不要跳过后台确认类型。
- 不要把 webp 原图直接上传微信素材接口。
- 不要未经处理直接发布带他人头像/昵称的图。
- 不要逐图配文，文案整篇讲透共同主题（见「文案核心原则」），不每图一句金句并列。
- 不要把图片强行裁成统一比例（3:4 等），用原图比例即可。
