# 微信公众号贴图发布 Skill（热点选图发文流程）

> 项目根目录：`/Users/zcy1/code_self/AI/project/dy-chat-img`
> 调用方式：用户说「发贴图」「写贴图文章」「发图片消息」「发小绿书」，或直接给一个热点
> 发布类型：微信公众号图片消息（贴图 / 小绿书），对应 `article_type: "newspic"`
> **数量不限**（2026-07-26 修订）：写好一篇就推一篇，不再限制每日篇数；去同质化靠领域/篇型/图源错开，不靠数量上限。同 AppID token 互踩，多篇串行发布、禁止并发。
> **选题源风险（重点）**：公共热搜榜直接转述话题/排名/热度值=搬运+同质化+低信息量+低价值AIGC 四条连锁踩雷。把热搜只当**选题线索**，内容用实拍/自制图+自己查的事实，不照搬榜单原文与热度值。

---

## 触发条件

用户表达想要发布**图片消息 / 贴图 / 小绿书**类型到微信公众号草稿箱，例如：

- 「发贴图」「写贴图文章」
- 「发图片消息」「发小绿书」
- 「今天发一篇贴图」
- 「贴图写这个热点：XXX」

---

## 执行流程（用户选定热点 → 搜图 → 用户筛图 → 写文 → 发布）

触发后按以下顺序执行，**不再问澄清问题**，中途模糊判断自己定。

### 阶段一：确定热点（谁定热点？）

- **用户直接给热点**：用户说「贴图写XX」「XX这个热点」→ 直接用该热点，跳过搜索。
- **用户没给热点，让我搜**：我先抓当前国内热点列表，列给用户选。抓取方法（走本机 curl，WebFetch/WebSearch 搜不了国内热点）：

```bash
# 百度实时热搜榜（移动端 UA + 解析 title/desc 字段）
UA="Mozilla/5.0 (iPhone; CPU iPhone OS 16_0) AppleWebKit/605.1.4 Mobile/15E148 Safari/604.1"
curl -s -m 20 -A "$UA" "https://top.baidu.com/board?tab=realtime" -o /tmp/hot.html

# 备选：头条搜索（title+abstract 字段最稳，见记忆 cn-hotspot-toutiao-search）
curl -s -m 20 -A "$UA" "https://so.toutiao.com/search?keyword=热点&pd=hotspot" -o /tmp/tt.html
```

抓到后把 Top 热点清单（含话题名）展示给用户，**让用户挑一个**作为本次贴图主题。若接口不可用，用 WebSearch 搜「今天 微博热搜」兜底。

> 注意：只列话题名供选，不转述榜单排名/热度值原文。

### 阶段二：用户选定热点后 → 搜强相关图片（≥50 张）

热点确定后，按以下步骤搜图：

1. **确认热点真实性**：WebSearch 1-2 次查事件起因、时间、人物、官方通报，避免写错事实。

2. **跑通用搜图脚本**（`search_hot_imgs.py`）：传「主体词 + 事件词逗号分隔 + 输出目录 + 张数」：

```bash
# 示例：热点「许家印被判处无期徒刑」→ 主体=许家印，事件=判决/无期/宣判/庭审/被捕/清盘
python3 search_hot_imgs.py 许家印 "无期徒刑,宣判,判决,庭审,被捕,清盘,烂尾,退市" "贴图热点/20260821-许家印无期" 50
```

脚本自动：360 图片接口多关键词翻页 + 必应 cn 兜底 → 按「标题含主体+事件词」判定强相关排序 → 去重/尺寸过滤（任一边≥300px）→ 下载到输出目录 → 生成 `manifest.md` 记录每张来源标题。

**图片强相关保障**：
- 标题同时含**主体词**（人物/品牌）与**事件词**才优先入选，防止「搜许家印却来一堆无关富豪图」。
- 下载后可选 OCR 复核（`swift ../ocr.swift *.jpg`），确认内容命中主体关键词；URL 与标题明显不符的旧图混淆直接删除。

3. **输出目录规范**：`贴图热点/YYYYMMDD-热点名/`（如 `贴图热点/20260821-许家印无期`），图片命名 `001.jpg`、`002.jpg`…（按文件名排序即正文顺序）。**至少 50 张**，让用户有得挑。

### 阶段三：用户筛图（关键转折点）

把图片文件夹路径告诉用户，**请用户去文件夹里删除不用的图片**：

> 「图片已放到 `贴图热点/20260821-许家印无期/`，共 53 张，来源见 manifest.md。请你去删掉不用的图，**留下的就是要发在贴图文章里的**。删完告诉我，我接着写文。」

- **此阶段我停手等待**，不擅自定稿用哪些图。
- 用户删除后，剩下的图片 = 贴图文章正文图，按文件名排序即正文顺序。

### 阶段四：用户处理完图片后 → 写贴图草稿

用户回复「处理完了」「删好了」后，按留下图片写 `贴图草稿-YYYYMMDD.json`：

- `title`：贴合热点、有钩子、≤22 字，能让人忍不住点开（标题须贴热点原词蹭流量，见记忆 `wechat-img-title-authority-front`）
- `summary`：一句话总起，作为 digest
- `cover.placeholder`：封面图 = 从用户留下的图里选最有冲击力的一张（写相对路径如 `贴图热点/20260821-许家印无期/012.jpg`）
- `images`：正文图片列表，**数量 = 用户留下的图片张数**（每项写 image_description，只参与挑图不上传判断）
- `body`：整篇主题正文，300-500 字（最多 600），讲透热点主题，不逐图配文

**文案核心原则——整篇讲透主题，不逐图配文：**
- 一组贴图必有一个**共同主题**，文本**只把这个主题讲透**，不逐张图介绍。
- **第一段必须先交代热点背景**：1-2 句话讲清「什么事、大概什么时候、从哪看到的」。
- 素材灵活组合：把热点讲明白、提炼主题、升华（从「升华素材箱」挑一种角度）、科普延伸。不强求齐全、不固定顺序，每篇随机组合。
- 科普基于可靠常识，不编造伪科学数据；口语化、人设化、不 AI 味；结尾不用「评论区聊聊」「你呢」套路话术。

### 阶段五：发布

```bash
cd /Users/zcy1/code_self/AI/project/dy-chat-img
# 更新 post_draft.js 顶部 ACCESS_TOKEN（2 小时有效，过期需重新获取）
node post_draft.js --draft "贴图草稿-YYYYMMDD.json" --dir "贴图热点/20260821-许家印无期"
```

脚本自动：按 `--dir` 目录文件名排序读取正文图（= 用户留下的图）→ 上传封面/正文图为微信永久素材 → 按 `article_type: "newspic"` 调用 `draft/add` → 返回 `media_id` 写入 `draft_response.json`。

发布后更新 `发布结果.md`，记录：操作日期、热点、标题、草稿 `media_id`、类型「图片消息（newspic）」、素材 media_id。

## 贴图草稿 JSON 格式

```json
{
  "type": "wechat-image-post",
  "title": "许家印被判无期，恒大的账还没算完",
  "summary": "从中国首富到无期徒刑，许家印的结局早有伏笔。",
  "cover": {
    "description": "庭审/判决相关最有冲击力的一张",
    "placeholder": "贴图热点/20260821-许家印无期/012.jpg"
  },
  "images": [
    { "image_description": "判决报道截图" },
    { "image_description": "恒大烂尾楼现场" }
  ],
  "body": "8月20日，深圳中院对许家印案一审宣判……（300-500字，讲透主题）",
  "style": "社会、财经、纪实",
  "color_tone": "深色、红金"
}
```

> 说明：`body` 是整篇主题正文（脚本 `content = draft.body`）；`images` 只管数量与上传，不参与文本；`summary` 作为 digest；封面 `placeholder` 写完整相对路径，脚本会直接上传。

## 关键参数说明

微信公众号图片消息 `draft/add` 接口与普通图文不同，必须注意：

| 字段 | 图文消息 `news` | 图片消息 `newspic` |
|---|---|---|
| `article_type` | `news`（默认） | 必须显式填 `newspic`，且放在 `articles[0]` 内 |
| 封面 | `thumb_media_id` | 也需要 `thumb_media_id` |
| 正文图片 | HTML `<img>` | 必须用 `image_info.image_list` 传永久素材 `media_id` |
| content | 支持 HTML | 只支持纯文本和部分特殊标签 |

正确示例：

```json
{
  "articles": [
    {
      "article_type": "newspic",
      "title": "...",
      "content": "纯文本...",
      "thumb_media_id": "...",
      "image_info": {
        "image_list": [
          { "image_media_id": "..." },
          { "image_media_id": "..." }
        ]
      }
    }
  ]
}
```

## 低创作度规避（重点）

公众号对低创作度内容限推荐，四条标准：①同质化 ②搬运洗稿 ③信息量不足 ④低价值AIGC。贴图尤其中招，每篇对照：

| 标准 | 规避做法 |
|---|---|
| ①同质化 | 篇型轮换（故事/盘点/对比/科普），同领域一周不重复 |
| ②搬运洗稿 | 图源走 B 档：搜真实图后精选处理（裁切/拼图/加来源标注条/注明出处），不原图直搬、不批量整组搬；自制卡片仅辅助；不照搬热搜榜单原文与热度值 |
| ③信息量不足 | `body` 有信息增量打底——热点介绍/升华/科普（健康/科学/物理/材料/经济等）灵活组合，不堆固定模板；事实可核查，不编数据 |
| ④低价值AIGC | AI 只整理素材，观点/经历/判断人工填并固定人设；不用「评论区聊聊」「你呢」套路结尾；不批量套模板金句 |

> 图源四档：A 自制卡片（`make_cards.py`）零搬运弱视觉 / **B 真实图+处理（日常主用）** / C 可商用图库 / D 实拍截图。B 档处理：搜图后裁切/拼图/加来源标注条（`add_source.py`），**禁止**原图直发、批量整组搬、不注明出处。

## 升华素材箱

贴图 body 的「升华」段，从下列角度**每篇挑一种**深挖，每篇挑不同、不雷同：

**信息增量类**：数据/统计、历史时间线、当事人原话、横向或纵向对比、真实案例
**换视角类**：反常识/辟谣、争议多角度、经济/商业链、法律/政策、心理机制、文化/地域
**实用类**：方法/操作指南、预测/趋势、词源/冷知识

## 注意事项

1. **access_token 会过期**：2 小时有效，发布前检查 `post_draft.js` 顶部是否还有效。
2. **图片必须本地上传**：`post_draft.js` 调 `material/add_material` 把图片转永久素材，`--dir` 指向热点图片文件夹。
3. **并发问题**：同 AppID 多次获取 token 会互踩，同一批贴图串行发布，禁止并发跑多个 `post_draft.js`。
4. **后台确认**：接口返回 `media_id` 后，去公众号后台「草稿箱」确认类型是否为「图片消息」。
5. **不做群发**：脚本只创建草稿，不调用群发接口。
6. **版权/隐私**：热点搜图可能含他人头像/昵称/聊天记录等隐私或版权风险，正式发布前建议打码、加来源标注条或确认无侵权风险。
7. **图片保持原始比例**：直接用原图，不强制裁剪成统一比例，避免切掉正文内容。

## 不要做

- 不要把 `article_type` 放到 payload 顶层。
- 不要在 `newspic` 的 `content` 里塞复杂 HTML。
- 不要并发发布多篇贴图。
- 不要跳过后台确认类型。
- 不要把 webp 原图直接上传微信素材接口。
- 不要未经处理直接发布带他人头像/昵称的图。
- 不要逐图配文，文案整篇讲透共同主题，不每图一句金句并列。
- 不要把图片强行裁成统一比例，用原图比例即可。
- **不要在用户筛图前擅自定稿用哪些图**——阶段三必须停手等用户删完。
