## 项目依赖与配置

- **音频生成**：`src/audio.js` 调用 Microsoft Edge TTS（`node-edge-tts`，免费零 key）。
- **推草稿**：`src/publish.js` 复用 `../wechat-img/src/index.js`，凭证从 `wechat-img/.env` 读取。
- **首次配置**：复制 `.env.example` 为 `.env`，按需改 TTS 音色/语速。
- **默认封面**：运行 `npm run init-assets` 生成 `assets/default-cover.jpg`。

## 选题

### 方向（商业财经，单人主播）

每次只聊 **一个具体信号**，不要泛泛而谈。优先顺序：

1. **用户指定**：用户点名某主题，直接用。
2. **蹭当下商业热点**：近 3 天财经新闻、公司动态、政策变化。
3. **自选未写过的**：从下列池挑，避开 `logs/` 历史主题。
   - **公司案例**：财报、并购、裁员、新产品、股价异动
   - **行业趋势**：AI 商业化、新能源、消费降级、出海、半导体
   - **投资逻辑**：某个赛道估值、基金调仓、巴菲特/段永平动作
   - **政策解读**：降准、新规、反垄断、出口退税、数据要素
   - **创业观察**：独角兽倒下、新消费品牌、SaaS 生死

### 去重

扫 `audio/logs/*.md` 的「主题」列，候选若和历史某篇语义重复，换一条。

### 篇数

默认 **1 期**（用户喊「来几期」「来一波」才多写）。每期独立选题、独立生成、独立推。

## 内容结构

每期分为两部分：

- **`script`**：完整音频稿，1800–2200 字，朗读约 10 分钟。
- **`body_markdown`**：公众号正文，800–1200 字，是音频的精华摘要 / shownotes。

### `script` 结构（10 分钟）

```
开头钩子（1–1.5 分钟）：
  抛一个反直觉问题、一个最新数据、或一个具体场景。
  不要寒暄，不要说「大家好欢迎来到本期播客」。

主体（6–7 分钟，分 3–4 段）：
  每段一个论点 + 案例/数据/逻辑。
  段与段之间用「那这件事为什么重要？」「我们先看一组数据」等口语化过渡。

收口（1–1.5 分钟）：
  给一个可执行结论、一个判断、或一个留给听众思考的问题。
  不要总结全文，要给增量。
```

**口语化要求**：
- 短句为主，每句不超过 25 字。
- 数字读 aloud：`2024年` → `二零二四年`，`10%` → `百分之十`。
- 不用 markdown、不用 ASCII 引号 `"`，需要引用时用「」。
- 允许少量口头禅（如「说白了」「你注意看」「这事有意思在哪」），增强真人感。
- 不要用「值得注意的是」「综上所述」「毋庸置疑」等 AI 套话。

### `body_markdown` 结构（800–1200 字）

```markdown
## 今天聊什么
3 句话点题：是什么、为什么现在聊、和你有什么关系。

## 核心观点
- **要点一**：一句话结论 + 一句话论据。
- **要点二**：一句话结论 + 一句话论据。
- **要点三**：一句话结论 + 一句话论据。

## 一个案例/数据
展开讲一个最有说服力的案例或一组关键数据。

## 给你的行动建议
1. 对普通读者：怎么看这件事。
2. 对投资者/从业者：怎么应对。

CTA 问题
```

**正文要求**：
- 800–1200 字，能过 `wechat-img/src/preflight.js`。
- 无 ASCII 双引号 `"`，用「」。
- 无正文超链接（`[文字](http...)`），音频链接由脚本自动注入。
- 无存疑词（据传/疑似/据说等）。
- 无六段全套模板（`## 一` 到 `## 六` + 3 个以上引言 + 6 处以上加粗）。

## 发布流程

1. Claude 生成 `episodes/E001/article.json`。
2. 运行 `node src/preflight-podcast.js episodes/E001/article.json`。
3. 运行 `node src/audio.js --from-json episodes/E001/article.json` 生成 `E001.mp3`。
4. 生成 `article.wechat-img.json`（顶部自动注入音频链接）。
5. 运行 `node src/publish.js --episode E001` 推草稿。

实际只需对 Claude 说：「写播客」，然后执行：

```bash
cd /Users/zcy1/code_self/AI/project/audio

```

## ⭐ 低创作度规避

与 `wechat-img` 同一套红线：

- **标题**：不用「我X了」情绪尾，不用「震惊/速看/刚刚/突发/曝光」。
- **正文**：不用「值得注意的是/综上所述/在当今社会/毋庸置疑/众所周知」。
- **结构**：避免 `## 一` 到 `## 六` + 大量引言 + 大量加粗的六段模板。
- **观点**：必须有具体案例/数据，不能全是「正确的废话」。
- **AI 金句**：避免 3 处以上「的尽头是」「不是…而是…」「更真/更重/更深」等句式。

## 常见问题

**Q：音频怎么放到公众号文章里？**  
A：微信语音素材限制 60 秒/2MB，长音频不能直接嵌入。`publish.js` 会在文章顶部注入音频链接（`<a href='...'>`），读者点击即可收听。如需可点击外链，配置 `.env` 的 `AUDIO_BASE_URL` 或 `AUDIO_UPLOAD_CMD`。

**Q：为什么是单人而不是双人？**  
A：商业财经信息密度高，单人独白更直接；AI 双人对话容易「尬聊」。后续如需双人，再扩展对话稿模式。

**Q：能不能生成完整逐字稿作为正文？**  
A：`wechat-img` 的 preflight 限制正文 1200 字，所以正文是精华摘要，音频是完整版。这是播客常见形态。
