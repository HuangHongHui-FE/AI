> 项目根目录：`/Users/zcy1/code_self/AI/project/mingchangmian`
> 调用方式：用户说「写名场面」「今天发名场面」「来一篇名场面」之类，Claude **自动**选点、切 GIF 首图、生成解读文章、推草稿

## 触发条件

用户说「写名场面文章」「今天发名场面」「来一篇」「写一场 XXX」之类。可指定某场（「写让子弹飞站着挣钱那场」），也可不指定让 Claude 自选。

**执行原则**：触发后**不再问澄清问题**，直接跑完整流程——选点 → 定视频源 → 切 GIF → 生成 article.json → 自查 → 推草稿 → 写日志。中途模糊判断（选哪场、标题怎么起、GIF 取哪几秒、解读角度）自己定。仅当真正阻塞（B站 cookie 没配且下不动、所有候选都找不到视频源）才停下来报告。

## 选点规则

### 1. 选题来源（按优先级）

a. **用户指定**：用户点名某场（「写无间道天台戏」），直接用，跳到第 2 步。
b. **蹭当下影视热点**：若当下有相关热点（新片上映的同系列旧作、演员去世/获奖、某老片/老梗翻红），优先选与热点挂钩的名场面——这是名场面号最大的流量来源。用 WebSearch 探一下近 3 天影视圈热点。
c. **自选未写过的**：从下列清单里挑一条 `logs/` 没写过的（清单非穷尽，可自行扩展）：
   - **华语经典**：让子弹飞「站着挣钱」/ 无间道天台「对不起我是警察」/ 大话西游「一万年」/ 霸王别姬「不疯魔不成活」/ 喜剧之王「我养你啊」/ 英雄本色「等了三年」
   - **鬼畜万恶之源**：三国演义「从未见过如此厚颜无耻之人」/ 甄嬛传「臣妾做不到」/ 范志毅「脸都不要了」/ 康熙王朝
   - **网络梗/短视频**：giao 哥「一给我嘞giaogiao」/ 冬人「奥利给干了兄弟们」/ 卢本伟「我卢本伟没有开挂」/ 周立齐「打工是不可能打工的」/ 影流之主
   - **抽象系（高风险，见自查 B 红线）**：孙笑川系列、岛市老八等——**只引用台词不出现原人物画面**，降低封号风险

### 2. 去重（不写写过的）

扫本项目 `logs/*.md` 的「名场面」列：

```bash
grep -hE '^\| 0[0-9]' logs/*.md | awk -F'|' '{gsub(/^ +| +$/,"",$5); print $5}' | sort -u
```

候选若和历史上某篇同一场（语义相同即算），换一条。

### 3. 篇数

默认 **1 篇**（用户喊「来几篇」「发一波」才多写）。每篇独立选点、独立切图、独立推。

## 视频源与 GIF 切片（核心，一篇一张）

### 1. 定视频源

每条名场面需要：**B站视频链接（BV号）+ 名场面所在时间段（开始-结束）**。

- 找法：WebSearch 搜「片名 名场面 B站」拿 BV 号；时间段先估，下完 raw.mp4 后用 ffmpeg 抽几帧确认台词/画面在不在区间内，不对就微调重切。
- **B站 cookie**：高清源 / 部分影视需要登录。首次跑前确认 `gif_clip.py` 能否直接下；报 cookie 错误则配 `--cookies-from-browser chrome`（gif_clip.py 当前未加此参数，需补——见「已知坑 1」）。
- 找不到视频源（BV 号搜不到 / 链接失效）→ 换一条名场面，不为单卡住。

### 2. 切 GIF（用 gif_clip.py）

```bash
python3 gif_clip.py "<B站URL>" <开始> <结束> <输出名>
# 例: python3 gif_clip.py "https://www.bilibili.com/video/BVxxxx" 01:23 01:31 让子弹飞-站着挣钱
# → 输出 clips/让子弹飞-站着挣钱.gif
```

**一张就够**：这张 GIF 同时作正文头图 + 封面底图（推草稿脚本 `--image` 指它，封面由脚本套 slogan 生成）。

**参数约束**：
- 时长 **3-8 秒**（名场面精华帧，太长体积爆炸、太短没情绪）
- 默认 fps 10 / 宽 360，体积应 < 3MB；超 3MB 缩短时长或改宽 240 重切
- **不要切整段长戏**，挑最有辨识度的一两句台词/一个动作的窗口

### 3. 验证

切完 Read 一下 `clips/<名>.gif` 预览（>5MB 读不动就 ls 看体积，体积合理即过）。画面不对（切错段、黑屏、带无关片头）→ 调时间码重切。

## 标题起名规则（贴名场面原词/原台词）

和热点号同理：标题必须含名场面的**原台词关键词或片名**，读者在信息流里一眼认得出是哪场，搜索流量才吃得着。

**做法**：
1. 写下原台词/片名核心词（如「让子弹飞 / 站着把钱挣了」）
2. 保留核心词，加一个轻钩子（「这段我看十遍」「就这一句封神」「长大后看懂了」）
3. ≤22 字，不标题党（无「震惊/速看/刚刚」限流词）

**正反例**：

| 名场面 | ✅ 贴原词标题 | ❌ 离原词太远 |
|---|---|---|
| 让子弹飞·站着挣钱 | 让子弹飞「站着把钱挣了」，这段我看十遍 | 成年人最该补的一堂课 |
| 无间道·天台 | 无间道天台「对不起我是警察」，就这一句封神 | 两个男人的宿命对峙 |
| 大话西游·一万年 | 大话西游「爱你一万年」，长大后看懂了 | 错过的爱情都在台词里 |
| 三国演义·厚颜无耻 | 诸葛亮「从未见过如此厚颜无耻之人」 | 古人骂人有多雅 |

**自检**：标题里有没有原台词/片名关键词？没有 → 重起。

## 文章结构（名场面解读，不是中年叙事）

名场面号的调性是 **「懂行 + 共鸣」**，不是 wechat-img 的中年叙事。篇幅 800-1200 字，6 段左右：

1. **开头**：直接抛台词或场景（「姜文这句『站着把钱挣了』，我看了十年才看懂」），不套「在...的今天」。
2. **场景还原**：一两句交代这是哪场戏、谁对谁、什么处境（让没看过的人也接得住）。
3. **为什么牛**：选 1-2 个角度切——台词的弦外之音 / 拍法（长镜头、构图、节奏）/ 演员细节（即兴、微表情）/ 幕后（删改、现场）——**别面面俱到**，深挖一点胜过流水账。
4. **共鸣落点**：这场戏戳中了什么（代际、阶层、爱情、尊严），用「我」或「我们」落地一句。
5. **金句收**：回到那句台词，给一个比开头更深的读法，不号召不升华。
6. （可选）**一句互动钩子**：问读者「你第一次看懂这句是几岁」之类。

> 网络梗类（giao/卢本伟）结构略变：开头抛梗→它怎么火的→为什么好笑/上头→一句人情味收（别端着分析亚文化）。

## 发文流程

对每条选题，按顺序：

1. **定视频源 + 切 GIF**：见上方「视频源与 GIF 切片」。输出 `clips/<名>.gif`。
2. **生成 article.json**：按 [[wechat-daily]] 的 JSON 字段 / 长度 / 调性 / 反 AI 味要求，写到 `output/YYYY-MM-DD/NN-名场面/article.json`。CTA 按主题选型（影视情怀向用「点赞在看」卡片即可）。**首图就是那张 GIF，body 头部由推草稿脚本自动嵌入，不用手贴图**。
3. **自查**（见下，**写完每篇必做，不过重写**）。
4. **推草稿**（串行！）：
   ```bash
   node /Users/zcy1/code_self/AI/project/wechat-img/src/index.js \
     --image "clips/<名>.gif" \
     --out-dir "output/YYYY-MM-DD/NN-名场面/"
   ```
   多篇时 **for 循环逐篇跑、每篇间隔 2 秒**，绝不并行（微信同 appid 并发 gettoken 会互踩 token，全报 40001）。
5. **写日志**：`logs/YYYY-MM-DD.md`，每篇记 标题 / 名场面 / BV号+时间码 / media_id / 时段建议。BV号+时间码记下来，下次同名场面直接复用，自然积累成素材库。

文件编号 `NN` 从 `01` 起。

## 自查清单（写完每篇必过，不过则重写）

### A. AI 痕迹自查

逐条扫 `body_markdown`：

- [ ] **禁用词全删**：「值得注意的是」「总而言之」「此外」「综上所述」「在当今社会」「在快节奏的」「不仅...而且」「毋庸置疑」「众所周知」「由此可见」——命中即改写。
- [ ] **无工整排比对仗**：没有「不是A而是B；不是C而是D」连续堆叠；没有连续三句字数句式雷同。
- [ ] **段落长短不齐**：6 段里至少 1 段只 1 句、1 段 6-8 行，别每段都 3-5 行。
- [ ] **开头不套话**：第一段直接进台词或场景，不是「随着...的发展」「最近...引发热议」。
- [ ] **有具体细节**：≥2 处具象（一句原台词 / 一个镜头动作 / 一个幕后数字），不纯抽象议论。
- [ ] **有人称落地**：出现「我」「我第一次看」之类第一人称，不全程上帝视角。
- [ ] **不端着说教**：没有「我们应该」「让我们珍惜」式号召结尾。
- [ ] **口语感**：≥2 处口语（「说白了」「讲真」「你别说」「可不」），不全书面语。

### B. 微信公众号规范自查

- [ ] **标题**：≤22 字，贴名场面原词/原台词（自检：标题里有原台词关键词或片名吗？没有→重起），无标题党限流词。
- [ ] **摘要 digest**：≤54 字，无换行无外链。
- [ ] **正文无外链**：`body_markdown` 里不能有 `[文字](url)`；引用来源用文字描述。B站/豆瓣链接一律不放正文（微信会变纯文本）。
- [ ] **GIF 合规**：单张 < 10MB（实际应 < 3MB，见切片约束），是 GIF 格式。不带别家平台明显水印（B站右下角水印可接受，硬挡不了就保留）。
- [ ] **无诱导违规词**：无「转发抽奖」「集赞」「关注领取」等。
- [ ] **敏感红线**（名场面号高发）：
  - 抽象系（孙笑川/nmsl/老八）**只引用台词、不出现原人物画面、不渲染低俗**，风险高的整条弃写换题
  - 涉政治人物的影视（如某些主旋律片段）不评价现实政治
  - 暴力/血腥镜头的 GIF 不切（选台词窗口而非打斗窗口）
  - 未审案件相关名场面用「涉嫌」原样转述，不预判
- [ ] **标点**：全中文标点，引号统一用「」（**JSON body 内严禁 ASCII 双引号 `"..."`，会破坏 article.json 解析**），无中英混用逗号，无错别字。
- [ ] **加粗/引言/分隔符**：`**加粗**` 3-5 处、`> 引言` 1-2 处、`---` 分章，不过度。

## 已知坑

1. **B站 cookie 没配 → 高清源下不动**：`gif_clip.py` 当前未带 cookie 参数。若报登录错误，需给脚本加 `--cookies-from-browser chrome`（yt-dlp 选项，自动读 Chrome 登录态，半年内不用维护）；或导出 `.bilibili-cookies.txt` 传 `--cookies`。**首次实跑前先确认要不要补这行。**
2. **并发推草稿必崩**：≥2 篇并行跑 `src/index.js` 会全 `40001 invalid credential`（同 appid 多次 gettoken 互踩）。**一律串行**（for + sleep 2）。
3. **JSON body 内引号一律中文「」**：`body_markdown` 用 ASCII `"..."` 会破坏 article.json 解析，推送报 `Unexpected token`。直接用「」。
4. **GIF 体积**：8 秒以上或宽 480 容易破 5MB，公众号加载慢且读不动。卡在 3-8 秒 / 宽 360。
5. **切片时间码偏移**：估的时间码常差几秒，下完 raw.mp4 后抽帧确认台词在不在窗口，不对就 ±3 秒重切，别盲推。

## 不要做

- 不一篇配多图（名场面号一篇一张 GIF，多了反而稀释）
- 不跨天重复同一场（每次开跑先扫 `logs/`）
- 不切整段长戏当首图（挑精华 3-8 秒）
- 不把 B站/豆瓣 URL 放正文（变纯文本，删）
- 不为流量硬上抽象系高风险人物画面（台词引用 OK，画面不出现）
- 不跳过自查直接推（自查是发文前最后一道关）
- 不定时任务（用户喊才跑）
