# 08 推草稿箱

> **输入**：`06-出物料` 生成的 `output/YYYY-MM-DD/NN-名场面/`（含 `article.json` + `cover.jpg`）
> **产出**：**名场面档案**公众号草稿箱里的一篇草稿（标题 / 摘要 / 正文 / 头图 / 封面都齐）
> **终点**：**到这里停手，不点「发表」** —— 发布权留给人
> **可扩展点**：选择器、等侯时长都在 `mp_draft.py` 顶部；加封面/原创声明等字段改主流程

> **状态**：本步 2026-10-10 曾停用（流程改成「只出物料，人自己发」），
> **2026-10-17 恢复并跑通**，从 `_已停用/B3-浏览器发草稿` 提为正式步骤 `08`。
> 它和 [`_已停用/06-推草稿`](../_已停用/06-推草稿/README.md)（走微信 API）**是两条并列的路，二选一**。

## 这一步做什么

用**操作浏览器**的方式把文章填进公众号编辑器并存草稿。不需要微信 API 凭据，**也不需要 IP 白名单**。

| | 08 浏览器（本步） | 06 推草稿（API，已停用） |
|---|---|---|
| 通道 | 操作 mp.weixin.qq.com 网页 | 调 `wechat-img/src/index.js` |
| IP 白名单 | **不需要** | **需要**（否则 40164） |
| 登录 | 扫码一次，存持久化 profile | 用 `.env` 里的 appid/secret |
| 封面 | **自动**（取正文首图） | 自动用 `--image` 合成 |
| 适用 | 想省掉白名单配置 | 批量、无人值守 |

> ⚠️ **两条路别对同一篇文章都跑**，会在草稿箱里生成两篇。

## 命令

```bash
cd skill/08-推草稿箱
python3 mp_draft.py "../../output/2026-10-09/01-我靠袁华/article.json" \
    --author 名场面档案 \
    --head-image "../../input/clips/024-我靠袁华-头图.gif"
```

首次跑（或会话过期）会弹出 Chrome 并**提示扫码** —— 扫完脚本自动继续。登录态存在
`~/Library/Caches/mingchangmian-mp-profile`，之后不用反复扫。

> ⚠️ **扫码成功后微信会另开一个标签页**打开后台，原登录页会一直停在「扫码成功」不动。
> 脚本已在**所有标签页**里找带 `token=` 的后台页（2026-10-17 修），别改回只看最初那个 page ——
> 那样会傻等 360 秒然后报「扫码等待超时」，而其实早就登录好了。

挑错时加 `--no-save`：只填不保存，浏览器留 90 秒给你看。

### 四个脚本

| 脚本 | 什么时候用 | 会不会新增草稿 |
|---|---|---|
| `mp_draft.py` | **新建**一篇草稿（正常发布路径）| ✅ 每跑一次多一篇 |
| `fix_draft.py` | **改已有**那篇（写错了、要换图）| ❌ 原地替换 |
| `list_drafts.py` | **只读**核对草稿箱（标题 / 时间 / 有没有封面）| ❌ 不写任何东西 |
| `cleanup_dupes.py` | 清掉调试堆出来的重复稿（保留有封面那篇）| ❌ 只删不加 |

**流程模板**（新建 → 核对）：

```bash
cd skill/08-推草稿箱
python3 mp_draft.py "<article.json>" --author 名场面档案 --head-image "<头图.gif>"
python3 list_drafts.py          # 看时间戳确认真的存进去了
```

> 保存后**一定要看 `list_drafts.py` 的输出**（或直接开草稿箱看更新时间）——
> 微信长文+大图可能「自动保存失败」，点了保存也可能没进去（见「本步的坑」第 12 条）。

## 头图（`--head-image`）

把一张图放在**正文最前面**。传了才有，不传就照旧只有文字。

**做法是「本地组装整篇 → 一次性粘贴」**：脚本把图片转成内联 `data:` URI 拼在正文 HTML 最前面，连同正文一起写进剪贴板，再全选粘贴。微信的粘贴处理器认得 `data:` URI，会自己把它转成正文图片。

> ⚠️ **不要试图去点编辑器工具栏的「图片」按钮上传。** 实测 5 种点法全部无效 ——
> 文本选择器超时、精确类选择器（`li.jsInsertIcon.img`）不可点、`force=True` 会点到正文引用块上、
> JS `.click()` 和鼠标坐标点击都无反应。**粘贴是唯一跑通的路径**（2026-10-09 验证）。

**宽度要用 640，不要用 B2 那张 360 的。** 公众号正文图片实际显示宽约 **677px**，
360 宽会被拉大糊掉。B2 的 360 首图是**给封面用的**（封面 900×383 由脚本合成），两者需求不同：

```bash
python3 skill/gif_clip.py "名场面/素材/019-…-50-56.mp4" 50 56 019-爆笑吕子乔-头图 --width 640
```

> 图是**粘进正文**的，不是 `article.json` 的字段 —— `article.json` 不用改。
> `--image`（封面用图）和 `--head-image`（正文头图）是两回事，可以都传。

## 编辑器的坑（都已在脚本里绕过）

1. **`#title` 不能用**。微信把真实的标题 textarea 设成 `visibility:hidden`、高度 0，真正的标题输入是**第 1 个 `.ProseMirror`**（contenteditable）。正文是**第 2 个 `.ProseMirror`**。
   ```python
   page.locator("div.ProseMirror").nth(0)   # 标题
   page.locator("div.ProseMirror").nth(1)   # 正文
   ```
   写这个脚本时就是先踩了 `page.fill("#title", ...)` 超时 30 秒才发现。

2. **`#author` 和 `#js_description`（摘要）是可见的**，可以直接 `fill()`。摘要不在首屏，Playwright 会自动滚过去。

3. **开头可能有引导弹窗**（如「支持添加话题卡片」），会挡住标题。脚本会先点「我知道了」关掉。

4. **正文用剪贴板粘 HTML**，不要逐字输入 —— 900 字逐字要几十秒，而且会丢掉加粗。脚本用 `ClipboardItem` 写 `text/html` 再 `Meta+V`；失败会回退 `execCommand('insertHTML')`，再失败才逐字。

5. **保存前必须回读校验**。脚本会读回标题和正文字数，不达标就**中止且不保存**，避免往草稿箱塞废稿。这是防止自动化「静默成功」。

6. **草稿箱列表页不会立刻刷新**。保存后直接开草稿箱可能看到空的（第一次验证就这样被骗过）——要**等 6-10 秒**，或从左侧菜单「内容管理 → 草稿箱」点进去。

7. **封面要单独传**（2026-10-08 实测）。
   微信的封面对话框只有四个入口：**从正文选择 / 从图片库选择 / 微信扫码上传 / 一键生成封面**，没有「直接上传本地文件当封面」。
   点弹窗里那些浮层元素时，Playwright 的 `is_visible()` 会判为不可见、`click()` 超时。

   **「从正文选择」这条路已经自动化了**（2026-10-17），但两个坑很隐蔽：
   - 弹窗里的缩略图是 **`span.appmsg_content_img`（用 `background-image`，不是 `<img>`）** ——
     按 `<img>` 找必然落空，报「对话框里没看到图」；
   - 选中它**必须用真实鼠标事件**（`page.mouse.click(x, y)`）。JS `.click()` 不会触发 Vue 的选中态，
     「下一步」会一直 `disabled`，看起来像点了没反应。点完还要**等「下一步」从 disabled 变可用**。
   - 裁切页的按钮是 **「上一步 / 确认」**，**不叫「完成」** —— 找「完成」会白等一轮。

   > 注意：`set_input_files` 塞给页面里那个 `input[type=file]`，**会把图插进正文末尾**，不是封面。踩过一次，记得用完删掉。
   >
   > 还有：**封面弹窗没关掉的话会挡住「保存为草稿」按钮**，脚本保存前会先清理弹窗（`_close_dialog`）。

8. **草稿箱必须从左侧菜单进**。「内容管理 → 草稿箱」能正常加载列表；**直接拼 URL 打开会是空的**（前端路由问题，2026-10-08 被这个骗过一次）。

9. **点草稿标题只是悬停**，会露出 删除/编辑/发表 三个按钮。真正的编辑入口是 `a.weui-desktop-icon-btn` 的**第 2 个**，而且会**开新标签页**，脚本要切过去。
   删除入口是**第 1 个**（垃圾桶图标）—— 但那个图标默认 `visibility:hidden`，
   必须**先 `card.hover()` 再点**；用 `page.mouse.move()` 到坐标是不行的（不会触发显形）。
   删完在可见的 `.weui-desktop-popover` 里点「删除」确认。

10. **每次跑都会往草稿箱存一篇**。调试时反复跑同一个 `article.json` 会堆出 N 篇同名稿
    （2026-10-17 一次调试堆了 6 篇）。挑错请用 `--no-save`，别反复跑完整流程；
    已经堆出来了就用 [`cleanup_dupes.py`](cleanup_dupes.py) 清理 ——
    它会**保留有封面的那篇**（`hasCover` 靠封面缩略图的 `background-image` 判断），删掉其余同名无封面的。

11. **改已有草稿用 [`fix_draft.py`](fix_draft.py)，不要重跑 `mp_draft.py`**。
    `mp_draft.py` 每次都新建一篇，重复稿就是这么堆出来的；`fix_draft.py` 是**原地替换**：
    草稿箱 → 找到那篇 → 编辑 → 清空正文 → 重贴 → 保存。

    ```bash
    cd skill/08-推草稿箱
    python3 fix_draft.py "夏洛特烦恼" "../../output/2026-10-09/01-我靠袁华/article.json" \
        --head-image "../../input/clips/024-我靠袁华-头图.gif"
    ```

    > ⚠️ 旧版 `fix_draft.py` 从 `/tmp/mp_session.json` 读 token，而**那个文件从来没人写过**
    > （`mp_draft.py` 不落盘 token）—— 所以这条路一直是坏的，2026-10-17 才改成复用 `ensure_login()`。
    > 登录态本来就在持久化 profile 里，不需要 session 文件。
    >
    > ⚠️ **编辑已有草稿的页面里，封面区的下拉浮层不吃自动化 hover**（2026-10-17 试过
    > hover 预览层 / 封面区 / 真实鼠标移入+微移 / mousedown，`#js_cover_null` 始终 `display:none`）。
    > 所以 `fix_draft.py` 的做法是：**封面已在就跳过**（`cover_is_set()` 判定），
    > 不在就尝试设，设不上**明确告警并告诉你手动怎么点** —— 不静默当成功。
    > 想换封面请手动：点左侧封面区 → 从正文选择 → 选图 → 下一步 → 确认。

12. **微信的「自动保存失败」不是你的脚本出错**。长正文 + 内嵌大 GIF 时，微信自己的
    自动保存会失败，底部状态条显示 **「⚠ 自动保存失败　正文字数 N」**。
    这时**点「保存为草稿」通常仍能成功**（手动保存走的是另一条请求），但**别把它当成功**：
    脚本的回读校验会报「点了保存但没看到『已保存』」，那就**去草稿箱核对** ——
    2026-10-17 实测那一次是**真的没存进去**（草稿箱里那篇还是上一次的时间戳）。

13. **回读校验永远别省**。`mp_draft.py` 保存后会读底部状态条找「已保存」；`fix_draft.py` 同样。
    没有这一步，「点了但没存」会被静默当成成功 —— 正是本 README 开头第 5 条警告的「静默成功」。

## 本步的坑 / 不要做

- **不要点「发表」**，只存草稿；发布权留给人工。
- 不要和 `_已停用/06-推草稿` 对同一篇跑两遍。
- 别把 profile 目录提交进版本库（里面有登录态）。
- 公众号会话会过期，届时重扫即可，脚本会自己提示。
- **封面文案「拖拽或选择封面」不可信**：封面**设上了它照样显示**。
  判「封面有没有设上」只看 `.js_cover_preview_new` 有没有 `mmbiz` 背景图（脚本已这么判）。
