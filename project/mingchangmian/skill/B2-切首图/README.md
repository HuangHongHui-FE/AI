# B2 切首图

> **输入**：`B1-剪成片` 用的**同一个源视频** + **同一个钩子段**（同样从素材文件名读，见 [`../B1-剪成片/README.md`](../B1-剪成片/README.md)）
> **产出**：`input/clips/<素材编号>-<名>.gif`（公众号文章首图，同时作封面底图）
> **可扩展点**：画幅/帧率/体积等约束统一在 `02-切图` 里维护；本文件只写差异，**不重复那些数字**

---

## 这一步做什么

给流程 B 的公众号文章切一张 GIF 首图，观感与流程 A 保持一致（都是会动的头图，都兼作封面底图）。

## 为什么从源视频切，而不是从成品切

成品视频带着**「名场面」斜向水印**，而流程 A 的首图（B站原片）是不带水印的。

为了文章观感一致，首图从**源视频的钩子段**切 —— 和 `B1` 共用同一个时间段。

> 那个水印是给**短视频平台**防盗用的，公众号文章首图不需要它。

## 命令

```bash
python3 skill/gif_clip.py "名场面/素材/<素材名>.mp4" <钩子起> <钩子止> <素材编号>-<名>
```

例（018 的钩子是 47-53）：

```bash
python3 skill/gif_clip.py "名场面/素材/018-高三八班、全体起立.mp4" 47 53 018-高三八班
# → input/clips/018-高三八班.gif
```

`gif_clip.py` 的第一个参数**既接受 B站 URL，也接受本地文件路径**：是已存在的路径就走本地裁剪，不经 yt-dlp、不用 cookie。

**命名要加素材编号前缀**（`018-…`），避免和流程 A 的 `<片名>-<名场面>.gif` 在共用的 `input/clips/` 里撞名。

## 参数约束

**不在这里重复** —— 全部见 [`../02-切图/README.md`](../02-切图/README.md) 的「参数约束」与「验证」两节（3-8 秒 / fps 10 / 宽 360 / 两遍调色板 / <3MB）。

与本步的差异只有两点：

- 输入是**本地文件**，时间段来自**用户给的钩子段**，不经 B站、不用 cookie、不会遇到 playurl 412
- 钩子段若超过 8 秒，在它内部挑最有辨识度的一个子窗口（不要整段切）

---

## 本步的坑 / 不要做

- **不要从成品视频切首图**（会带上水印）。
- **不要改钩子时间段** —— 以 `B1` 用的那个为准，单一事实来源。
- 不要在这里另写一套画幅/体积数字，会和 `02-切图` 漂移。
- 切完 Read 一下 `input/clips/<名>.gif` 预览确认，别盲推。
