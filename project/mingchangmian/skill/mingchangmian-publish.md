# 名场面 Skill（总索引 / 路由器）

> **项目根目录**：本仓库根目录（即 `skill/` 的上级目录），下文命令一律在此目录下执行
> **两条互不干扰的流程** —— 先按下方触发条件路由，再走进对应步骤
> 一篇只配**一张名场面首图**（GIF），不另搜图、不配多图
> **终点是「物料」，不是「发布」** —— Claude 准备好可复制粘贴的东西（公众号正文/封面、视频成品/文案），
> **公众号 / 视频号 / 抖音 / 快手由人手动发**。原来的自动推送步骤已挪到 `_已停用/`
> 文章 JSON 字段 / 排版细节见 [[wechat-daily]]（wechat-img 项目），本 skill 只写**名场面专属：素材 + 首图 + 解读 + 自查 + 出物料**

## 两条流程（先路由）

**只判断一件事：用户给没给素材。**

| | 流程 A（图文） | 流程 B（视频成稿） |
|---|---|---|
| **触发** | 说「写名场面」「今天发名场面」「来一篇」，**没给素材** | **给了视频素材** —— 钩子段写在**文件名**里（`019-标题-50-56.mp4`）|
| **素材来源** | Claude 自己搜 B站 | 用户提供 |
| **产出** | GIF 首图 + 公众号文章 | **成品视频** + GIF 首图 + 公众号文章 |
| **前半段** | `01-选题` → `02-切图` | `B1-剪成片` → `B2-切首图` |
| **后半段** | `03 → 04 → 05 → 06 → 07` | **同一套，不复制** |

两条流程**只在前半段分叉，共用后半段**。跑哪条由触发条件决定，彼此不影响。

### 流程 A：图文（Claude 自己找素材）

| 步骤 | 文件夹 | 做什么 | 产出 |
|---|---|---|---|
| 01 | [`01-选题/`](01-选题/README.md) | 定今天写哪一场（蹭热点 / 自选 / 去重） | 片名 + 名场面 |
| 02 | [`02-切图/`](02-切图/README.md) | 找 BV号 + 时间码，切一张 3-8 秒 GIF | `input/clips/<名>.gif` |
| 03 | [`03-起标题/`](03-起标题/README.md) | 起一个贴原台词的标题 | 标题（≤22 字） |
| 04 | [`04-写正文/`](04-写正文/README.md) | 写 800-1200 字解读，落成 article.json | `output/YYYY-MM-DD/NN-名场面/article.json` |
| 05 | [`05-自查/`](05-自查/README.md) | AI 痕迹 + 公众号规范双清单，不过则重写 | 过 / 不过 |
| 06 | [`06-出物料/`](06-出物料/README.md) | **出物料**：跑 `--dry-run` 过硬门，生成可复制的正文/封面 | `发布物料.md` + `copy.html` + `cover.jpg` |
| 07 | [`07-写日志/`](07-写日志/README.md) | 追加一行日志（同时是去重依据） | `logs/YYYY-MM-DD.md` |
| 08 | [`08-推草稿箱/`](08-推草稿箱/README.md) | **（可选）**操作浏览器把稿子填进公众号草稿箱 | 草稿箱里一篇草稿（含头图 + 封面）|

### 流程 B：视频成稿（用户给素材）

| 步骤 | 文件夹 | 做什么 | 产出 |
|---|---|---|---|
| B1 | [`B1-剪成片/`](B1-剪成片/README.md) | 从**文件名**读钩子段 → 剪成四段成品 | `名场面/成品/<素材名>.mp4` |
| B2 | [`B2-切首图/`](B2-切首图/README.md) | 从**同一个钩子段**切文章首图 GIF | `input/clips/<编号>-<名>.gif` |
| 03–05 | 见左边流程 A 的表 | 起标题 / 写正文 / 自查，**完全同一套** | 同流程 A |
| 06 | [`06-出物料/`](06-出物料/README.md) | 出公众号物料，**同一套** | 同流程 A |
| B4 | [`B4-出视频物料/`](B4-出视频物料/README.md) | 给成片写**文案**（短标题 + 描述） | `article.json` 里的 `video_short` / `video_desc` 等 |
| B5 | [`B5-发视频号/`](B5-发视频号/README.md) | **（可选）**操作浏览器把成片发进视频号草稿箱 | 视频号草稿箱一条草稿 |
| 07 | [`07-写日志/`](07-写日志/README.md) | 同流程 A | `logs/YYYY-MM-DD.md` |

> **发布由人做**：公众号从 `copy.html` 复制正文 + 传 `cover.jpg` 当封面；视频号 / 抖音 / 快手传成片 + 复制文案。
> 每个平台要传什么、后台在哪，见 `B4-出视频物料` 和 `名场面/账号运营.md`。
>

> 两者都**只存草稿，绝不点发表**；要不要用由人决定，不用就照上面的手动流程走。
>
> **原来的自动推送**（`06-推草稿` 微信 API、`B4-发视频号`）**2026-10-10 停用**，
> 代码原样留在 [`_已停用/`](_已停用/README.md)，要恢复自动化时去那儿看。

> 原 `B4-发视频号` 已提为 [`B5-发视频号/`](B5-发视频号/README.md)，都不在 `_已停用/` 里了。）

> **命名说明**：`B1`/`B2`/`B4`/`B5` 的 `B` 前缀标记「属于流程 B」；`01`~`08` 不带前缀 —— 它们既是流程 A 的开头，又是两条流程共用的后半段。这个不对称是有意的，别去「统一」它。

## ⚠️ 最高优先级：preflight 硬门

`wechat-img/src/preflight.js` 是**唯一有否决权的规则**——`06-出物料` 跑 `index.js` 时由它强制内嵌调用，FAIL 就 `exit 1`、物料根本生成不出来，跳不过。它由 656 篇历史稿进化而来，**比本 skill 任何一条规则都严，且会随版本变化**。

**本 skill 的所有写作规范与它冲突时，以它为准。两条流程共用它。**

几条最容易踩的（完整见各步 README）：

- **第一人称全面禁用**（2026-09-14 决定）：全文「我」最多 1 处，禁「我认识/我朋友/我觉得/我们这代人」
- **存疑词禁用**：「据传/疑似/据说/有消息称」
- **万能骨架禁用**：开头「≤8字短句。＋展开」、结尾「不是X是Y」「说到底，」「X的是Y」
- **事实段 ≥ 情绪段**

**能出物料 = 这份稿子过过硬门**，所以复制出去的一定是扫过的稿。没过就回炉改稿（`05-自查`），**不是改门**。

## 依赖与首次配置

- **切图脚本**：`skill/gif_clip.py`（流程 A 用，依赖 `yt-dlp` + `imageio-ffmpeg`；流程 B 的 `B2` 也复用它，那时输入是本地文件、不走 yt-dlp）
- **剪辑脚本**：`skill/B1-剪成片/剪辑模板.py` + `批量剪.py`（流程 B 用）。在**仓库根目录**跑即可 —— 素材/成品的相对路径由脚本里的 `MEDIA_ROOT` 统一按 `名场面/` 解析。依赖 `imageio-ffmpeg` 提供的 ffmpeg
- **出物料脚本**：`skill/06-出物料/出物料.py`。底下复用同级的 wechat-img 项目：`node src/index.js ... --dry-run`，**排版/封面/硬门都不重复造**（两条流程共用）
- **`.env` 现在不用配了**：`--dry-run` 全程不碰微信 API，也不读 appid/secret（`wechat-img/src/config.js` 只在真推时才校验）。要恢复自动推送时才需要（见 `_已停用/06-推草稿`），届时坑在 cwd、IP 白名单、token 缓存三处
- **必须存在的同级项目**：`../wechat-img` —— 出物料脚本启动就检查
- **目录约定**（根目录只有这几个可见文件夹，新东西按类归位，别往根目录丢）：
  ```
  skill/     程序与配置：本索引 + 01~08 步骤 + B1/B2/B4/B5 步骤 + gif_clip.py
             _已停用/ 放停用的自动推送步骤（代码原样保留，别删）
  input/     输入素材：input/clips/ 放切好的首图 GIF（脚本自动建）
  output/    成品产出：output/YYYY-MM-DD/NN-名场面/（article.json、发布物料.md、copy.html…）
  logs/      每篇发文日志
  名场面/    流程B 的媒体库（2.1GB，已 gitignore）：素材/ 成品/ resource/ 图片/
             以及 剪辑流程.md、账号运营.md —— **脚本不在这里**，在 skill/B1-剪成片/
  ```

## 全局红线（跨步骤，各步 README 里有更细的）

- 不一篇配多图（名场面号一篇一张 GIF，多了反而稀释）
- 不跨天重复同一场 —— **流程 A 每次开跑先走 `01-选题` 的去重**；**流程 B 若复用已有名场面，同样要先查 `logs/`**
- 不把 B站/豆瓣 URL 放正文（变纯文本，删）
- 不为流量硬上抽象系高风险人物画面（台词引用 OK，画面不出现）
- **不跳过硬门**：`06-出物料` 跑通才算这份稿能发；出不了就回炉改，不改门
- **Claude 不发任何东西** —— 到了 `发布物料.md` 就停手，交给用户。
  **唯一例外是 `08-推草稿箱` 和 `B5-发视频号`**：用户明确要求时，可把稿子/成片推进
  **草稿箱**（不是发布），且**绝不点「发表」**。
- **视频号短标题不能带逗号**（平台不报错、静默失败，见 `B4-出视频物料`）
- **流程 B 的钩子段必须播两遍**，不许「优化」成一遍（见 `B1-剪成片`）
- 不定时任务（用户喊才跑）
