# 名场面发文 Skill（主流程 / 索引）

> **项目根目录**：本仓库根目录（即 `skill/` 的上级目录），下文命令一律在此目录下执行
> **调用方式**：用户说「写名场面」「今天发名场面」「来一篇名场面」之类，Claude **自动**选点、切 GIF 首图、生成解读文章、推草稿
> 一篇只配**一张名场面 GIF 首图**（用 `skill/gif_clip.py` 切），不另搜图、不配多图
> 文章 JSON 字段 / 排版 / CTA / 推草稿脚本细节见 [[wechat-daily]]（wechat-img 项目），本 skill 只写**名场面专属：选题 + 切图 + 解读 + 自查**

---

## ⚠️ 最高优先级：preflight 硬门

`wechat-img/src/preflight.js` 是**唯一有否决权的规则**——推草稿时由 `index.js` 强制内嵌调用，FAIL 就 `exit 1` 拒推，跳不过。它由 656 篇历史稿进化而来，**比本 skill 任何一条规则都严，且会随版本变化**。

**本 skill 的所有写作规范与它冲突时，以它为准。**

几条最容易踩的（完整见各步 README）：

- **第一人称全面禁用**（2026-09-14 决定）：全文「我」最多 1 处，禁「我认识/我朋友/我觉得/我们这代人」
- **存疑词禁用**：「据传/疑似/据说/有消息称」
- **万能骨架禁用**：开头「≤8字短句。＋展开」、结尾「不是X是Y」「说到底，」「X的是Y」
- **事实段 ≥ 情绪段**

推之前想先看效果：加 `--dry-run` 只生成封面 + HTML，不调微信 API（硬门照样跑）。

## 触发条件

用户说「写名场面文章」「今天发名场面」「来一篇」「写一场 XXX」之类。可指定某场（「写让子弹飞站着挣钱那场」），也可不指定让 Claude 自选。

**执行原则**：触发后**不再问澄清问题**，直接跑完整流程（下方 01→07）。中途模糊判断（选哪场、标题怎么起、GIF 取哪几秒、解读角度）自己定。仅当真正阻塞（B站 cookie 没配且下不动、所有候选都找不到视频源）才停下来报告。

## 流程索引

七个步骤，每步一个文件夹，**改哪一步就只动那个文件夹**：

| 步骤 | 文件夹 | 做什么 | 产出 |
|---|---|---|---|
| 01 | [`01-选题/`](01-选题/README.md) | 定今天写哪一场（蹭热点 / 自选 / 去重） | 片名 + 名场面 |
| 02 | [`02-切图/`](02-切图/README.md) | 找 BV号 + 时间码，切一张 3-8 秒 GIF | `input/clips/<名>.gif` |
| 03 | [`03-起标题/`](03-起标题/README.md) | 起一个贴原台词的标题 | 标题（≤22 字） |
| 04 | [`04-写正文/`](04-写正文/README.md) | 写 800-1200 字解读，落成 article.json | `output/YYYY-MM-DD/NN-名场面/article.json` |
| 05 | [`05-自查/`](05-自查/README.md) | AI 痕迹 + 公众号规范双清单，不过则重写 | 过 / 不过 |
| 06 | [`06-推草稿/`](06-推草稿/README.md) | 推微信草稿箱（**串行**） | 草稿 + media_id |
| 07 | [`07-写日志/`](07-写日志/README.md) | 追加一行日志（同时是去重依据） | `logs/YYYY-MM-DD.md` |

> 想扩展 skill 支持更多内容（新题材、新文体、新账号），按上面的分工改对应文件夹即可。

## 依赖与首次配置

- **切图脚本**：`skill/gif_clip.py`（已写好，依赖 `yt-dlp` + `imageio-ffmpeg`，已 pip 装妥）
- **推草稿脚本**：复用同级的 wechat-img 项目：`node ../wechat-img/src/index.js`，**不重复造**
- **首次配置 `.env`**（本项目根目录，且**必须留在根目录**，名场面号独立 appid/secret，别和 wechat-img 混用）：
  ```
  WECHAT_APPID=名场面号的appid
  WECHAT_APPSECRET=名场面号的secret
  AUTHOR_NAME=名场面号署名
  ```
  在项目根目录跑 `node ../wechat-img/src/index.js ...` 时，dotenv 读本项目 `.env`（cwd 是本项目），不会污染 wechat-img。
- **目录约定**（根目录只有 4 个可见文件夹，新东西按类归位，别往根目录丢）：
  ```
  skill/    程序与配置：本索引 + 01~07 步骤文件夹 + gif_clip.py + .bin/ffmpeg（软链，脚本自动建）
  input/    输入素材：input/clips/ 放切好的 GIF（脚本自动建）
  output/   成品产出：output/YYYY-MM-DD/NN-名场面/（article.json 等）
  logs/     每篇发文日志
  ```

## 实跑约定

| 角色 | 谁做 | 是否每次变 |
|---|---|---|
| 选点（蹭热点 / 自选 / 去重） | Claude 自动 | ✅ 每次换 |
| 定视频源（BV号 + 时间码）+ 切 GIF | Claude（调 `gif_clip.py`） | ✅ 每次换 |
| 生成 article.json + 自查 | Claude | ✅ 每次换 |
| 推草稿（`wechat-img/src/index.js`） | 脚本，Claude 调 | ❌ 不动代码 |
| preflight 硬门 | 脚本自动强制跑，**不过拒推** | ❌ 不动（改稿子，不改门） |
| 排版 / CTA / 封面规范 | 见 [[wechat-daily]] | ❌ 不动 |
| 日志 `logs/YYYY-MM-DD.md` | Claude 更新 | ✅ 每次加 |

## 全局红线（跨步骤，各步 README 里有更细的）

- 不一篇配多图（名场面号一篇一张 GIF，多了反而稀释）
- 不跨天重复同一场（每次开跑先走 `01-选题` 的去重）
- 不把 B站/豆瓣 URL 放正文（变纯文本，删）
- 不为流量硬上抽象系高风险人物画面（台词引用 OK，画面不出现）
- 不跳过 `05-自查` 直接推（自查是发文前最后一道关）
- 推草稿**一律串行**，绝不并行（同 appid 并发 gettoken 互踩，全报 40001）
- 不定时任务（用户喊才跑）
