# write-article —— 写作编排

**给什么**：热点主题 + 事实清单 + 避撞清单
**还什么**：写作 prompt（plan）或符合性校验结果（verify）

原实现是 559 行的 `04-writing-pools.md`（全自然语言规范），靠 Claude 自己读、自己抽、自己记。此原子把**抽维度**和**验成稿**做成代码。

## 触发

「写这篇文章」「生成写作 prompt」「验一下稿子」

## 用法

```bash
# plan：产出写作 prompt
node atom/write-article/src/index.mjs \
  --topic "美舰闯南沙" \
  --facts 03-fetch-facts/facts-raw.json \
  --dedup 02-dedup-log/result.json \
  --images 2 \
  --out-dir 04-write-article

# verify：校验写好的稿件
node atom/write-article/src/index.mjs --verify article.json --dims 04-write-article/dims.json
```

| 维度 | 池大小 | 抽什么 |

| `opening_hook` | 20 | 开头钩子（场景代入/数据冲击/冷知识起…） |

### 被禁用的池项

**第一人称已全面禁用（2026-09-14）**，以下池项标 `banned` 永不抽中：

## 抽的是骨架不是标签

这是 2026-09-14 的核心教训：**抽抽象标签时，模型会用自己最顺手的句式去实现它**——标签不同、句式相同。实测近 40 篇：结尾 42% 塌进「说到底/不是X是Y」，开头 62% 塌进「≤8字短句。＋展开」。

所以 prompt 里给的不只是标签名，还有**结构要求**（「以某人的一个动作收尾，无判断」），verify 阶段还会按结构判据检查成稿。

## verify 测什么

这是 selfcheck 测不出来的部分：

| 检查 | 例子 |
|---|---|
| 结尾骨架符合性 | 抽了「数字定格」，末句必须含数字 |
| 结构配方符合性 | 抽了「##2 + 6 段」，实际必须有 2 个 `##`、约 6 段 |
| 格式组合符合度 | 抽了 5 种元素，至少出现 3 种 |
| 字数区间 | 800-1200 |
| 可查证事实数 | ≥3 段含具体数字 |
| 非纯文字展现 | 至少 1 种（表格/列表/提示框） |

**分工**：`selfcheck` 管通用硬门（第一人称/模板句/句长节奏），`write-article verify` 管本篇形状。

## 硬约束（写进 prompt，verify 也查）

- 全文禁第一人称（「我」≤1 处）
- 800-1200 字
- 三件套至多用两件（编号小标题 / 每段引言 / 每段加粗）
- ≥3 条可查证事实、事实段 ≥ 情绪段
- 升华段 ≥3 句
- 6 条禁飞骨架（不是X是Y / 说到底 / 真正X的是Y / ≤8字短句开头 / X的是Y / 这才是X留给我们的）

## 已验证

- plan 模式：11 条事实 + 9 个维度 → prompt 完整可用
- verify 模式：字数不足、## 数不符、段数不符均正确报出

## 已知坑

1. **结构配方的判据在 `detail` 字段**（「##2 + 6 段」），不在配方名里——配方名只有「双标题+清单」这种概括，解析不出数字
2. **段落数允许 ±1**——图片行、列表块会让计数有出入
3. **format 池的「表格」语法含竖线**，从 md 抽取时会被列切分打断，该条已手工修正
4. 池子是从 md 正则抽取的，md 结构变化会导致抽取失败——改 md 后重跑抽取脚本
