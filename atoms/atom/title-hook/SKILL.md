# title-hook —— 标题生成与校验

**给什么**：热点原词（热榜标题原文）
**还什么**：合规标题 + 校验结果

**标题规则在 2026-08-27 简化了**：直接用热榜原词，不套骨架、不抽池子。因为蹭流量的核心是「标题里就是用户正在搜的那句话」，抽象化改写反而蹭不到。同质化风险改由正文维度轮换去破。

## 触发

「起个标题」「这个标题行吗」「标题太长」

## 用法

```bash
# 原词 → 标题（自动压缩/补全）
node atom/title-hook/src/index.mjs --raw "西藏泥石流已致3人遇难265人失联，救援仍在紧张进行中（最新通报）"

# 校验自己写的候选标题
node atom/title-hook/src/index.mjs --raw "原词" --check "我写的标题"

# 带近篇去重
node atom/title-hook/src/index.mjs --raw "某原词" --dedup 02-dedup-log/result.json --out-dir 01-title

# 原词太短时补事件词
node atom/title-hook/src/index.mjs --raw "运-20赴西藏救援" --event "泥石流"
```

## 压缩逻辑（超 22 字）

按优先级逐步处理：

1. 去掉括注 `（）`、书名号 `《》`、引号 `「」`、方头括号 `【】`
2. 还超就按逗号切，保留前半（主体+动作通常在前）与**含数字的片段**
3. 仍超就硬截断到 22 字——宁可断句不完整也不能超

实测：`西藏泥石流已致3人遇难265人失联，救援仍在紧张进行中（最新通报）`（33 字）
→ `西藏泥石流已致3人遇难265人失联`（17 字）

## 补全逻辑（短于 12 字且有事件词）

补上事件词，但**只能补原词里隐含的**，不能编造新的权威主体或动作。

## 硬底线

| 检查 | 说明 |
|---|---|
| ≤22 字 | 超了微信后台也会截断 |
| **非「我X了」情绪尾** | 正则由 darwinian_evolver 在 656 篇历史稿上进化，覆盖「愣住了/想了半天/眼眶热了/扎心了」等变体 |
| 无标题党词 | 震惊/速看/刚刚/突发 |
| **「曝光」放行** | 「央视曝光」是正当新闻动词，是蹭度硬杠杆，不算标题党 |
| 不与近 N 篇同原词 | 读 dedup-log 的 `title_words.used` 比对 |

WARN（不拦）：标题太短、未见具体信息点。

## 输出

```json
{
  "ok": true,
  "raw": "西藏泥石流已致3人遇难265人失联，救援仍在紧张进行中（最新通报）",
  "final": "西藏泥石流已致3人遇难265人失联",
  "chars": 17, "max_chars": 22,
  "compressed": true, "expanded": false,
  "errors": [], "warns": [],
  "duplicates": [],
  "title_style": "贴原词-西藏泥石流已致3人遇难265人失联"
}
```

`title_style` 字段直接就是日志该记的格式，塞给 `dedup-log --append` 即可。

## 已验证

- 超长原词（33 字）→ 压缩到 17 字，主体+动作+数字全保留
- 情绪尾「美舰闯南沙，我看懵了」→ 正确拦截
- 「震惊！某地发生大事」→ 正确拦截
- 「央视曝光擦边手办乱象」→ 正确放行（曝光不算标题党）
- 与近篇同原词 → 正确报出冲突的篇目 id

## 已知坑

1. **压缩是机械片段拼接，不是智能摘要**——复杂原词压缩后可能读起来生硬，需要人工润一遍
2. **硬截断可能断在半句**——这是保底策略，优先用前置的去括注/保留数字片段
3. **不要自己编造权威主体**：蹭度硬杠杆（央视/政法委 + 曝光/严打）必须原词本身带的，不能另造
