第一章

语言模型的本质

1.1预测下一个 token

「信息就是惊喜，就是你猜不到的程度。信息量是由内容的离谱程度来决定的，越离谱信息量就越高。」

接龙游戏：床前明月____ → 几乎所有人填「光」。今天天气很____ → 不唯一：好／热／冷／不错。

候选概率
好35%
热20%
冷15%
不错10%
其他合计20%

token：语言模型处理的最小单位不是「字」而是 token。今天天气很好 切成 今天 | 天气 | 很 | 好 = 4 个 token（6 个字）。合并的两个理由：①省步数（4 步 vs 6 步）②常一起出现的字应视作整体。

语言模型，是一个给定前文、输出「下一个 token 概率分布」的程序。

循环生成示意：

今天天气很 → 好 今天天气很好 → ， 今天天气很好， → 适合 今天天气很好，适合 → 出门

1.2为什么预测 token 能带来智能

图灵测试（图灵，1950，《计算机器与智能》）：裁判通过打字和两个看不见的对象聊天，一个是人一个是机器，聊完判断哪个是机器。反复测试也分不出来 → 认为机器具备人的智能。

ALAN TURING
1912 — 1954
《计算机器与智能》1950

关键：测试里裁判能看到的只有文字。机器内部怎么运转不重要，重要的是写出来的像不像人。

语言模型从海量人类文字里学「给定前文，人接下来会写什么」。预测得越准，接出来的文字越像人。把预测下一个 token 做到极致，就是在通过图灵测试。

要预测得准，光记字词搭配不够，需要三样东西：

  • 法国的首都是____ → 巴黎 —— 需要知识
  • 小明比小红高，小红比小刚高，三个人里最矮的是____ → 小刚 —— 需要推理
  • 他打开冰箱，发现牛奶已经过期了，于是皱着眉头把它____ → 倒掉／扔了 —— 需要常识

结论：「预测」这个看似简单的目标，逼着模型去掌握文字背后的东西。

机器是否真的「理解」至今有争论；图灵测试给的是行为标准——让模型预测的概率尽量接近人。

1.3概率对应了多少信息？

猜数字游戏：从 1～8 中等概率选一个，你问只能答「是／否」。

笨办法：是 1 吗？是 2 吗？…… 每次「不是」只排除一个。

折半问法（假设答案是 6）：

第几问问题回答剩余候选
开始——1,2,3,4,5,6,7,8
第一问大于 4 吗？是5,6,7,8
第二问大于 6 吗？否5,6
第三问大于 5 吗？是6

8 → 4 → 2 → 1。任何答案都能在 3 次后确定。

信息 = 帮助你消除不确定性的东西。 每次折半提供 1 bit；3 次共 3 bit。

bit 的直观定义：区分两个等概率可能性所需要的信息量。

4 个候选折半 2 次；8 个 3 次；16 个 4 次。候选越多，起始越不确定，需要的信息越多。

折半法不仅「最多 3 次」，平均也最省：每次是／否最多 1 bit，确定 8 个等可能候选至少需 log28 = 3 bit，所以任何问法平均至少 3 次，折半法正好踩在下限上。

单个结果的信息量 = −log2 p(x)

为什么底数是 1/2：信息量本质就是「折半了多少次」。记住三点：①p(x) 是概率 ②概率越小，出现时信息量越大 ③概率为 1 的结果信息量为 0。

呼应开头：越离谱 = 概率越小 = 信息量越大。 「明天太阳从东边升起」信息量 ≈ 0；「太阳从西边升起」是天大新闻。

1.4熵：平均而言，答案有多难确定？

改变规则：选 1 的概率 90%，剩下 10% 分给 2～8。此时先问「是 1 吗」更有效——90% 的时候一问就结束。

难度不只由「有几个候选」决定，还与各候选出现的概率有关。

熵 H(X) = Σ p(x) · I(x) = −Σ p(x) · log2 p(x)

硬币对比：

情况熵为什么
正反各 50%1 bit两种结果同样可能
正面 90% / 反面 10%≈ 0.469 bit大部分时候可预期是正面
必定正面0 bit没有不确定性

猜数字两局对比：

情况熵
1～8 等概率3 bit
1 占 90%，2～8 平分 10%（每个 1/70 ≈ 0.0143）≈ 0.750 bit

熵的实在含义：平均最少要用多少 bit 才能把答案记下来——数据能被压缩到的极限，任何无损编码的平均长度都不可能低于熵。

规律掌握越准 → 编码越短。能压到熵，说明能被利用的规律都挖出来了，剩下的是真正无法预测的随机性。

压缩即智能：语言的下一个 token 真实概率里藏着语法、常识、逻辑、人的意图。模型预测越准 → 越能把文字压到接近它的熵 → 这就必须把文字背后的规律学进去。

「预测越准、压缩越短」是数学事实；「压缩得好就是智能」只是一个有启发的研究视角，不是已证明的定理。反例：「一万个 A」可以写成「A 重复一万次」，一个简单程序就能压得极短，但不能说它会推理。

1.5交叉熵

熵是数据本身的性质，规则不变熵就不变（0.75 bit），模型估得准不准都改变不了它。会变的是：按模型的估计去编码，实际要花多少 bit。

真实规则「1 占 90%」；模型以为 8 个等概率。模型认为每个数字都是 1/8，给每个都分配 3 bit。可 90% 出现的是 1，本来 0.152 bit 就够：

数字 1：真实出现 90%，模型给码长 −log₂(1/8) = 3 bit 数字 2～8：真实共出现 10%，模型给码长也是 3 bit 平均码长 = 0.9×3 + 0.1×3 = 3 bit

比熵多花 2.25 bit，全是估计错概率白白浪费的。

交叉熵 H(p, q) = −Σ p(x) · log2 q(x)

和熵只差一处——把对数里的 p(x) 换成 q(x)。

  • p(x)（真实概率）负责加权：这个结果实际多常出现。
  • q(x)（模型概率）负责定价：这个结果每出现一次要花多少 bit。
  • 当 q = p 时，交叉熵 = 熵。

三种模型对比（真实规则都是 1 占 90%）：

模型认为的概率交叉熵比熵多花
和真实一样：1 占 90%≈ 0.75 bit0
等概率（什么规律都不知道）3 bit2.25 bit
2 占 90%，其余平分（自信地猜错）≈ 6.04 bit≈ 5.29 bit

自信地猜错，比什么都不知道还糟。

不需要知道真实概率 p(x)：真实概率已经体现在真实数据里了。

困惑度 = 2交叉熵，意思是「模型的犹豫程度相当于在几个等可能候选里猜一个」。等概率模型交叉熵 3 bit → 困惑度 23=8；掌握规律的模型 ≈ 0.75 bit → 困惑度 ≈ 1.7。

训练语言模型，就是在海量的人类文本上，不断降低交叉熵。

1.6香农的实验

CLAUDE SHANNON
1916 — 2001
《印刷英语的预测与熵》1951

英文 26 字母 + 空格 = 27 种符号。已知信息越多，下一个字符越好猜：

已知的信息每个字符的熵（约）
什么都不知道，27 种符号等可能4.75 bit
知道每个字母各自出现的频率4.03 bit
知道前 1 个字母3.32 bit
知道前 2 个字母3.1 bit
知道前面约 100 个字母0.6～1.3 bit

已知的上下文越多，下一个字越好猜，熵就越低。 这也是语言模型要尽可能看长前文的原因。

香农的办法：直接让人当预测者。遮住一段英文，让受试者一个字符一个字符地猜。论文一次实验里 102 个字符有 79 个是第一次猜中的。

香农估算：英文每个字符的熵只有 0.6～1.3 bit，约等于抛一次硬币。

由于交叉熵永远不低于熵，模型在真实文本上的交叉熵，就是语言熵的一个上界：模型越好，上界压得越低。

第二章

神经网络

2.0为什么不能靠人写规则

想让人写规则：「口渴」后接「水」，「困了」后接「咖啡」…… 但语言里规律太多（搭配、语法、常识、语气）且处处例外，永远写不完写不对。早年机器翻译都卡在这。

规则只能让机器自己从海量文本里统计和学习出来。

最简单的统计办法：数「某段前文后面都跟过什么」。「一杯」后跟「水」600 次、「茶」300 次、「咖啡」100 次 → 预测 60%／30%／10%。

表的问题：词表 10 万 token，只看前 10 个，组合就有 1050 种，绝大多数从没出现过。他在沙漠里走了三天三夜，终于喝到了一杯____ 查表只会得到「没见过」；人却一眼看出这和「口渴了想喝水」是同一类情境。

需要的不是死记，是举一反三：从见过的句子学到规律，用到没见过的句子上。神经网络就是这种工具。

2.1神经元

最简单的神经元：一个输入 x，一个输出 y。两件事：①算一次函数 wx+b（w = 权重，b = 偏置）②送进非线性函数弯折，最常用 ReLU：

ReLU(z) = max(0, z)

例 w=2, b=−1：

x=0 → 2×0−1 = −1 → ReLU = 0 x=0.5 → 2×0.5−1 = 0 → ReLU = 0 x=2 → 2×2−1 = 3 → ReLU = 3

把神经元想象成一个开关：b 决定在哪里打开（这里 x=0.5），w 决定打开之后增长多快。

真实神经元有很多输入：一个 token 表示成几千个数字（向量），上一层也有几千个神经元各产生一个输出。给每个输入配一个权重，乘完加起来 = 加权求和：

y = ReLU(w1x1 + w2x2 + ⋯ + wnxn + b)

为什么叫「神经元」：借自大脑——加权求和 = 汇总，ReLU = 过阈值才放电。（McCulloch & Pitts, 1943）

为什么一定要弯折：一次函数套一次函数还是一次函数。只有加权求和的话，叠多少层都等价于一层，只能表示直线式关系。加上 ReLU 这样的弯折，才能表示弯弯曲曲的复杂关系。

2.2Softmax：从分数到概率

最后一层特殊：词表里每个 token 对应一个神经元，算出的加权和就是这个 token 的分数（logits）。最后一层不做 ReLU，否则负分全变 0，分不出高低。

分数不能直接当概率：可正可负；加起来不等于 1。

Softmax：先对每个分数取指数（保证为正），再除以总和（保证加起来等于 1）。

候选分数取指数概率
水3.0≈ 20.09≈ 69%
茶2.0≈ 7.39≈ 25%
书0.5≈ 1.65≈ 6%
语言模型的骨架：前文 → 神经网络 → 每个 token 的分数 → Softmax → 下一个 token 的概率

2.3通用逼近定理

只要神经元足够多，哪怕只有一层，神经网络也能以任意精度逼近任意连续函数。（Cybenko / Hornik, 1989）

用 ReLU 直观看出：3 个 ReLU 拼出一个「小帐篷」：

ReLU(x) − 2·ReLU(x−1) + ReLU(x−2)

把很多帐篷并排，按目标曲线各处高度调好每个帐篷，加起来就是贴着目标曲线的折线。帐篷越多越窄，折线越贴近。

这个定理有三件事没说：①没说要多少神经元 ②没说参数怎么找 ③没说能不能推广。

2.5梯度下降

刚搭好的网络参数都随机，输出概率表也乱，交叉熵很高。训练就是在海量文本上把交叉熵降下来。

单参数例子：模型是「输出 = w × 输入」，只有一条数据（输入 2，正确答案 6）。损失用误差平方。

设 w=1：预测 = 1×2 = 2，误差 = 2−6 = −4，损失 = 16 把 w 从 1 调到 1.01：预测 = 2.02，误差 = −3.98，损失 ≈ 15.84（降了约 0.16） 参数增加 0.01，损失减少约 0.16，变化比例 ≈ −16 ← 这就是【梯度】

梯度：参数往某方向微微一动，损失会怎么变。梯度为负 → 该调大。梯度为正 → 该调小。

把损失想象成一片山地，参数是你站的位置，梯度告诉你脚下坡朝哪边、多陡。看不到整座山，但每一步都往下坡走，就能走到谷底附近。

新参数 = 旧参数 − 学习率 × 梯度

2.6反向传播

反向传播只需要正向算一遍、反向推一遍，就能得到所有参数的梯度，用的是微积分的链式法则（Rumelhart、Hinton 等，1986）。

输入 x = 1 第1层：h = a × x (a=2) → h = 2 第2层：y = b × h (b=3) → y = 6 损失： L = (y−9)² → L = 9 ① 损失对 y 的梯度：2×(y−9) = −6 ② 第2层 y = b×h b 的梯度 = h×(−6) = 2×(−6) = −12 传给 h 的梯度 = b×(−6) = 3×(−6) = −18 ③ 第1层 h = a×x a 的梯度 = x×(−18) = 1×(−18) = −18

每一层做的：拿到后面传回来的梯度，乘上自己这一层的局部系数，算出自己参数的梯度，再把梯度继续传给前一层。

常用的优化器 Adam：参考最近几步梯度的平均方向（像滚下山的球有惯性），还会给每个参数单独调整步子大小。

梯度消失：深网络为什么难训练。梯度每往回传一层就要乘上该层局部系数：

每层系数 0.5，传 30 层：0.5³⁰ ≈ 0.000000001 → 梯度消失 每层系数 1.5，传 30 层：1.5³⁰ ≈ 19 万 → 梯度爆炸

2.7归一化

同样的连乘在数值往后传时也会出现：每层放大 10%，1.196 ≈ 9400；每层缩小 10%，0.996 ≈ 0.00004。

归一化：每层计算之前，先把向量的数值调回标准的大小范围。

最常用 层归一化 LayerNorm：对每个位置的向量，先减平均值，再除以标准差。

向量 (2,4,6,8)： 平均值 = 5 → 减去 → (−3,−1,1,3) 标准差 = √[(9+1+1+9)/4] = √5 ≈ 2.24 → 除以 → (−1.34,−0.45,0.45,1.34)

数值的整体大小被去掉，各分量之间的相对关系保留。

现代大模型常用更简单的 RMSNorm：不减平均值，只除以「均方根」，效果差不多，计算更省。

2.8残差网络

2015 年何恺明等人发现：CIFAR-10 上，56 层的普通网络连训练误差都比 20 层的更高。

解决办法 残差连接：每一层不再输出一个全新的结果，而是算出对输入的修改，再加回到输入上。

没有残差：向量 → 第1层重写 → 第2层重写 → ……（每层都重抄一遍） 有残差： 向量 → 加上第1层的修改 → 加上第2层的修改 → ……

好比在原稿上做批注，而不是每层都重抄一遍。抄得越多越容易走样；批注再多，原稿都还在。

xL = x0 + F1 + F2 + ⋯ + FL

更关键的好处：给梯度修了一条「直通路」。 残差层输出 y = x + F(x)，梯度回传时局部系数是「1 加上 F 的系数」：

没有残差：y = F(x)， 局部系数 = F 的系数，比如 0.01 有残差： y = x + F(x)， 局部系数 = 1 + F 的系数，比如 1.01 传 30 层：0.01³⁰ = 10⁻⁶⁰（彻底消失）；1.01³⁰ ≈ 1.35（完好传回）

用上后他们训练出 152 层网络，拿下 2015 年 ImageNet 冠军。今天的大语言模型每一层都用了残差连接。（He 等，2016）

2.9背答案还是学方法：过拟合与泛化

两个学生看一万道乘法题和答案。学生 A 把答案全背下来，学生 B 学会乘法的方法。出没见过的题：A 答不出来，B 能算出来。B 不只是记住了，而是学会了。

压缩和泛化来自同一个源头：不是先压缩、然后突然变聪明，而是找到了规律，就同时获得了压缩能力和解决新问题的能力。

参数足够多时网络完全可以硬记训练数据，训练集交叉熵很低，换新文本就不行 = 过拟合。

训练集交叉熵验证集交叉熵说明
下降同步下降学到的东西能推广，训练正常
继续下降不降反升开始死记训练数据，过拟合了
都很高都很高模型太小或训练不够，没学会

判断模型学没学会，要看它在没见过的文本上的表现，而不是训练数据上的分数。

第三章

Transformer

2017 年 Google 论文《Attention Is All You Need》提出 Transformer 架构（Vaswani 等，2017）。语言模型只需「接着往下写」，所以只用解码器这一半。

Google
《Attention Is All You Need》2017
token 编号序列 ↓ 嵌入：每个编号换成一个向量 ↓ 加入位置信息 ↓ Transformer 块 × N 层（注意力 + 前馈网络） ↓ （归一化 + 残差连接） ↓ 输出层：把最后一个位置的向量变成每个 token 的分数 ↓ Softmax 下一个 token 的概率

3.1嵌入：把编号变成有含义的向量

分词后每个 token 有编号（「水」是 452，「茶」是 25）。不能直接把编号送进网络：编号本身没有含义。

甜脆红圆是水果能喝
苹果0.70.80.80.910
梨0.80.60.10.610
水000001

嵌入：给每个 token 分配一个向量，大模型里通常几千维。所有 token 的向量存在嵌入表里，查表就能把编号换成向量。

Llama 3 的 80 亿参数版本：词表约 12.8 万个 token，每个向量 4096 维，嵌入表约 5.25 亿个数字。

训练会让意思相近的 token 靠在一起：

token向量（示意）
水(0.9, 0.1)
茶(0.8, 0.2)
书(0.1, 0.9)

「水」和「茶」夹角约 8°，「水」和「书」夹角约 77°。

向量操作：

操作怎么算代表什么
点积对应位置相乘再加起来两个东西有多像
加法对应位置相加把两组特征叠在一起
减法对应位置相减两者差在哪 = 一种「关系」
数乘每个位置乘同一个数方向不变，特征整体变强或变弱

word2vec：「国王」−「男人」+「女人」≈「女王」（Mikolov 等，2013）

叠加（superposition）：三维空间里随机两方向夹角落在 88°～92° 的概率只有约 3.5%；在 GPT-3 的 12288 维里超过 99.98%。模型可以把远多于维度数的概念各自放在几乎互不干扰的方向上。

3.2注意力

他口渴了，于是喝了一杯____ → 大概率填「水」 他困了，于是喝了一杯____ → 更可能「茶」或「咖啡」

决定答案的「口渴」和「困」在好几个 token 之前。

每个位置都必须能从前文的其他位置收集信息。 最简单的办法是平均，但有用信息会被大量无关词冲淡。

注意力机制：

  1. 给前文的每个位置打一个「相关程度」分数
  2. 用 Softmax 把分数变成权重（都是正数，加起来等于 1）
  3. 按权重对各位置的信息加权平均

注意力的结果会加回当前位置的向量上（残差连接）。

3.3因果掩码：只能往前看

每个位置只能看它自己和前面的位置，否则就是偷看答案。

当前位置＼能看到他口渴喝了一杯
他✓
口渴✓✓
喝了✓✓✓
一杯✓✓✓✓

做法是把「未来位置」的分数设为负无穷，经过 Softmax 后权重为 0。这叫因果掩码。

一段 1000 个 token 的文本，一次就能提供约 1000 道练习题。

3.4查询、键、值（QKV）

每个位置根据自己的向量算出三样东西：

名称直观含义类比：图书馆找书
查询 Q我在找什么信息？你想查的主题
键 K我这里有什么信息？每本书书脊上的标签
值 V如果你关注我，我能提供的内容书的正文

手算一次：前文「他 / 口渴 / 喝了 / 一杯」，为最后一个位置「一杯」收集信息。假设向量只有两维：

位置键值
他(0, 2)(0, 1)
口渴(2, 0)(1, 0)
喝了(1.5, 0)(0.8, 0)
一杯(0.5, 0)(0.3, 0)

「一杯」的查询是 (1, 0)，意思大致是「我在找和饮水有关的信息」。

位置点积权重
他06.9%
口渴250.9%
喝了1.530.9%
一杯0.511.4%

缩放：分数要先除以 √d。上面例子里除以 √2 后，「口渴」的权重从 50.9% 变成约 43.6%。

Attention(Q, K, V) = softmax(QKT / √d) · V

3.5多头注意力

如果「一杯」的查询换成 (0, 1)（「这件事是谁做的」）：

位置分数权重
他271.1%
口渴09.6%
喝了09.6%
一杯09.6%

这次注意力集中到「他」身上。所以 Transformer 同时使用多组独立的 Q、K、V 矩阵，每组叫一个注意力头。

研究者找到过功能清晰的归纳头：前文出现过「A B」，之后再遇到「A」时会去关注上次「A」后面的「B」。

3.6位置信息

注意力只看「相关程度」，本身不知道顺序。「狗咬人」和「人咬狗」用字完全相同，意思截然相反。

旋转位置编码（RoPE）：不改 token 向量本身，而是在算注意力时，把查询和键按「和位置成正比的角度」旋转一下。（Su 等，2021）

二维看最直观：假设每往后一个位置多转 10°。第 3 个位置的查询转 30°，第 5 个位置的键转 50°。多出来的夹角是 50°−30° = 20°，只和两个位置相差 2 有关。

RoPE 让注意力分数只取决于相对距离，而不是绝对位置。Llama 等许多模型都用 RoPE。

3.7前馈网络

注意力完成「位置之间交换信息」，接下来每个位置各自经过一个前馈网络。结构简单：先把向量放大到约 4 倍宽，经过非线性函数，再压回原宽度。

GPT-3：向量宽度 12288，前馈网络中间层宽度 49152。

类比：注意力 =「开会交流」；前馈网络 =「回到工位各自消化」。

前馈网络约占 Transformer 参数的三分之二。

3.8把所有部件拼起来

一个 Transformer 块由两个子层组成。归一化放在子层前面（Pre-Norm）：

x = x + 注意力(归一化(x)) ← 各位置交换信息，写回残差流 x = x + 前馈网络(归一化(x)) ← 各位置各自加工，写回残差流

参数都在哪里？ 设向量宽度 d：

部分矩阵参数量
注意力Q、K、V、输出，4 个 d×d 矩阵4d²
前馈网络d→4d、4d→d，2 个矩阵8d²
合计12d²

代入 GPT-3 最大版本（d=12288，96 层）：

每层： 12 × 12288² ≈ 18.1 亿 96 层： 18.1 亿 × 96 ≈ 1739 亿 嵌入表：50257 × 12288 ≈ 6.2 亿 合计 ≈ 1746 亿，与公布的 1750 亿基本一致
第四章

从模型到 ChatGPT

本章依次回答五个问题：一张概率表怎么变成一段话？只会续写的模型怎么变成聊天助手？它怎么联网、看图、用工具？模型为什么越做越大？它有哪些做不好的地方？

4.1自回归生成

生成就是循环：从概率表里选出一个 token，接到前文后面，再交给模型预测下一个。自己的输出成为下一步的输入 = 自回归生成。

重要推论：已经写出的 token 不会撤回。 如果前面选了一个不太好的词，后面只能顺着它往下写。

4.2采样：从概率表里挑一个

还是「他口渴了，于是喝了一杯____」，模型给出水 69%、茶 25%、书 6%：

策略做法特点
贪心永远选概率最高的稳定，但容易单调、重复
随机采样按概率抽签更多样，但偶尔会抽到离谱的低概率 token
Top-k只在概率最高的 k 个里抽截掉长尾，但 k 是固定的
Top-p（核采样）从高到低累加概率，达到 p 就停候选数量随情况自动变化

Top-p 以 p=90% 为例：水 69% + 茶 25% = 94% > 90%，所以只在「水」和「茶」里抽；按比例重新分配后约 73% 和 27%，「书」被排除。

完全猜得到的文字，没有信息。

4.3温度：保守还是大胆

温度：先把每个分数除以温度，再做 Softmax。

温度水茶书效果
0.5≈ 88%≈ 12%≈ 0.6%更集中、更保守
1≈ 69%≈ 25%≈ 6%原始分布
2≈ 53%≈ 32%≈ 15%更平均、更多样

温度趋近 0 → 最高分拿走几乎全部概率（相当于贪心）；温度很高 → 分数差距几乎抹平。

采样只能在模型给出的概率里挑，改变不了模型本身的理解能力。

4.4基座模型：只会续写

模型学的都是「人写的文本接下来通常是什么」，这一步叫预训练，得到基座模型。它只会续写，不会「回答」：

输入：法国的首都是哪里？ 基座模型可能的续写：德国的首都是哪里？英国的首都是哪里？……

知识在预训练里已经学到了，缺的是「以助手身份回应」的行为方式。 把它变成助手的训练统称后训练。

4.5监督微调（SFT）：看示范学回答

收集大量「指令 + 优质回答」的示范，用同样的「预测下一个 token」方式继续训练。训练时通常只对「助手」部分计算交叉熵。

<|系统|>你是一个乐于助人的助手。 <|用户|>法国的首都是哪里？ <|助手|>法国的首都是巴黎。<|结束|>

数据质量比数量更重要。 InstructGPT 只用了约 1.3 万条提示；LIMA 只用 1000 条精心挑选的示范，就让一个 650 亿参数的基座模型有了相当不错的对话能力。

4.6RLHF：从人类偏好中学习

基于人类反馈的强化学习（RLHF）三步：

  1. 收集比较数据：对同一个问题让模型生成几个回答，请标注员选出更好的
  2. 训练奖励模型：用这些比较数据，训练另一个模型给回答打分
  3. 强化学习：模型生成回答 → 奖励模型打分 → 让高分回答更可能被生成

奖励投机：奖励模型略微偏爱长回答，模型就越写越长、越写越空。

InstructGPT 研究中，标注员更喜欢 13 亿参数的 InstructGPT 的回答，而不是 1750 亿参数的 GPT-3 的回答。

后来出现更简单的 DPO（直接偏好优化）：跳过奖励模型，直接用「较好／较差」的回答对去调整模型。

4.7推理强化学习：只告诉它对不对

DeepSeek-R1-Zero
AIME 15.6% → 71.0%

DeepSeek-R1 的报告显示：直接在基座模型上用推理强化学习训练（R1-Zero），模型在 AIME 2024 数学竞赛题上的正确率从 15.6% 提升到 71.0%。

没有人教它「怎么想」，只告诉它「结果对不对」，它却自己摸索出了「多想一会儿」的策略。
阶段数据得到什么
预训练数万亿 token 的普通文本基座模型：知识多，但只会续写
监督微调数千到数十万条示范能按指令回答
偏好对齐（RLHF、DPO）人类或 AI 的比较数据更有用、更得体、更安全
推理强化学习可自动判对错的题目更强的推理能力

4.8联网、看图、用工具

工具调用：模型只负责写出「要做什么」。 外部程序看到特定格式就去执行，再把结果作为一段新文字拼到上下文后面交还给模型。

<|助手|><|调用工具|>搜索：北京 今天 天气<|结束|> <|工具结果|>北京今天晴，最高气温 22℃…… <|助手|>北京今天是晴天，最高 22℃，适合出门。<|结束|>

看图：把图片也变成 token。 把图片切成许多小方块，再用一个专门的网络把每一块转成一个向量。

不管是聊天、用工具还是看图，对模型来说，一切都是一串 token。它做的始终只有一件事：根据前文，预测下一个。

4.9规模定律

影响模型能力的三个核心量：参数量 N（脑容量）、训练 token 数 D（读过多少书）、计算量 C（花了多少学习时间）。

常用估算：训练计算量 ≈ 6 × N × D。代入 GPT-3：6 × 1750亿 × 3000亿 ≈ 3.15×10²³，与论文报告的 3.14×10²³ 几乎一样。（Kaplan 等，2020）

只扩大这一项扩大 10 倍后，交叉熵约变为原来的
参数量84%
数据量80%
计算量（最优分配时）89%

2022 年 Chinchilla 发现：在固定计算预算下，每个参数约对应 20 个训练 token 比较划算。Llama 3 的 80 亿参数版本读了约 15 万亿 token——因为模型只训练一次，却要被使用无数次，而使用成本取决于参数量。（Hoffmann 等，2022）

4.10损失降不到零

Chinchilla 研究把交叉熵拆成三部分：

交叉熵 ≈ 不可约的部分 + 模型不够大带来的部分 + 数据不够多带来的部分

第一项无论如何都消除不了，拟合出的值约为每个 token 1.69 nat（约 2.4 bit）——它对应的是自然文本本身的熵。

交叉熵永远不低于熵。 规模定律描述的，正是模型的交叉熵如何一步步逼近语言本身的熵。

4.11幻觉

幻觉：模型生成流畅、自信但与事实不符的内容。四个角度理解：

  1. 训练目标是「像」，不是「真」。
  2. 零散的事实没有规律可循。 训练数据中 20% 的生日信息只出现过一次，那么可以预期基座模型在这类问题上至少有约 20% 会答错。（Kalai, 2025）
  3. 评测奖励「猜」。 回答「不知道」和答错一样得零分。
  4. 写出的字收不回来。

越是冷门、越是具体（人名、数字、日期、引用、网址），越容易出错。

4.12其他常见局限

局限根源应对
知识有截止日期只知道训练数据收集之前的内容让它联网检索或自己核对
上下文有限注意力计算量随长度平方增长重要要求放在开头或结尾
数字母、精确计算出错看到的是 token 而不是一个个字符让它写代码来算，或调用计算工具
迎合用户RLHF 把「同意我」的偏好也学了进去中立地提问，直接要求它指出问题
学到关联，不等于掌握因果学到 A→B 不一定能答出 B→A换个角度追问，关键推理自己检查
模型的能力往往参差不齐。它可能解得出一道复杂的数学竞赛题，却在一个简单的常识问题上犯错。判断它可不可靠，最终要看它在没见过的、你自己的真实任务上表现如何。

总结

语言模型做什么？ 给定前文，输出下一个 token 的概率 怎么衡量做得好不好？ 交叉熵：越低，越接近人写作时的真实概率 预测的极限在哪里？ 语言本身的熵：交叉熵永远不低于它 用什么来做预测？ 神经网络：参数加非线性，能逼近任意函数 怎么把参数调好？ 梯度下降 + 反向传播 怎样才算学会？ 在没见过的文本上也预测得好 具体用什么结构？ Transformer：注意力收集上下文，前馈网络加工信息 一段话怎么写出来？ 自回归生成：温度和 Top-p 决定怎么挑 怎么变成聊天助手？ 后训练：SFT 学格式，RLHF 学偏好，可验证奖励练推理 怎么联网、用工具？ 写出调用工具的文字，外部程序去执行 为什么要大？ 规模定律：交叉熵随规模平稳下降 它做不好什么？ 幻觉、知识截止、上下文有限……大多能从「预测下一个 token」找到根源
万卷人言化作丝，层层网络织新辞。
前文照应千般意，概率权衡一句诗。
梯度回传修旧失，人间偏好亦为师。
纵然出口皆成锦，几处真知几处疑。

留给读者的问题

  1. 现在的架构是最优的吗？ 人脑里没有反向传播，没有 Q、K、V；一个孩子到十几岁接触的词不到 1 亿个，大模型却要读十几万亿个 token。这说明还有很大的改进空间，还是飞机本来就不必像鸟一样扇翅膀？
  2. 不靠人类的语言数据，能达到同样的智力吗？ AlphaGo Zero 不看人类棋谱，只靠自己和自己下，就超过了所有人类棋手。可围棋有明确的规则和输赢，语言和现实世界里，谁来当裁判？
  3. 大模型有自我意识吗？ 如果有，它在哪里：在训练好就不再改变的参数里，在每一场对话里，还是在每生成一个 token 的那一次计算里？一次对话结束，算不算一个意识的消亡？
